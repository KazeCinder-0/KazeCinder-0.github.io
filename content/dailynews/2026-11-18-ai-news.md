### 4. 同一天两家把「省」写进架构：商汤 9B 塞进 10GB 显存，OVHcloud 7B 在纯 CPU 上跑出 50 tok/s

**11 月 17 日晚**，**商汤**发布 **SenseNova Loop-9B 正式版**（承接 **10 月 31 日** 的 Preview，同样开放权重与代码）。思路是「参数不多存、多算几遍」：模型只存 **32 个物理层**，其中第 **4 至 27 层**组成共享块跑两遍，一次前向传播实际完成 **56 次**解码层计算；存储按 **9.41B** 计，计算量按等效约 **14.6B** 计。解码器四层一组（三层线性注意力 + 一层全注意力），循环块内两条残差流用**流形约束超连接（mHC）**路由、Sinkhorn 归一化迭代 **20 次**。官方 **AWQ 4bit** 权重约 **4.9GB**，显存需求 **10GB 以内**；256K 上下文配 8bit KV 缓存约 **15GiB**，上限 **512K**，支持文本与图像输入。厂商自评里 Preview → 正式版为 AutomationBench **14.33 → 36.67**、Terminal-Bench 2.1 **40.45 → 59.55**、GAIA **37.86 → 69.90**、BIRD **71.38 → 72.34**；对 **Qwen3.8-27B** 三项两胜一负：NL2Repo **41.36 对 44.60** 输、AIDABench **65.31 对 65.01** 赢、AutomationBench **36.67** 打平。**寒武纪**于 11-18 凌晨宣布 Day 0 适配，基于 `vllm_mlu` 把循环结构静态展开为 56 个顺序层、复用 Qwen3-Next 算子、把 mHC 的 Sinkhorn 迭代用 Triton 融成单 kernel。

同一天，欧洲云厂商 **OVHcloud** 在官方公告（法国鲁贝，正式发布放在 **11 月 19 日** OVHcloud AI Summit）推出首个模型家族 **Olala** 及首个成员 **Olala mini 7A1B**：总参数 **7B**、每层 **256 个专家**、激活仅 **1B**、BF16，混合注意力结合 **Differential-TPA** 与 **Mamba-3**。结果是 **8GB 显存** GPU 可跑，RTX A4500 上 **160 tok/s**，完全不用 GPU 的普通 CPU 也有 **50 tok/s**；初始上下文 **32K**，以 **Apache 2.0** 上架 Hugging Face，同时放出权重、预训练基座、技术报告与 **AI Act 合规文档**。训练在三台欧洲公共超算 **Jupiter、MeluXina、Jean Zay**（GH200 / A100 / H100）上完成，公共支持折合约 **700 万欧元**算力时。法国搜索引擎 **Qwant** 已把它接进快答功能，响应快 **20%**、运行成本降为原来的 **三分之一**。年底 v1.1 扩到 **128K** 并加强数学，v2.0 计划超过 **100B**，方向是企业 agent、云 DevOps 与网络安全。CEO **Octave Klaba** 的说法很直白：不能指望别家实验室未来几年一直开源，训练成本三年降了 **20 倍**，现在做模型是可以赚钱的。

**核心亮点：**
- **两条省法都今天可验**：Loop-9B 权重在 Hugging Face / ModelScope，Olala mini 权重在 Hugging Face `OVHai`，两者都是 Apache 2.0，10GB 显存档位与无显卡机器各有明确落点。
- **一个换深度、一个换显存**：商汤用重复计算换等效深度、不增权重体积；OVH 用稀疏激活换显存与功耗，方向完全不同却都在回答「同一张卡能跑什么」。
- **循环次数有可查的消融**：官方测出 AIDABench-QA 与办公任务在 **3 圈**见顶（比单圈好 **6.42% / 16.93%**），LiveCodeBench V6 与图表任务在 **4 圈**见顶（好 **8.10% / 8.55%**），默认只跑 2 圈是效率取舍，不是能力上限。
- **欧盟主权叙事进了模型卡**：Olala mini 把 AI Act 合规文档与权重一起发，对需要向监管交代数据来源与部署位置的欧洲团队，这比多几个跑分更实用。
- **需要保留的清醒**：Loop-9B 虽写 Apache 2.0，Hugging Face 仓库是 **gated**（需登录并接受条款），且检查点依赖具体循环范围与 mHC 执行顺序，推理栈不认这套结构就跑不起来；Olala mini 的 **32K** 上下文是硬限制，Qwant 的 20% / 三分之一均为厂商自报。两家的评测也都是自评，无第三方复现。

### 5. 5.25 秒压到 55 毫秒：微软 Copilot SDK 2.0 用 Rust 重写运行时，GitHub Copilot 同批上线一批能直接开的功能

**11 月 17 日** Ignite 上，微软把原先的 **GitHub Copilot SDK** 改名为 **Copilot SDK 2.0**，核心变化是多租户 Rust 运行时：多个智能体会话可在**单个进程内**并行，每个会话各有状态、凭据、工具、文件与历史且彼此不可见，创建会话不再需要起容器 / 进程 / 虚拟机。微软给出的自测数字是：相同预热负载下，创建客户端与会话并完成一轮对话从 TypeScript CLI 的 **5.25 秒**降到 Rust 进程内核的 **55.3 毫秒**；**10 个客户端**内存占用从 **1383MB** 降到 **126MB**；吞吐量从每秒 **7.55** 个会话升到 **120** 个。新增**按会话分配身份**（每次模型与工具调用都归属传入凭据的用户，服务端不存长期凭据）、**empty 模式**（会话以最小能力启动：无宿主 shell、无宿主文件系统、无默认工具，只注册应用真正需要的 API / MCP / 网络调用）、**持久会话**（事件日志记录消息、工具调用、计划与检查点，`sessionFs` 决定存对象存储 / 数据库 / 按租户路径，任何实例可凭 ID 在重启或换机后恢复），并在同一运行时上给出六种智能体架构。

**11 月 18 日凌晨**（GitHub changelog feed，JST 03:00—03:04）Copilot 同批上线：**GPT-6.2 Astra / Sol** 进入 Copilot 模型选择器（Pro+ / Max / Business / Enterprise；VS Code、Visual Studio、Copilot CLI、coding agent、Copilot app、github.com、GitHub Mobile、JetBrains、Xcode、Eclipse 逐步推出）；**Copilot Fusion** 三档定型（Fusion Standard 用 MAI-Code-2、Fusion High 用 GPT-6.1 Terra、Fusion Max 用 Claude Sonnet 5.5），可在 github.com、Visual Studio 与 GitHub Mobile beta 选择；**Copilot app** 新增 **Azure DevOps 仓库**支持与 **browser use**（直接复用你已登录的 Chromium，公开预览、默认关闭）；**code review** 新增 Adaptive effort（按 PR 自选审查深度）、跨仓库上下文与 secret detection；**Copilot Evals** 进入公开预览，可针对你的 skills、agents、MCP 工具重跑测试；**Copilot CLI 1.0.113+** 支持 Microsoft Entra 登录（预览）。

**核心亮点：**
- **今天就能装 / 能开**：Copilot CLI 升到 1.0.113 以上即可试 Entra 登录；Pro+ 及以上可直接在模型选择器切 GPT-6.2 或 MAI Code 2；code review 三项与 Copilot Evals 均为公开预览。
- **empty 模式是本批最值得抄的设计**：让会话默认一无所有、由应用逐项加回能力，比「默认全开再靠提示词约束」更接近最小权限。
- **凭据不再需要落到 VM 上**：按会话身份 + 短期凭据刷新，与今天 HN 上受关注的 `lend`（SSH agent proxy，凭据请求回到本机由 Touch ID 批准）指向同一个痛点。
- **需要保留的清醒**：55.3ms / 126MB / 120 会话每秒全部来自微软自测，**未公布独立基准**；browser use 虽复用已登录浏览器，默认关闭且为公开预览，团队里「谁打开了它」仍是需要先盘清的资产。同一批 changelog 里还夹着 DeepSeek Harness `dsh-v0.2.2-rc.4`（release candidate，修复异常模型响应处理与桌面端 LiveShare 建分享失败），别把 rc 当正式版。

### 7. 补丁 diff 成了漏洞说明书：Google 首次确认「无人在环」全自动攻击链，Anthropic 同日把披露窗口从 90 天砍到 30 天

**11 月 16 日**发布、**11 月 17 日**在中文与英文安全社区密集解读的 **Google Threat Intelligence Group（GTIG）**《2026 年第四季度 AI Threat Tracker》，首次确认一例**完全无人工介入**的漏洞发现与利用链：研究者在**一台暴露于互联网的测试服务器**上发现名为 **`exploit_agent`** 的多智能体 LLM 框架，接入云端前沿模型与本地模型，持续比对热门 Web 应用软件**补丁前后的代码差异**，从 diff 反推被修复的缺陷，自动起草并运行可用利用程序；同一服务器上还放着窃取来的数据、暴力破解脚本、安装 webshell 的脚本，乃至清除竞争对手所留 webshell 的脚本。配置文件里有一条俄语注释，提示「把密钥直接填在这里，不要写在聊天记录里」；受害者遥测显示目标偏向法国媒体、娱乐与教育网站。报告还记录 **CAIRN** 被用于美国航空航天业入侵、**PentAGI** 被用于 8 月下旬至 10 月初扫描亚洲大量机构、**CyberStrikeAI / ARTEX / LLMJacking / LLM Mixer**，以及通过篡改 coding-assistant 配置投放后门的供应链攻击；并预估约 **3 个月**内出现不复杂的自主攻击、约 **6 个月**内出现更复杂的。作为时间尺度的参照：PaperCut 打印管理服务器的两个漏洞 8 月下旬被作为零日串联利用，安全研究者与 **Huntress Labs** 用 LLM 在披露**一天内**生成可用利用程序，**GreyNoise** 追踪到披露**四天后**的攻击活动，其中一次仅用几分钟就从初始入侵点拿到域管理员权限。

与这份报告同一条 security-control 线的，是 **Anthropic Frontier Red Team** 于 **11 月 16 日**发布的《Coordinated vulnerability disclosure timelines》：把向厂商报告漏洞的协调披露窗口，高危 / 严重问题从 **90 天缩到 30 天**，其余问题 **45 天**；维护者 **15 天**无回应即升级至外部漏洞协调机构（此前 30 天），补丁发布后 **30 天**（此前 45 天）才公开完整技术细节；新规自 **2027 年 1 月 1 日**起适用于所有新报告，进行中的报告保留原期限。Anthropic 同时承认存在已超期 90 天但未公开的高危漏洞，将给维护者额外 **30 天**宽限，并把动机直说成「前沿模型找漏洞的能力明显变强」。同日谷歌发布 **Google AI Threat Defense**（Gemini + Wiz 上下文排序 + CodeMender 自动修补 + Mandiant 经验）。

**核心亮点：**
- **今天该做的一件事**：把安全修复从「普通 commit 走公开分支」改成尽量私有流程，发布前假定补丁内容对攻击者可见，补上补丁级模糊测试与「补丁引入新缺陷」审查。
- **维护者的日历要重排**：30 天而不是 90 天，意味着 SECURITY.md、私密漏洞报告通道（GitHub Private Vulnerability Reporting）、告警邮箱与快速发版通道得先自动化，否则修复窗口短于流程本身。
- **SLA 要按机器速度重设**：攻防时间尺度从周压到小时级，企业安全团队需把「被外部 AI 报告漏洞」纳入预案；GTIG 也点明，对攻击者而言挖 **N-day**（已披露未完全修复）比找零日更高效。
- **两家一手披露互为佐证**：Google 从攻击侧给出自动化已落地，Anthropic 从披露侧缩短窗口，同一天指向同一个结论——发现能力已经跑在修复能力前面。
- **需要保留的清醒**：GTIG 尚未公布操作者身份、具体目标受损情况、框架技术细节、实际成功率与防御方应对；报告也强调这**不等于 AI 能自动攻破任意系统**，成败仍取决于目标是否存在可利用漏洞。这类自动化目前以速度换隐蔽、取证痕迹多，反而更易被检测；国别归因（俄语注释、疑似关联方）本栏不采信。

### 10. 27280 次运行里 64.5% 的钱花在没通过的任务上：社区把「Agent 到底贵在哪」拆成了可复核的数字

本窗口社区讨论度最高的三组材料都指向同一件事——**Agent 的成本不在模型报价，而在没跑通的那些步骤**。**Runta 与 Baseten** 发布 **FrontierHarness Eval v1.1**（HN **291 分 / 103 条评论**）：**22 种 harness 配置 × 5 个开源模型 × 62 个终端任务**，共 **27280 次运行**、**830 亿 token**。结论是最佳性价比 harness **随模型改变**：Codex CLI 配 **GLM-5.3** 拿第一，Alma 配 **Kimi-K3** 拿第一，而 Codex CLI 换到 Kimi 就从**第 1 掉到第 16**；成本方差分解里 **92.8%** 来自模型、**2.3%** 来自 harness 本身、**4.9%** 来自两者交互；最扎心的是 **64.5% 的全部花费**用在了未通过的运行上。作者给的建议很反直觉：如果你频繁换模型，**按模型重选 harness 省下的钱可能比换模型本身更多**。

第二组是 **Dan Luu** 用 GPT-6 Astra 重跑 8 月的验证技术评测（HN 86 分）：给 agent 一份 Zstd RFC 从零实现，对比 TDD、QuickCheck、属性测试、Lean 4、ACL2、结构化 fuzzing、差分测试与「不指定方法」（Default）。上一轮 GPT-5.6 Sol 在 medium 档平均花 **3.50 美元**才让 63% 的运行通过 holdout、xhigh 档 **5.50 美元**到 77%；换成 GPT-6 Astra 后 medium 档 **1 美元**就有 99% 以上运行全过——旧基准直接饱和，只好换更难的 IMAP / Pandoc RFC（按目录价约 **9 万美元**，每条件 25—80 次运行）。更难的一档里没有任何条件达到完全正确，**差分测试最好、TDD 再次垫底、属性测试终于符合预期，而 Default 依旧最优**；他同时反驳了「单元测试经验上无用」的病毒式解读，强调数据薄、误差棒宽。第三组是支付风控公司 **Forter** 的口径：其网络上 Agent 下单量从 8 月中旬到 11 月中旬增至 **7.9 倍**、Agent 订单环比 **+67%**；11 月 2 日当周 **Meta Muse 占 49%**；爬取型 Agent 占比从 8 月 17 日当周的 **1.2%** 升到 11 月 2 日当周的 **80.5%**，已超过依赖协议接入的商业协议 Agent。

**核心亮点：**
- **可直接拿来改流程**：把 harness 当模型配套件而非固定基建，换模型时同步重测；把「未通过运行的花费」单独做成一条监控指标，比盯每百万 token 单价更有用。
- **验证方法的结论仍然反直觉**：在强模型上「让模型自己选怎么验证」多数时候比硬性指定 TDD 更划算，差分测试值得排进下一个实验位。
- **Agent 身份正在成为风控问题**：Forter 的 1.2% → 80.5% 说明商家面对的已主要不是协议接入的合作 Agent，而是自报身份的爬取型流量，「能不能区分合法 Agent 与恶意爬虫」会直接影响风控与履约。
- **HN 当日其他高热度**：40 岁工程师职业焦虑 **442 分 / 349 评论**（另有 12 年最低的 Who is Hiring 帖量）、卡内基梅隆把计算机课程免费放上 YouTube **1538 分**（当日榜首）、Optimizely 被入侵并在 Zoom / GitLab 投放恶意软件 **354 分**。
- **需要保留的清醒**：FrontierHarness 与 Dan Luu 的数据都是单一团队自测、误差棒宽；Forter 的占比基于其自有网络流量口径，不代表全网购物 Agent 结构。另有一条值得今天就用上的小工具 **dead-tests**（静态扫描「看起来有覆盖、实际永远不会失败」的测试：同名 def 覆盖、pytest.raises 后不可达 assert、JUnit 缺 @Test、expect(x) 无 matcher、被注释掉的断言），修复已并入 vue、Laravel、pydantic。
