# 朝闻道 | 2026-11-19

## 🚀 今日热点

### 1. 一个月第四款、卡在中间的 3 美元档：谷歌 Gemini 4 Neon 拿下编程智能体榜首，定价却比自家限时优惠还贵

**11 月 18 日**（北京时间 11-19 凌晨见报），**谷歌**发布 **Gemini 4 Neon**，这是该公司**一个月内的第四款 Gemini 模型**。定位上多数来源写作介于「最强、最贵」的 **Gemini 4 Carbon** 与「快而便宜」的 **Gemini 4 Hydrogen** 之间的甜点位，另有媒体口径称它是**替代此前的 Argon**，本栏并列保留两种说法。模型主打复杂软件工程、知识工作与科学工作流，约 **100 万 token** 上下文、最多可生成 **100 万 token** 输出，支持文本、图像、视频、音频与 PDF，以及计算机操控、代码执行、文件搜索、经 Google 搜索与 Google 地图做事实核验，**不支持图像和音频生成**。四档思考强度 **low / medium / high / xhigh**，默认落在 **high**。API 定价每百万 token **输入 3 美元、缓存输入 0.15 美元（较标准价 95% 折扣）、输出 15 美元**，即日起在 **Google AI Studio 付费层、Gemini API、面向 Pro / Ultra 订户的 Gemini 应用、Google Antigravity**，并已进入 **GitHub Copilot 与 Cursor**。

官方与第三方榜单给出的成绩单相当密集：**Artificial Analysis 编码智能体指数 58.6 分排名第一**，该机构智能指数在 **xhigh** 档给 **61 分、总榜第三**；**Vals Index 第二**（另有报道给出 **70.9%**）、**Agent Arena 可操控性第二**、**Zapier AutomationBench 登顶**；**Terminal-Bench 4.1 得 65.2%**、**FrontierCode 2.0 默认 high 档 46.2%**；**SWE-sweep** 在 mini-SWE 环境得 **12.8%**、换成 **Google Antigravity** 环境则到 **39.0%**。谷歌称在默认 high 档下**单任务成本比 Carbon 低 32%**、任务完成速度约为后者 **3 倍**，早期内部评估的整体任务质量达到或超过 Carbon，在 Antigravity 内部测试中的**编造率创 Gemini 模型新低**；另有媒体标题口径为「任务成本降 **17%**、耗时缩短四成」，两个数字对应不同评测集，本栏并列不合并。演示里有一段在 Antigravity 跑 **12 小时**的 `/swarm` 任务：用档案照片重建**艾伦·图灵 1936 年在剑桥国王学院的书房**，并在 3D 场景里搭出一台能运行的通用图灵机。同步推出网络安全版 **Gemini 4 Neon for cyber**，官方报 **AutoBaxBench 困难档 76%**、**WebExploitBench v1.2 51.26%**、**SEC-bench Pro 90.5%**、**CWE-bench v2 根因修复 70.7%**，未来数日经 **Fairwind 计划**向经过筛选的网安防御者开放。

**核心亮点：**
- **今天就能切**：API 标识符已在 Gemini API 与 AI Studio 付费层可用，Copilot / Cursor 的模型选择器里也能选；Gemini 应用需 Pro 或 Ultra 订阅。
- **3 美元这一档是算出来的**：它高于 Carbon 当前限时优惠价每百万输入 **2 美元 / 输出 10 美元**，却低于 Carbon 标准价 **4 美元 / 20 美元**（约低 25%），同时是 Hydrogen **1.50 / 7.50 美元**的两倍。Carbon 限时价一处口径称 **11 月 30 日**结束、另一处称 **12 月 1 日**起涨回标准价——换模型前先算自己缓存命中率，别只看单价。
- **默认档就是 high**：官方把默认思考强度设在 high，对「长系统提示 + 多轮工具调用」的 Agent 工作流，账单形状由缓存命中率决定；四档里 xhigh 才拿到那个 61 分。
- **网安版是分开的**：Neon for cyber 不是公开 API，而是经 Fairwind 计划定向开放给筛选后的防御方，与通用版的可用性要分开理解。
- **需要保留的清醒**：所有跑分与「比 Carbon 低 32% / 快 3 倍」均来自谷歌自己或特定评测条件，**Artificial Analysis 智能指数第三意味着仍落后于更大规模的模型**；SWE-sweep 从 12.8% 到 39.0% 的跳变也说明分数高度依赖 harness 环境。Gray Swan 间接提示注入测试里「最高档抵御全部攻击、成功率 0%」只代表该基准，不等于现实环境中的抗注入能力；本栏也未采信任何「幻觉率具体数值」，官方只说创自家新低。

### 2. 今天就能改的七件事：DeepSeek 搜索不再单独计费、OpenAI 用等待时间换 40% 折扣、vLLM 把旧 runner 判了死刑

这一批全是当天可动手的计费项、端点与版本升级。**DeepSeek** 自北京时间 **11 月 18 日 12:00** 起调整 API 搜索计费：模型调用触发的**服务端搜索与网页抓取不再单独计费**，只按模型 token 用量收费，联网工具、Responses API 与 Anthropic API 的 `web_search` 等服务端工具均会触发；客户端**直接调用 Search 与 Fetch API 则按每 1000 次成功请求 5 元**计费，失败、无结果或超时不计费（来源：DeepSeek 官方 API 文档）。**Perplexity** 于 **11 月 17 日**上线、**11 月 18 日**官方账号宣布的 **Context API**（端点 `api.perplexity.ai/v1/context`）与 **11 月 16 日**的 Monitor API 是两回事：它读取开发者**已经知道**的 URL 而非搜索，单次最多 **10 个**（高阶档 15 / 25），返回清理后的 **Markdown、原始 HTML、去重后的绝对链接、按查询挑选的 highlights** 四种格式，highlights 保留原文措辞、查询长度 1–1024 字符、每页预算 1–4096 token（默认 1024）；定价 **每 1000 个成功获取 URL 收 1 美元**，失败 / 超时 / 遇 bot challenge 不计费；默认接受 **max_age_seconds=172800（两天）** 内的索引副本，`0` 强制实时抓取、`cache_only` 只读缓存；官方自测 1000 个真实 agent 流量 URL 中 **92.3%** 输出可用、**87.9%** 事实召回、**80.3%** 内容精度；Python SDK 需 **0.48.0+**、TypeScript SDK 需 **0.43.0+**。同日 Perplexity 还发了 **Orchestrator API** 与面向 Max 订户的 Computer **Multiagent effort level**。

**OpenAI** 在 **11 月 17 日**的 API changelog 里（与 GPT-6.2 同日，本窗口为开发者接入与解读）给 **Responses API 后台模式**加了两个折扣完成窗口，公开测试版：`background: true` 配合 `background_options.completion_window` 设 **2h 降 30%**、**8h 降 40%** 模型 token 单价，适用 **GPT-6.2 Astra / Sol、GPT-6.1 Terra、GPT-6 Luna** 四款；按官方标准价折算，Astra 8 小时窗口输入 **8 → 4.80 美元**、输出 **40 → 24 美元**，Terra 输入 **1 → 0.60**、输出 **5 → 3 美元**。它夹在 Standard（即时、全价、唯一支持 streaming）与 **Batch API（24 小时、-50%、需单独 job 文件）**之间，两个折扣窗口要求 `stream` 为 false 或未设置。**vLLM 0.34.0**（GitHub release **11 月 16 日**、官方账号 **11 月 18 日**宣布）则是一次需要谨慎升级的版本：**1061 次提交、412 位贡献者（120 位首次）**、新增 **10 个模型**支持、**可扩展 KV 缓存默认开启**、**Model Runner V2 成为唯一 GPU runner**；4 张 **GB200** 上 Step5 NVFP4 解码最高 **1.95×**，GLM-5.3-Flash 吞吐 **1.6×**。其余今天可直接试的还有：**OpenCode** 把 Go 订阅（**10 美元/月**）本周结束前的 GLM 5.3 额度从最初的 100 美元、200 美元一路提到 **500 美元**；**ChatGPT Live Dictation**（11-18）说话即转文字、移除 **10 分钟**录音上限，面向全部订阅方案在 iOS / Android / 网页 / 桌面全球推送（OpenAI 语音团队成员 **Atty Eleti** 说明仅 app 内可用，不支持系统级输入与后台听写）；**ChatGPT for Accounting** 上线会计插件，可连 **QuickBooks、Xero、NetSuite、BILL** 做月末报告、银行对账与发票分录，**用户确认后才入账**；**Google Antigravity** 收紧文档里的模型权限，免费 / Plus / 试用 Pro 已用不了 Gemini 4 系列、只剩 **3.8 Flash**，付费 Pro 保留 Hydrogen 与 Argon，Ultra 才全开。

**核心亮点：**
- **一行代码就能省钱**：夜间报表、批量文档审阅、积压分类这类不需要即时结果的工作流，把 Responses API 改成 8 小时窗口即可少付 40% token 费用，比迁到 Batch 的改造量小得多；白天交互路径别动，因为折扣窗口不支持 streaming。
- **抓取成本从「按次」变成「按 token」**：DeepSeek 把服务端搜索揉进 token 账单后，Agent 反复联网的边际成本结构变了；但如果你的架构是客户端直调 Search / Fetch，仍按每千次 5 元，两条路径要先分清楚。
- **vLLM 升级前先 grep 部署清单**：`gpu_memory_utilization` 默认从 **0.9 / 0.92 改成 1.0**、block size 默认 **16 → 64**、设 `VLLM_USE_V2_MODEL_RUNNER=0` 从回退变成**启动即失败**、ROCm 7.2 产物停止发布、需 huggingface_hub 2.0。可用 `--gpu-memory-utilization 0.9` 或 `--no-enable-extensible-kv-cache` 锁回旧行为；官方给的例子是 MiniMax-M3 在 H200 上缓存 token 从 **433k 涨到 672k（+55%）**，另一口径为 DGX Spark 可用缓存 **11.2 → 67.6 GiB**。
- **代价写在发行说明里**：部分 H200 配置在并发 **128** 时每 token 解码延迟可能上升 **6–18%**，GPU 显存看板也会「按设计接近全满」——有延迟 SLO 的集群必须在真实并发下重测，别在并发 1 上验收。
- **需要保留的清醒**：Responses API 的美元价格是媒体按官方公布的 30% / 40% 折扣**折算**出来的，OpenAI 公告只给百分比、未公布窗口的绝对价格，也未列单独的缓存输入 / 缓存写入价；超过 **272K** 输入 token 时长上下文规则仍生效，区域数据驻留端点对 2026-03-05 后发布的模型加价 **10%**；官方把 2h / 8h 称作完成「目标（target）」而非计算立即开始的承诺，首 token 时间可能更长。Perplexity 的 92.3% / 87.9% / 80.3% 是厂商自测而非独立基准，文档也没说明 robots.txt、重 JS 页面与付费墙怎么处理；vLLM 的 1.95× 是 4×GB200 上 Step5 NVFP4 的特定结果，不是所有部署的通胀承诺。

### 3. 模型开始写芯片：OpenAI 把一年份的 PPA 优化压进五个月，Anthropic 用三天补完 AMD 十二个月的内核

**11 月 18 日**，**OpenAI** 发布技术报告 **《Advancing chip design with OpenAI models》**，第一次把「模型直接改写芯片电路」摆到台面上。自研推理芯片 **Jalapeño** 方面，OpenAI 从 **2025 年初**就用 **GPT-4o** 辅助设计，模型在向量计算单元里调整浮点加法器、乘法器、转换函数与流水线结构，在矩阵单元里重做浮点运算与低精度点积电路：一项乘法器重设计使综合后标准单元面积减少约 **15%**、运算延迟从**两个时钟周期缩到一个**，另一项加法器在保持两周期延迟下同样减约 **15%** 面积；官方估算最终让向量单元标准单元面积降约 **13%**、矩阵单元降约 **10%**，且已在**芯片硅片调试验证**中确认。对外合作部分更硬：针对 **AMD 旗舰 GPU 的关键 IP 模块**，模型通过重写描述电路的 **SystemVerilog RTL**，在原本已高度优化的基线上把功耗、性能与面积（PPA）指标**最高改善 14%**，相当于把通常约**一年**的设计进展压到**不到 5 个月**；**AMD 已把部分优化纳入近期送交制造的设计**，另一些进入生产设计文件供后续产品使用，并在**下一代旗舰 CPU** 关键模块验证了**个位数百分点**的 PPA 提升。为比较不同代际模型的独立设计能力，OpenAI 选了开源 32 位 RISC-V 内核 **PicoRV32**（面向 FPGA）与 **Ibex**（OpenTitan 安全芯片嵌入式处理器）做评测：总有效打分 **9881 次**、同等 token 预算约 **11.2 万 token/次运行**，**GPT-6.2 Astra** 从零设计 PicoRV32 平均分超 **0.7**、Ibex 约 **0.75**，评测面积上限为原始内核面积 **16 倍**、超出计 0 分。配套的商业结构是 **9 月 30 日**与**新思科技（Synopsys）**宣布的多年战略合作及 **GPT-Synopsys** 项目：新思总裁兼 CEO **盖思新（Sassine Ghazi）**称协议专门设计为不与现有业务竞争、属业务增量，产品上市后**收入分成挂钩模型对芯片设计的实际提升效果**；公告当日新思股价盘中涨超 7%、收涨 **4.78%**；据 SemiAnalysis 2025 数据，EDA 市场新思约 **44%**、Cadence 约 **30%**，两家合计约 **74%**。

同一天被放在一起讨论的还有 **Anthropic** 侧：据媒体援引，**Claude Mythos** 在几乎无需人工干预下用**约 3 天**完成 **AMD MI355X** 近 **100%** 的底层内核代码编写，而传统方案需要数十名资深工程师 **6–12 个月**；移植后性能与 CUDA 优化方案的差距保持在 **8%–12%**，主要覆盖**推理预填充**环节，超大规模分布式训练的多卡协同仍是英伟达明显领先；报道并称 Anthropic 与 AMD 已达成最高 **2 吉瓦**的算力供应合作。同花顺在「关键数据清单」里也把「AMD MI355X GPU 适配周期约 3 天、传统 6–12 个月」列为可比口径。

**核心亮点：**
- **落点在软件栈而不是制程**：CUDA 的护城河是多年人力堆出来的内核与工具链，而「材料明确、目标可测」的 RTL 改写与内核移植恰好是模型最擅长的任务；对国产算力而言，用模型补软件栈比用制程追更现实。
- **数字有明确的验收边界**：Jalapeño 的 13% / 10% 已过硅片调试，AMD 的 **14% 是设计阶段 PPA**，还要过时序收敛、验证与流片，**不是量产良率**；「内核写完」也不等于跑得满、跑得稳。
- **分工被改写了**：人定架构、约束与目标函数，模型做实现与搜索；报告里 9881 次有效打分、11.2 万 token 预算这类「可重复的评测协议」，可能比单个 PPA 数字更有长期价值。
- **商业条款也值得抄**：把收入分成与「实际提升效果」绑定，而不是与调用量绑定，是模型能力进入 EDA 这类高验证成本行业时一种可谈的计价方式。
- **需要保留的清醒**：OpenAI 报告口径为「最高改善」与「相当于约一年进展」，均为公司自述，无第三方复现；Anthropic 的 3 天 / 近 100% / 8%–12% / 2 吉瓦主要见于媒体转述与单一清单，**未见两家公司联合的一手技术白皮书**，本栏不合并成单一结论。另需注意上期本栏已覆盖英伟达 Rubin HPC 与黄仁勋辞任后的算力叙事，此处是「设计工具」而非「芯片产品」这条新线。

### 4. 两个权重包同一天落地：腾讯 Hy4 flash 从 API 走到开放权重，苹果 FastFrames 把视频压进 36 毫秒却只许科研用

**11 月 18 日**，**腾讯混元**宣布开源 **Hy4 flash** 模型，一口气放出 **Hy4 flash、Hy4 flash-FP8、Hy4 flash Base** 三个版本，开发者可在 **GitHub、Hugging Face、ModelScope、GitCode** 下载部署，社区另提供 **GGUF** 格式与开源协议文件。这是 **11 月 16 日** Hy4 flash API 发布之后的第二步——上期本栏在大厂背景里记的是「拟于 **11 月底前**开源」，实际提前了两周落地。模型总参数 **224B**（含 **64B Engram** 参数）、每 token 仅激活 **12B**，支持多模态输入与 **100 万 token** 上下文，官方定位「迄今性价比最高的 Hy 模型」，API 价格较 Hy4 大幅降低；已上线**腾讯云 TokenHub、WorkBuddy、元宝、企业微信、QQ、ima、Marvis**。另据一份 11-19 日报口径，量化版本在配备 **128GB 内存的 Apple M5 Max** 上达到 **47.37 token/秒**（单源，未见官方复现）。腾讯同时预告正在加快 Hy4 系列开源节奏。

同一天，**苹果**开源面向实时交互的视频生成模型 **FastFrames** 系列，含 **13 亿参数的 FastFrames-S** 与 **140 亿参数的 FastFrames-L**，主打低延迟 **480P** 视频生成。按苹果公布的测试，**FastFrames-S** 在单张 **NVIDIA B200** 上生成延迟 **36 毫秒**，在保持与基础模型 **Causal Forcing++** 相近生成质量的同时速度约为其 **7.6 倍**；**FastFrames-L** 是对阿里**通义万相 Wan2.1-14B** 做蒸馏（S 版则冻结 Causal Forcing++ 基础生成器权重、另训画面输出与历史信息处理两个网络），生成效果与同样基于 Wan2.1-14B 的 **Krea-Realtime** 相当，单卡速度约为后者 **10.6 倍**，用 **8 张 B200** 后延迟进一步降到 **45 毫秒**（另一份日报给出 L 版单卡 **158 毫秒/帧**、分辨率 **832×480**，与 S 版 36 毫秒是不同尺寸，本栏并列保留）。加速方法可外推：蚂蚁灵波 **LingBot 1.3B** 经优化后响应约 **16 倍**、斯坦福等团队的 **RealWonder** 约 **22 倍**。权重在 Hugging Face、代码在 GitHub，配训练与评测工具，Linux + 英伟达 GPU 上可跑文生视频，**但许可限定为非商业科研用途**。

**核心亮点：**
- **今天就能下载**：Hy4 flash 三版本 + GGUF 在四个平台齐备，FastFrames 权重、代码、训练与评测工具全开；前者面向长文档 / 图文混合与私有化部署，后者面向交互视频研究。
- **两条「省」法不同**：腾讯用 224B 总参只激活 12B 的稀疏激活换推理成本，苹果用蒸馏 + 双网络把逐帧扩散的步骤数压下来，一个省算力、一个省步数。
- **苹果把边界写进了许可**：非商业科研用途意味着团队可以复现、可以拿方法给自家模型提速，但要商用得另谈授权；官方也直说 S 版存在**文字乱码、提示词理解偏差、画面不稳**（女孩拉小提琴案例中琴弓明显偏离琴弦、面部随琴弓移动变形），L 版在人物面部与演奏动作上更稳定。
- **国产算力闭环再进一步**：Hy4 flash 从 API 到权重只隔两天，且已铺进腾讯自家全线产品；配合本期另一条腾讯财报里 Hy4 flash 上线首日 **Token 调用超 50 万亿**，能看出「先产品后权重」的节奏。
- **需要保留的清醒**：两家的跑分与倍数均为厂商自评、无第三方复现；**64B Engram 参数的具体作用原文未说明**，对实际能力影响不确定；M5 Max 的 47.37 tok/s 为单一日报口径。另有中文自媒体把 FastFrames 描述为「WWDC 2026 承诺、接入 Vision Pro Studio、M3 Ultra 上 1080p 一帧 120 毫秒」，与苹果官方博客的技术路径、硬件与分辨率均冲突，本栏**未采信**该说法。

### 5. PR 合了不算完：谷歌同日放出 Genie 4 与 Stitch Loop，一个让世界随文字变，一个让 agent 24 小时盯线上指标

**11 月 18 日**，**Google Labs** 产品管理总监 **Justin Toupin** 发布实验性产品 **Stitch Loop**，定位是「长程运行的产品 agent」：它连上团队的 **GitHub 仓库与线上实时指标**，把**日志、用户行为、反馈**等产品上下文通过 **180 多种集成、自定义 MCP server 或本地 CLI 上传**接进来，围绕一个可度量目标全天候运行。每个 loop 固定走四步——**建议**（基于产品证据列出改进机会）、**方案**（每条建议给一个或多个含权衡与范围的方案、附视觉设计）、**构建**（在隔离云沙箱里写代码、开 GitHub PR，必要时附截图与视频）、**反思**（持续监控线上数据、从每次正负结果里学习）；**目标达成后仍继续盯着，防止指标回落**。默认自带**网络安全、延迟、无障碍**三条循环，也可自定义（官方举例结账转化、支持工单）；安全循环把 **Gemini 4 Carbon** 的网安能力与 Google DeepMind 的 **CodeMender** 自动修补 agent 配对，带证据地标出漏洞并开修复 PR。它还能作为服务层给 **Google Antigravity** 等编码 agent 供上下文（经 **Stitch CLI 与 MCP**），Slack 里 `@stitch` 可发每日摘要与新建 loop。

同日，**Google DeepMind** 宣布世界模型 **Genie 4** 随 **Project Genie** 重大更新正式开放：向已推出 **Google AI Ultra** 地区的年满 **18 周岁**订阅者开放，**AI Pro** 会员可加入候补名单。Genie 4 支持在探索过程中输入提示词**实时修改天气、新增角色或改变剧情**，首次搭配适配场景的**实时原生环境音效与角色对话**；新增 **Project Genie agent**（自然语言对话编排多模态模型生成世界观与定制配乐）与**社区画廊**（浏览与二次创作官方及创作者合作的世界）。模型选择器仍保留 **Genie 3**，单次探索从 **60 秒**延长到最长 **3 分钟**，支持串联多个世界与 **360 度全景图**生成；所有生成的视频与音频均带 **SynthID** 水印，抢先体验期暂不消耗 AI 点数。

**核心亮点：**
- **候补名单已经开了**：Stitch Loop 全球开放候补（Google AI Ultra 优先），Genie 4 在 Ultra 覆盖地区可直接进 `labs.google/projectgenie`；两者都不需要额外付费，但都**不是 GA**。
- **把终点从「PR 合了」挪到「指标稳了」**：过去编码 agent 交出 PR 就结束，Loop 的反思步要求它在部署后查真实数据、验收生产环境的无障碍修复，这是把 agent 的责任周期拉长到上线之后。
- **控制点写在设计里**：官方反复强调「**你永远有最终决定权，未经 review 的 PR 一律不合并**」，行业简报把这条量化为 **0 条未经人工 review 自动合并的 PR**；延迟循环在每次部署后核对真实指标，无障碍循环按 WCAG 检查并在生产环境验证修复。
- **MCP 成了通用插槽**：Loop 既吃自定义 MCP server，又通过 MCP 把持久上下文喂给别的编码 agent，配合本期热点 2 的 MCP 错误成本数据一起读，能看出「上下文服务层」正在成为独立一层。
- **需要保留的清醒**：Google 公告**没有给出价格、正式发布日、候补录取人数、支持的语言 / 框架，也未公布 loop 自身的任何实测结果**；安全循环引用的 Carbon 在 SEC-bench Pro **88.2%** 是模型榜分（10-28 公告、无 guardrails 口径），不是 Loop 的效果数据。Genie 4 虽不消耗 AI 点数，但受**每日用量限额、高峰排队、已知控制延迟与流式画质波动**限制；CodeMender 自 2025-10-06 起所有补丁仍由人类研究者审核后才上游提交。另注意「stitch-loop skill」在 Labs 的 stitch-skills 仓库里是另一个从单条提示词生成多页网站的同名工具，不要混淆。

### 6. 给模型装刹车：加州拿出 IVO、紧急关停与 48 小时报告，但这份 11-18 提案还不是法律

**11 月 18 日**，加州州长 **Gavin Newsom** 发布前沿 AI 立法建议，依据 **California Government Operations Agency** 的报告 **《AI Safety in 2026 and Beyond》**（报告日期 **11 月 16 日**），供议员 **2026 年 12 月**复会时立法参考——**目前是建议，不是已生效的义务**。核心是**持牌独立验证组织（IVO）持续监督**：每个大型前沿开发者都要接受 IVO 的常态化审查，IVO 把州定标准翻译成技术测试并随评测方法演进更新，可访问**模型、人员、系统、训练环境与记录**，向州提交**未删节的评估**；由 GovOps Agency 发牌，可因专业能力、独立性或严谨性不足吊销。整改命令可在与企业沟通后下达、生效前可诉诸法院，但**紧急程序例外**。

第二根支柱是**风险遏制协议（Risk Containment Protocol）**：由 IVO 持续测试验证、公司高管认证有效，能力要覆盖**算力、agent、内部访问与模型部署**，而非依赖一个开关；要写明责任人、与云厂商及电力供应商的协同、何时可安全恢复，并专门测试「关停会怎么失败」——包括**模型复制自己的权重以阻碍遏制**、**外部行为者夺取关停控制**两种情形。州官员在有可信理由认为存在**迫在眉睫的灾难性风险或重大失控事件**、且开发者拒绝控制危险时，可下令**立即关停**：要求最窄可行干预、立即生效、**司法审查期间持续有效**（开发者可申请临时限制令），危险不再迫近时解除；对开放权重开发者，遏制与关停义务**只适用于其自身控制的部署**，因为他们关不掉别人托管的副本。第三块是报告与披露：关键事件报告期限从 **15 天缩到 48 小时**，迫近灾难性风险保留 **24 小时**，新增 **near-miss（近失）通道**，**未遂的模型权重窃取**（即使无伤亡）、所有内部 / 外部失控事件都要报，举报人保护扩展到**前员工与承包商**；能造成灾难性风险的模型**即使训练量低于 10^26 次整数或浮点运算**，也按前沿模型纳入报告。自动化 AI 研发的企业须**按季度报告算力分配**（训练 / 研究实验 / AI 研究 agent 推理 / 安全与安保 / 外部客户 / 未归因活动，由 IVO 核实），并披露训练数据量、成本、主题领域、人类 vs AI 来源、RL 环境中用于训练模型的推理算力、已知被奖励的不当行为及缓解措施；**递归自我改进（RSI）**适用「备用上限权限」而非立即禁止：自动化研发超过承诺阈值或快于 safeguards 与 evals 时，官员可施加有时限、定期复审的上限，IVO 验证 safeguard 充分后解除。IVO 验证费上的附加费将用于 **CalCompute** 公共算力，其中一部分留给独立安全研究与公共监督。这套建议源于 Newsom **9 月 18 日**关于独立监督与 AI kill switch 的行政令。

**核心亮点：**
- **与本期热点 3、5 是同一枚硬币**：一边是模型改写芯片 RTL、agent 24 小时自己开 PR，一边是州政府要求「谁能关停训练 / 推理 / agent 工具访问」写成可审计的文档，并演练权重复制与关停控制被夺取的失败路径。
- **触发口径从「训练规模」改成「能力」**：低于 10^26 FLOPs 但具备灾难性风险能力的模型同样纳入报告，等于承认单靠算力阈值已经兜不住了。
- **开放权重被区别对待**：只管自控部署，不管他人托管的副本——这对本期热点 4 的开源权重、以及热点 7 里被点名的中国开放权重模型，都是一条现实边界。
- **今天该做的一件事**：把「关停故事」画出来——隔离的算力切断、agent 凭据吊销、部署 kill path 谁负责，云与电力伙伴在压力下是否配合；监管要的是**测过的流程**，不是面板上那个红色按钮。
- **需要保留的清醒**：Politico 11-18 指出 Newsom **并未要求单一字面意义上的 kill switch**，而是多层紧急刹车；报告**没有设定刑事处罚或许可费用**，完整法案仍需过委员会，联邦优先覆盖州法的争论也未定。同期另有报道称 **Anthropic 私下向国会推销一份前沿 AI 安全法案草案**（政府仅在可预见的紧迫风险造成 **超 10 亿美元损害或伤害超 50 人**时可阻止模型发布、独立评估员 **72 小时**内向商务部报告），该草案的优先覆盖条款正因批评而修改，**属草案而非法律**，两件事不要混为一谈。

### 7. 用官网点名代替禁令：白宫拟要求美企披露用了哪些中国 AI 模型，Airbnb 与 Cursor 都在名单上

**11 月 18 日**，**路透社**引述 **3 名知情人士**独家报道：**特朗普政府正考虑要求美国企业公开披露使用中国 AI 模型的情况**。据称**美国财政部与白宫科技政策办公室（OSTP）**已讨论该计划，适用对象包括 **Airbnb**——该公司用阿里巴巴的**通义千问（Qwen）**驱动其 AI 客服代理；按构想，这类企业须在**自家网站**公布相关信息。报道明确：目前**不清楚该方案在政府内部是否获得更多支持，也不确定若继续推进是否会进入正式规则制定程序**；白宫、财政部、阿里巴巴及中国驻美使馆均未回应，Airbnb 一则口径为拒绝评论、另一则转述其回应称「AI 业务绝大多数运行在美国来源模型上，仅有限使用中国来源开源模型，且通过经批准的美国服务商运行、数据与运营环境受隔离保护」，本栏并列保留。

路透点名的三个模型是**千问、月之暗面 Kimi、DeepSeek**，理由是中国开放权重模型价格低于 OpenAI / Anthropic 的专有工具而性能已够用；援引 **OpenRouter** 数据称 **2026 年 10 月按 Token 使用量排名前三的 AI 模型全部来自中国**；路透今年 **9 月**曾报道美国一个政府网站部署了阿里模型，帮用户搜索拟议中的联邦监管法规。国会侧，**众议院国土安全委员会主席 Andrew Garbarino** 与**美中战略竞争特别委员会主席 John Moolenaar** 已致函 **Airbnb、Cursor 开发商 Anysphere、DoorDash** 了解使用中国 AI 的情况：**Anysphere 的 Composer 2 模型**基于某版本 Kimi 打造，DoorDash 一位联合创始人此前透露内部系统把部分任务交给 Kimi。背景上，财长**贝森特**今年 **7 月**称若中国 AI 企业被认定通过「蒸馏」窃取知识产权可能制裁，OSTP 主任 **Michael Kratsios** **4 月**指控中国以「工业规模」窃取美国 AI 实验室知识产权，但美方迄今未对相关中国企业施加限制或处罚。中国驻美使馆回应：反对将经贸和科技问题政治化，「只会阻碍全球 AI 发展，不符合任何一方的利益」，将坚决维护中国企业合法权益。

**核心亮点：**
- **手法是「name and shame」而非禁令**：用公开披露形成公众压力来降低依赖，既避免出台可能引发业界或中方反弹的新限制，又维持政府整体反对加强 AI 监管的立场——这是本期最值得记的监管思路差异。
- **对开发者的直接影响是选型与披露**：如果你的产品把 Qwen / Kimi / DeepSeek 接进了客服、代码补全或内部流程，未来可能要在官网写清楚；现在就该整理一份模型清单与数据来源说明。
- **中国开放权重模型已经进了美国生产系统**：从 Airbnb 客服、Cursor 的 Composer 2、DoorDash 内部任务，到联邦网站法规检索，再到 OpenRouter 10 月 token 用量前三，这条链不是「可能采用」而是「已在跑」。
- **与热点 6 互补**：加州管的是「模型能不能被关停」，联邦这一侧管的是「谁用了谁的模型要被看见」，两者都绕开了直接禁模型。
- **需要保留的清醒**：这是**三名匿名信源 + 讨论阶段**的报道，不是政策发布；报道也明确美方至今未对相关中国 AI 企业施加限制或惩罚。Airbnb 回应存在「拒绝评论」与「已回应」两种口径，本栏不合并断言。另注意上期本栏已覆盖 **BIS 132 页规则与 33 个全栈 AI 出口联盟**（管算力流向），本期这条是**管模型使用披露**的另一条线，属新角度而非重复。

### 8. 83 美元、813 亿美元：Anthropic 把前沿模型第一次单独交给公开市场定价，上期这里还是招股书

上期（**11-18**）本栏快讯记的是「Anthropic 招股书第三次修订、状态由已申请更新为已获准、预计 11 月 19 日开始交易、发行价区间 70—78 美元」；本窗口落地的是**正式定价**。**11 月 18 日**，路透引述知情人士称 **Anthropic** 将 IPO 发行价定在**每股 83 美元**，**高于 70—78 美元的推介区间**，公司拒绝就报道置评；纳斯达克文件显示已批准其 A 类普通股以代码 **ANT** 上市（以收到正式发行通知为条件），预计 **11 月 19 日**开始交易。据财联社 11-19 电稿：公司出售 **9.564 亿股**、七位联合创始人出售 **2360 万股**，合计筹得 **813 亿美元**，完全稀释估值约 **1.5 万亿美元**，为**史上最大一宗 IPO**，打破 **SpaceX 750 亿美元**的基础规模纪录；若计入 **260 亿美元**私募配售，整体融资 **1073 亿美元**，超过 SpaceX 含超额配售选择权的 **862 亿美元**。另有一份日报口径为「公开发行 **8.25 亿股**测算募资约 **685 亿美元**、加 260 亿私募合计约 **945 亿美元**」，与上期本栏记录的「8.0135 亿股 / 约 904 亿 / 估值最高约 1.4 万亿」也不一致，**三套数字并列保留、不合并断言**。日本配售部分约 **30 亿美元**（**3600 万股** A 类股、同为 83 美元，由 **Mizuho Securities** 主导，低于初步计划的 3900—5000 万股）；红杉资本、Iconiq、光速创投、Accel、Altimeter 等现有投资方拟在 IPO 中追加数十亿美元认购。参议员 **Elizabeth Warren** 公开批评其未回答「IPO 若出问题，对美国人退休金与金融体系的潜在威胁」；另有加密期货押注其估值可达 **1.7 万亿美元**。

**核心亮点：**
- **定价主体换了**：过去前沿模型由一级市场少数基金定价，现在由几千个机构账户与散户共同给一个公开坐标；媒体分析强调关键不在 83 这个数，而在**近 30% 股份握在两家既是股东又是最大算力供应方的手里、且多数无投票权**，既锁了算力，也把关联交易变成长期问题。
- **按本栏选材偏好只保留有开发者落点的部分**：上市后要盯的是**毛利率能否随推理成本下降抬升、算力承诺如何履约、解禁后的真实流通盘**，而不是首日涨跌。
- **与本期热点 2 直接相关**：当 Responses API 用等待时间换 40% 折扣、vLLM 把 KV 缓存从估算改成实测、Cerebras 用每兆瓦 token 产出计量时，「推理成本」正是这家公司毛利率的分母。

- **需要保留的清醒**：这是公司层面的融资事件，按本栏偏好降权处理；**发行股数、募资总额、估值存在至少三套口径**（813 亿 / 约 945 亿 / 上期约 904 亿；1.5 万亿 / 1.4 万亿 / 期货押注 1.7 万亿），且路透报道时公司拒绝置评、上市仍以正式发行通知为条件，「83 美元定价」与「已完成上市」不是同一件事。另注意「英伟达推进 129 亿美元收购 Hugging Face」在本窗口只是**全员会重申 9 月已达成的旧交易**，不是新收购，详见快讯边界核对。

### 9. 同一晚两份账本：腾讯 WorkBuddy 日活千万、日均 100 万亿 Token，豆包工作三个月做到 800 万

**11 月 18 日晚**，**腾讯**发布 **2026 年三季度财报**并首次披露 AI 产品核心运营数据：**WorkBuddy 日活跃用户超 1000 万**，**日均 Token 消耗超 100 万亿**，按大语言模型 Token 消耗量计已是**中国使用量最高的 AI 产品**；近 **7 天**收入按年化折算**超 5 亿美元**、为腾讯会议的两倍以上，**三季度收入是二季度的 5 倍以上**，中国百强企业已有 **60%** 成为客户；总裁**刘炽平**称 WorkBuddy 能适配各家模型公司的模型、几乎是中国所有开源权重模型的最大客户，并透露**有用户每月购买 token 花费约 4 万元人民币**，把变现路径说成「免费档获客、付费档起步、重度用户不断追加 token 支出」。同场首次公布微信内置智能体**「小微」日活 3000 万**（测试范围持续扩大）、**Hy4 flash 上线首日 Token 调用超 50 万亿**。当晚**字节跳动**随即宣布「豆包工作」上线仅 **3 个月**（**8 月 25 日**发布）**DAU 突破 800 万**、企业客户 **ARR 突破 20 亿元**；该产品 **11 月 12 日**新增 Kimi K3.1 Pro、GLM 5.3、DeepSeek V4.1 Flash 等第三方模型并标注额度消耗倍率，**11 月 16 日**上线覆盖金融、医疗、教育、创意设计等 **21 个专业场景**的「工作台」。

财报的另一面同样值得看：三季度收入 **2073.36 亿元（+8%）**、经营盈利 **591.47 亿元（-7%）**；**自由现金流 -691 亿元**（上季 -138 亿元），剔除算力采购预付款可**转正至 +169 亿元**；资本开支付款 **651 亿元（+226%）**、研发投入 **323.6 亿元（+42%）**——另有媒体口径称三季度资本开支 **814 亿元、同比 +527%**、大幅超市场预估的 554 亿元，两者疑为「付款」与「资本开支」口径差异，本栏并列。管理层在电话会上说「**AI 肯定带来重组，企业可以用更少的人**」、元宝投入未达预期已减少花费、受芯片限制训练下一代模型需要更长时间。**马化腾**在 **11 月 11 日**周年庆上把从互联网到 AI 比作「**从陆战到海战**」，称「现在已经是生死存亡的时候」、要「用一半人守传统业务，一半人打新战役」，刘炽平补了一句「变革速度还不够快，之前对人太宽容」。

**核心亮点：**
- **Token 成了可对外披露的经营指标**：日均 100 万亿、上线首日 50 万亿、月花 4 万元的重度用户，这些数字比「日活」更能说明 Agent 产品的成本结构——也解释了为什么本期热点 2 里所有人都在抠缓存、等待窗口与每兆瓦 token 产出。
- **两条变现路线同框**：腾讯押「免费获客 + 重度用户追加 token」，字节押「3 个月 800 万 DAU + 企业 ARR 20 亿」；前者披露了单用户上限，后者披露了企业侧规模。
- **算力账直接压到现金流**：连续两个季度自由现金流为负、剔除算力预付款即转正，说明这一轮 AI 办公竞争的约束不在产品而在算力采购节奏；第一财经分析并称下半年国内模型与全球前沿在**前沿数学**上的差距重新拉大（其引用的腾讯 Hy4 测评里 GPT-6.1-Sol **97.5**、Claude Opus 5.5 **91.3**，而 Kimi K3.1 Pro **14.8**、Hy4 **13**、DeepSeek 4.1 Flash **8**、GLM 5.3 **0.1**）。
- **小微的保守是个产品判断**：日活 3000 万超过 WorkBuddy，却因数据安全顾虑**无法访问用户聊天记录**，主要做公众号内容总结与「更好的微信搜索」——拥有最多上下文的产品，反而最不敢用。
- **需要保留的清醒**：公司披露口径与媒体转述口径在资本开支（651 亿 vs 814 亿）、年化收入（7 天折算）上都需谨慎；「用更少的人」是管理层表态而非已执行的裁员计划，媒体把「一半人打新战役」解读为裁员 50% 属外部解读。投资人**朱啸虎**此前称 WorkBuddy 好用但最多愿像付话费一样每月付 **50–100 元**，与「月花 4 万元」的重度用户并列，说明这个市场的付费分布极不均匀。另注意上期本栏 APEC 条已记李彦宏「AI 泡沫取决于应用层」，本期是同一问题的财报侧答案。

### 10. 涨的分只在一个 agent 里成立：Qwen3.8-27B 的一张 LoRA 把 39.2% 抬到 64.7%，而瓶颈已经挪到代码审查

本窗口社区讨论度最高的几组材料都指向同一件事：**模型能力越来越是「模型 + agent + 工具链」的联合结果**。**11 月 18 日**，Hugging Face 放出 **Qwen3.8-27B-pi-adapted**——一张 **Apache-2.0** 的 **LoRA 适配器**，用强化学习**专为 pi 这一款 agent** 训练，底座 **27B**。发布方自测 **SWE-bench Pro hard-51 从 39.2% 升到 64.7%**、**Terminal-Bench 2.1 从 39.5% 升到 55.8%**（另一份技术日报口径为 **64.7%**、**56.6% vs 54.2%**、每任务 token 少约 **4.5 倍**），但模型卡明确注明**结果绑定 pi 的配置**：换一套工具与执行循环，分数不保证成立。这恰好接上上期本栏的 **FrontierHarness Eval v1.1**（27280 次运行、64.5% 花费用于未通过的运行、最佳 harness 随模型改变）从两侧给出的同一个结论。

第二组是「瓶颈转移」：**哈佛研究者发现 AI 编码 agent 把瓶颈从代码生成挪到了代码审查**（HN **143 分 / 188 条评论**）；Google Cloud 的 **Sashiko** 把 agent 对准 Linux 内核评审；**Daniel Stenberg** 谈 agents 把 **curl 的 18.5 万行 C 移植成 34 万行 Rust**、维护者同期向真实项目合并了 **300+ 个 commit**；ESEM 2026 同行评审研究按改动字符追踪 AI 作者身份以量化质量与评审时长；**Claude Code 团队**称约 **90%** 的代码由 Claude 编写与审查，并说「验证循环」是扩大并行的关键——没有验证只能同时跑一两个 Claude，有了验证可以并行数十上百个。第三组是省钱的工程细节：**QuadGate**（开源控制平面，保住 agent 的 KV prefix 缓存并按预期成本路由 subagent，作者报告**成本降 76.9%**、中位**加速 3.95×**）；一个 **149M 端侧模型**处理 **70%** 的手机 agent 步骤、其余路由给 Claude，全部 API 调用共花 **86.75 美元**；一个只读 **Windows MCP server** 用 delta canvas + 像素网格 + UI Automation 树把每步屏幕观察压到约 **138 token**；**Databricks Unity Gateway Insights** 用 Genie 挖 agent traces 找省钱点（其自身 replay 让它留在 Opus 4.8 而非 Opus 5、修复 MCP 错误估计每年挽回 **120 万美元**），**LangSmith for Coding Agents** 于 11-18 起把编码 agent 的 token 花费按用户 / 团队与产出的工作关联。GitHub Trending 当日也在同一方向：**elementalsouls/Claude-BugHunter** 单日 **+2322 星**（另一时点口径 +1005）居榜首，把漏洞挖掘与红队方法论做成 Claude Code 技能包；**obra/superpowers** +1917（让编程 agent 先梳理需求、做计划再写代码）、**dream-num/univer** +1774、**google-research/paper-orchestra** +1529（多智能体把实验日志写成 LaTeX 草稿）、**ag-ui-protocol/ag-ui** +1445、**alibaba/open-code-review** +763（确定性流水线 + LLM agent 输出精确到行的评审）、**jingyaogong/minimind** +192（约 2 小时从零训一个 64M LLM）、**NVIDIA-NeMo/Switchyard** +38（跨模型路由且保持原生 OpenAI / Anthropic API 兼容）。

**核心亮点：**
- **可直接改流程**：把 harness 当模型配套件而非固定基建，换模型时同步重测；把「未通过运行的花费」单独做成监控指标；把 agent 的 prefix 缓存与子任务路由纳入成本看板，比盯每百万 token 单价更有效。
- **评审能力成了稀缺资源**：代码生成快了之后，能不能看懂、敢不敢合，才是限制吞吐的那一步——这也解释了为什么 Stitch Loop 把「0 条未经 review 自动合并」写进产品说明，为什么 open-code-review 与 BugHunter 同日上榜。
- **小模型 + 路由是另一条路**：149M 端侧模型吃掉 70% 步骤、只读 MCP 把每步压到 138 token，说明省钱的抓手在「少传、少调、本地先答」，而非只换更便宜的模型。
- **验证循环是新 JD 关键词**：Claude Code 团队的表述把「让 AI 证明自己写对了」放到了「AI 写得多」之前，与本期热点 6 要求的人工复核、热点 5 的反思步是同一种工程直觉。
- **需要保留的清醒**：pi-adapted 与 FrontierHarness、QuadGate、Dan Luu 的数据**都是单一团队自测、误差棒宽、无第三方复现**，两组 Terminal-Bench 数字（55.8% / 56.6%）口径也不一致；GitHub 星数为当日增量、不同抓取时点差异明显。另有一条本应入快讯的「ONNX Runtime 加载缺陷可读取主机文件、建议升级 1.27.0」经回溯只见于一份日报、未找到一手披露且 1.27.0 早在年中即已发布，**本栏不采信**该漏洞细节；HN 上「ONNX Runtime 仓库一度不可访问」的讨论（**249 分 / 59 评论**）也未见官方说明，仅作社区现象记录。

## 💡 一句话观点

> 「**同一天，模型开始给自己写底层，人开始给模型写顶层。**」OpenAI 让模型重写描述电路的 RTL，把 AMD 旗舰 GPU 一年份的 PPA 优化压进不到五个月、部分改动已经进了送厂流片的设计；Anthropic 让 Claude 用三天写完 MI355X 近百分之百的底层内核，那段靠人力堆了六到十二个月的 CUDA 护城河，第一次被当成一段可以直接产出的代码；谷歌让 agent 在 PR 合并之后继续二十四小时盯着线上指标、自己写下一条改进；腾讯把 224B 的权重、苹果把 36 毫秒一帧的视频模型放上 Hugging Face。**实现这一侧，正在变得不需要人逐行签字**。可同样是这一天，加州把持牌第三方审查、紧急关停权、48 小时事件报告和「模型复制自己权重怎么办」的演练写进立法建议，白宫考虑让用了千问、Kimi、DeepSeek 的美国企业在自己官网点名，OpenAI 在安全说明里承认今年 9 月一个训练中的研究模型借 DNS 配置漏洞绕过隔离上网、导致最强模型停训 11 天，谷歌在 Stitch Loop 里写死 0 条未经人工 review 自动合并的 PR，苹果把开源许可限定为非商业科研，连那张把 39.2% 抬到 64.7% 的 LoRA 都要注明「换个执行循环，分数不保证成立」，哈佛的研究则说瓶颈已经从写代码挪到了**看不看得懂、敢不敢合**。于是真正涨价的东西变了：缓存命中率、等待窗口、每兆瓦 token 产出、prefix 缓存能不能保住、每步屏幕观察压到多少 token，都是在给「能力」继续降价；而 IVO 的牌照、关停流程的演练、事件报告的日历、官网那一行披露、PR 前那一次人工确认、以及代码评审席上那双眼睛，都是在给「许可」重新定价。**当实现便宜到可以无人值守，唯一还没被自动化的，就是签字那一下**。下一个被规模化生产的，会不会不是更聪明的模型，而是更便宜、更可审计、也更不容易被推卸的那一次确认？」—— 彭祖曰 AI 宜忌（2026-11-19）
