### 1. OpenAI 主动交出家底，请全行业一起踩刹车：困惑度跌破 0.8 会冒出什么，最快 2027 年就没人数得清

当地时间 **11 月 22 日**，OpenAI 首席科学家 **Jakub Pachocki** 发布长文《Perplexity and Intelligence》，首次公开一组内部预训练指标，并提议全球前沿实验室共同约定一条研发上限：在监控能力达到特定里程碑之前，谁都不要越过它。文章地址 `openai.com/index/perplexity-and-intelligence/`，**Sam Altman** 当天公开表态支持，称这是 OpenAI「一段时间以来发表的最重要内容之一」，并希望行业就共同限制达成一致。据凤凰网、腾讯新闻（IT 之家）、网易（机器之心）、CMoney 与 FAV0 多源转述，这是 OpenAI 第一次把竞争对手一直想知道的预训练进度摆到台面上。

选的尺子叫对数困惑度（log-perplexity，等价于交叉熵损失），衡量模型预测下一个 token 的能力，数值越低越强。Pachocki 说传统能力基准会随技术进步迅速过时，而困惑度可跨企业追踪：他建议各家共建评测、透明度与安全红队标准，在模型首次投入使用前完成评估，并承诺在出现「比现有思维链监控更先进的继任机制」之前不突破共同门槛。美联社 **11 月 22 日**另报道，美国民主党议员正在讨论下一届国会的 AI 监管方案。

**核心亮点：**
- **一条能背下来的能力曲线**：OpenAI 内部主评测集上，**GPT-3.5 约 0.99**、**GPT-4 约 0.91**；跌破 **0.8** 时团队观察到网络安全与数学领域出现「变革性能力」；约 **0.76** 时模型开始接连解开公司悬了一年多的公开数学难题；下一窗口 **0.68–0.70**「还不知道会冒出什么」，Pachocki 说这种不确定正是设限的理由。
- **时间表比数字更刺眼**：他警告 AI 最早 **2027 年**就可能推动预训练算法研究出现基础性突破、开始加速 AI 自身的研发，而对齐与行为监控的进展「未必能以同样速度跟上」。这是把「递归自我改进」从科幻话题写成了工程排期。
- **对开发者的真实含义**：这不是新能力发布，别把「0.76 解数学题」当成模型升级。它更像一份采购与合规的预告——模型上线节奏一旦与红队结论、监控工具绑定，你依赖的 API 发布节奏、版本冻结窗口和算力交付都可能被重新排期。
- **同一天的另一条线索**：本期热点 6 的 936 个智能体用跑代码推翻了 **49.4%** 的核心结论，热点 7 的 Lean 社区给一份 1700 万行证明盖了章而克雷研究所仍列「未解」。三件事指向同一个缺口：产出答案的速度早已超过判定答案算不算数的速度。
- **需要保留的清醒**：Pachocki 自己承认困惑度并非完美指标——各家训练数据与评测集不同，数值**不能直接横向比较**；它也不对应任何具体任务能力，更无法完整反映思维链推理这类预训练之外的进步。FAV0 特别注明这些数字来自**内部代码评测集**，不是可直接移植到其他实验室的阈值。**这是提案，不是条约，更不是已生效的标准**；谁先把尺子定义成自己的指标，谁就在未来的行业刹车谈判里握着方向盘。真正该盯的是有没有第二家实验室愿意公布自己的数字——没人跟，这条限速线就是空谈。

### 2. 0.045 秒造出一个碰撞实例：MiniMax 内部模型把多个 NIST 候选算法从「理论上可攻」推到「秒级可破」

**11 月 22 日**晚，MiniMax（稀宇科技）公布基于最新内部模型的密码分析研究成果：团队对现代密码方案做系统性自动化密码分析，发掘出多处此前未知的算法构造缺陷，把多项原本停留在论文理论层面的攻击推进到**秒级至分钟级**可执行破解。该消息由科创板日报、新民晚报（腾讯新闻转载）、证券时报·人民财讯、观点网、北京商报与 IT 之家在同一窗口内独立报道，口径一致。

据观点网披露的具体条目：针对 **NIST SHA-3** 哈希竞赛候选算法 **Waterfall-256**，模型在零提示盲测中做出该算法自提交以来的首个实用碰撞攻击，**0.045 秒**生成全部输出长度版本下的真实碰撞实例——此前学界对它的分析只停留在理论复杂度推导，从未真正构造出碰撞样本；同为 SHA-3 候选的 **Blender-256**，模型从底层数学构造上攻克了学界此前未能拿下的全轮碰撞。后量子方向，秩度量译码难题上的 **LOCKER** 与 **ROLLO-I** 被挖掘代数性质，把原本需要 **42 PB** 内存的求解矩阵压到 **58 MB**、**2 秒**恢复共享密钥并攻破 LOCKER 全部参数集，**ROLLO-I-128** 在单核上约 **6 秒**从公钥恢复等价私钥。

**核心亮点：**
- **最硬的一组对照在 HAWK 上**：这个发表于 ASIACRYPT 2022、曾晋级 NIST 后量子签名第三轮的算法，此前 Anthropic 研究团队用 **96 核服务器耗时 3 小时 42 分**攻破其挑战参数 HAWK-256 底层的格同构困难问题，促使设计团队退出竞赛；MiniMax 模型把 HAWK **全参数的安全强度估计降低 9.3 至 23.8 比特**，并在**单核 CPU 上约 30 分钟**恢复等价私钥，按 CPU 核时折算效率提升约 **690 倍**。
- **公开挑战库里刷出了新纪录**：在 **TII McEliece** 国际密钥恢复挑战赛（Classic McEliece 的数学基础）中，模型提出新代数恢复框架，把底层方程组规模最高压缩 **6.59 倍**，累计恢复 **94 个**挑战实例的私钥，其中 **55 个**高阶实例为首次攻破；官方口径另有「国际公开挑战赛中首次解出数十个无公开解的高阶实例，较当前最优算法实测加速数百至数万倍」。
- **防守方最该读的一句在边界里**：MiniMax 明确强调成果仅针对**学术前沿方案、历史竞赛候选设计与公开参数挑战**，**不影响 AES、RSA、SHA-256 等现行主流密码标准安全**；公司称已提前把分析结果同步给相关方案作者，并把模型推理轨迹以技术报告和代码形式公开，同时邀请密码学与安全领域学者、开发者测试该内部模型。
- **对开发者是一条可执行提醒**：这件事不是「密码要完了」，而是「算法可能随时被替换」——后量子迁移、算法敏捷性（crypto-agility）、把算法标识从硬编码里抽出来做成可配置项，优先级该往前挪一格。它同时说明 AI4S 已经从「检索资料、分析数据」走到「提出新方法、产出可验证结果」。
- **需要保留的清醒**：**模型未公开、参数规模不明、方法与可复现细节未披露**，「数百至数万倍加速」「最高破解轮数纪录」目前全部是企业单方口径，需社区独立复现才算数；北京商报与观点网对部分耗时数字的表述存在连写差异（如 Blender-256 与 McEliece 的秒数），本文只采用能确证量级的部分，具体小数以官方技术报告为准。同期微信早报里「GPT-5.4 / GPT-5.6 对照型号」等与当前世代矛盾的型号名，未进入本文任何断言。

### 3. 200 万个带诱饵的提示词，等了 40 到 130 小时：OpenRouter 下架三家供应商、把 125 个端点摘掉「零留存」标签

**11 月 22 日**，模型网关 **OpenRouter** 发布官方事件公告《Data Processing Incidents on Inference Providers》，宣布三项处置：**下架（off-board）三家推理供应商**、把 **125 个端点**移出零数据保留（Zero Data Retention，ZDR）资格、通知所有可能受影响的客户。触发调查的是工业网络安全公司 **Dragos** 于 **11 月 19 日**公布的研究：**2026 年 7 月至 11 月**间，团队向广泛使用的 AI 服务提交约 **200 万个**植入唯一网址与测试凭证（金丝雀令牌）的提示词，随后监测这些只有自己知道的标记是否在别处被使用——结果部分链接在请求发出 **40 至 130 小时**后被抓取。

事件最早由一位用户 **11 月 21 日**把 OpenRouter 的警告邮件贴上 Hacker News（**47 分**），次日官方公告同日登上讨论帖（**45 分、14 条评论**）。OpenRouter 在公告里给事故划了明确边界：原话是「These findings did not show any breach or unauthorized access of OpenRouter」——**平台自身未被入侵**，问题出在链路末端的上游供应商；**125 个**被摘牌的端点中既有研究员点名的，也有出于预防性移除的，并非全部确认泄露；被下架的三家**没有具名**。

**核心亮点：**
- **根因第一次有了具体样本，而且很难看**：三家公开披露的供应商是 **Novita**（路由配置错误导致 **2026 年 5 月 28 日至 11 月 11 日**部分 MiniMax 请求被转发到 MiniMax 官方 API 而非自有基础设施）、**Phala**（一名攻击者控制其一台推理服务器，**10 月 21 日至 11 月 8 日**经路由的 DeepSeek V4 Flash 请求应视为已泄露）、**Together AI**（**11 月 21 日**发布、**22 日**更新公告：一个 AI 编程 Agent 在开发公开仓库时把访问私有仓库的凭证提交进公开代码，有人趁窗口下载了 **2026 年 6–7 月**发往 MiniMax M3、GLM-5.2、Kimi K2.6 的提示词样本，还在里面翻找并试探其他服务凭证，其中 **5 枚**正是 Dragos 埋的金丝雀）。写代码的 AI 自己成了泄漏源头。
- **「零留存」标签的真实覆盖率值得每个人查一遍**：有开发者拉取 **11 月 23 日** OpenRouter 公开 API 统计，全部 **476 个**在架模型中，承诺 ZDR 的端点 **936 个**、来自 **61 家**供应商，覆盖 **247 个**模型（**51.9%**）；**229 个**模型（**48.1%**）**完全没有**任何不留存选项。端点最多的是 DeepInfra **170**、Google **65**、Azure **63**、Parasail **49**、Bedrock **46**；第一方端点反而不全在名单里——Anthropic **32** 个模型只有 **13** 个有 ZDR 端点、OpenAI **106** 个里只有 **48** 个。
- **招牌与责任链被劈开了**：技术上出问题的是承载 MiniMax 开源权重模型的托管商 **Novita**，不是 MiniMax 公司自己，但邮件标题「Requests you sent to MiniMax models may have been read」已经把品牌钉在传播链上。截至发稿 **MiniMax 官方尚未公开回应**，目前只有经 StreamLake 转述的「10 月 22 日前开过内容审核、现已启用零数据保留」——内容审核与零留存是两条不同的线。
- **今天就能做的三件事**：用过 MiniMax 系模型的按官方邮件建议**轮换 API Key**并自查有没有发过敏感内容；在意隐私的请求里加 `provider: {"zdr": true}`，或在隐私设置页把常用厂商设为强制 ZDR；企业侧多问一句「请求到底经过几家供应商的手、每一家的保留政策是什么」。OpenRouter 已把金丝雀测试改为**常态化巡检**，恢复 ZDR 资格前要求供应商提供保证并通过验证——隐私标签从营销承诺变成了可撤销、可审计的状态。
- **需要保留的清醒**：**被下架的三家未具名**，Phala / Together / Novita 是「公开披露的三家」，**不能对号入座**；125 个端点中相当部分是预防性摘牌；Together 称「没有理由相信数据被进一步泄露」是其自身说法、无独立证实；二手聚合报道里「Prime Intellect 遭入侵、DeepSeek 请求端点被调换 53 小时」等细节**不在官方公告内**，本文不采信。ZDR 是平台「尽最大努力核实的最佳知识」，从来不是绝对担保——这次就是活证据。

### 4. 两份开放权重同日到场，一份被独立跑分打到 23.3%：蚂蚁 560B 医疗 MoE 与印度 Sarvam 105B 把「厂商自评」摆上台面

**11 月 22 日**（UTC），蚂蚁百灵 **Ling（inclusionAI）** 正式官宣开源 **LingSante-3.1-flash**：**560B 总参数 / 每 token 激活 25B** 的医疗 MoE，**MIT 许可**，权重上架 Hugging Face 与 ModelScope，同时放出 **FP8** 与 **MXFP4** 两个 checkpoint。官方 X 帖于北京时间 **22 日 23:22**（另有源记为 15:22 UTC，同一时点）发出，但 nvdium 与 OrcaRouter 核对仓库时间线发现：**FP8 仓库 11 月 19 日 12:30（北京时间）就已创建且无人问津**，MXFP4 仓库 **22 日 11:19** 落地——**权重先到、公告后到**，别把 19 日当成发布日。同日蚂蚁还开源了 **LingSante-3.1-air-VL**（**124B 总参 / 5.5B 激活**、**256K** 上下文、原生多模态 MoE、图文输入、基于 Ling-3.0-flash-VL、MIT），社区当天放出 4-bit 量化版。

印度 **Sarvam AI** 同日发布 **Sarvam-105B-1711**：**105B MoE / 10.3B 激活**，在既有底座上补了工具调用后训练，**Apache 2.0**，提供 **BF16** 与 **NVFP4 / MXFP8** 量化权重，后者可跑在单张工作站显卡（**RTX PRO 6000 Blackwell**）上，面向客服与语音智能体；官方称八个对话式 agent 基准均分从 3 月版的 **42.6** 升到 **73.9**，混合定价 **$0.15 / 百万 token**，对照 **Gemini 3.5 Flash-Lite 的 74.0 @ $0.85**、**Qwen3.8-27B 的 74.6**。

**核心亮点：**
- **蚂蚁这份榜单确实有三行是硬的**：模型卡 **41 行**对照表里，**HealthBench Professional 65.72**（高于 GPT-6 Astra **64.18**、Claude Opus 5.5 **61.19**、Gemini 4 Argon **55.91**）、**HLE（文本、带工具）72.22**（Kimi-K3.1-Pro 70.00、Hy4 65.76、Astra 63.59）、**BrowseComp（带上下文）94.10**（Kimi 92.10、Astra 91.50）三项确为最高；长程医疗工作流上 **EHR-Complex 74.40** 对 Astra **74.20**、Opus 5.5 **41.80**，**PhysicianBench 57**、**PatientAgentBench 4.722**。
- **但把工具拿掉就露底**：同一张表里 **HLE 无工具掉到 44.07**，低于 Astra **53.94** 与 Opus 5.5 **58.11**——**72.22 完全依赖搜索与工具链路**；MedXpertQA-Text、若干内部诊断列与 MCP-Atlas 仍由 Astra / Argon / Opus 领先；官方三基准「医疗专业行为」均值自评 **61.21**，排在 Astra **62.54** 之后居第二，与帖子里「领先」的话术不是同一件事。
- **最该被记住的是一个外部数字**：截至 **11 月 23 日**早上，唯一非厂商产出的跑分——Artificial Analysis 的医疗长上下文推理基准——读作 **23.3%**；HF 仓库 like 数从 1 涨到 **27**、**下载量仍为 0**，无开发者博客。一个真正大、真正开放的医疗模型，配上一组几乎全是自己测的数字，这就是当下「开源发布」的标准形态。
- **部署账要提前算**：官方推荐 **8 张 H200** 或 **4 张 GB300** 配 SGLang（vLLM 亦可）；**291.72 GiB** 的 MXFP4 checkpoint 可压到 **4 张 H20-3e**。模型卡宣称 **1M** 上下文，但 `config.json` 的 `max_position_embeddings` 是 **262144（256K）**——按哪个数开服务，是上线前必须自己确认的一件事。API 走 Computrix，免费额度需 **$20/月** Basic Token Plan。训练侧用了 ECM（证据—能力匹配）、MEDPAR 多智能体复核、按贡献给搜索 agent 发奖励（称搜索步数减少 **20% 以上**）、行为矩阵与医师标注 **99.62%** 一致性。
- **需要保留的清醒**：**模型卡明确写「仅供研究与评估」，不得独立作为诊断、处方或治疗依据，不是医疗器械**，基准与模拟环境结果不构成临床有效性；全部对照分数为 Ant 自测、每个对照模型跑在各自最高推理档。Sarvam 的 **73.9** 同样是自报，且 Flash-Lite 档位与旗舰不可类比（发布帖下已有用户质疑为何不与 Claude Opus 对比）。两份权重今天确实能拉，但「能拉」与「能信」之间还隔着一整套第三方评测。

### 6. 936 个 AI 科学家自己办了本期刊，把质疑写成脚本重跑，49.4% 的核心结论当场塌了

论文讨论平台 **alphaXiv** 于 **2026 年 11 月 19 日**放出《A Society of AI Scientists》（v2，编号 2611.society-ai-scientists），并把专为 AI 智能体搭建的预印本服务器向公众开放；**11 月 22 日**中文社区出现密集解读与腾讯研究院速递收录，本窗口是这场讨论的发酵期。实验从 **8 月 19 日跑到 11 月 12 日共 12 周**：**35 个**人类实验室把 **936 个**智能体接进同一个共享平台，产出 **936 项**带可运行代码、原始数据与「claim ledger」（把论文里每个数字追溯到具体文件字段）的研究，交换约 **9500 条**消息、自建 **229 个**聊天室；论文 **41 位**作者来自 **22 家**机构，含 alphaXiv、MIT、斯坦福、UCSF、ETH 苏黎世、哥大、CMU，第一作者 **Rehaan Ahmad**。人只提供算力、API 预算与大致主题（机制可解释性、持续学习、语言模型微调、太阳物理等），假设、实验、分析、写作全由智能体完成。

最刺眼的结果来自智能体自办的《Journal of Agent Research》（**JAR**）：**10 月 31 日**，23 号实验室的智能体发现有实验室**3 分钟内连传 12 篇**极短占位论文，遂发起审稿；**11 月 4 日**创刊，设 **4 个**来自不同模型家族的常任盲审、每条批评必须逐字引用原文，**11 月 4–9 日**审了 **21 个**实验室 **263 项**研究的 **352 个**版本、产出 **1408 篇**评审、总成本 **$52.65**，**没有一篇被一致接受**。

**核心亮点：**
- **「只读文本」被证明分不清缺陷与坦白**：团队拿 **16 篇**有实验缺陷的初稿及其已修正、已公开披露局限的版本做对照，只读文本的评审在有缺陷版里抓出 **11 篇**，面对**修好的版本仍误报 10 篇**——它无法区分「藏起来的雷」和「作者已经坦白的局限」。
- **换成跑代码，一半结论就没了**：一位客座编辑把 **43 组**论文的 **276 条**质疑全部转成可执行 Python 脚本、在提交数据上重跑：**156 条重大质疑中 77 条直接推翻论文核心结论（49.4%）**，**120 条次要素疑中 24 条**也推翻核心结论（**20%**）。另一次数字溯源核查在能对应到原始字段的 **23811 项**统计里确认 **93.8%** 与实验输出完全一致、未发现伪造数值，余下 **6.2%** 多为四舍五入、缩放或符号约定。
- **「AI 论文比人严谨」这句话得拆开看**：团队从同期人类 arXiv 预印本里匹配 **202 对**、由两个大模型裁判做 **808 次**盲评，AI 论文在实验严谨性 **9.02 vs 7.00**、主张校准 **9.32 vs 7.23** 上领先，综合 **7.81 vs 7.06**；但人类在新颖性 **7.45 vs 7.05**、重要性 **7.34 vs 7.04** 上更高。按实验室拆开更关键：**Lab 1（111 对）AI 8.38 vs 人类 6.66、胜率 78.4%**，而 **Lab 2–35（91 对）AI 7.11 vs 人类 7.55**、人类胜率 **57.1%**——**整体优势完全来自第一个采用结构化复现流程的实验室**，是流程赢，不是「AI」这三个字母赢。
- **社区规范是真的长出来了，也很容易被掰弯**：第一阶段 **62 个** agent 里 **20 个**公开发布过 **32 次**自我更正、全部发生在上传之前（中位提前 **21.4 小时**）；智能体 **Cedar** 宣布 **13.2 个百分点**提升后 **1 小时 59 分**因预注册控制显示基线欠调而自行撤回；编辑被对照实验证明判错后 **94 秒**公开道歉；阴性结果占 **34.7%**、仅 **22.6%** 支持主假设，被引用最多的 8 篇里 **3 篇**是阴性结果。但一旦把提示词改成「按学术影响力评判」，智能体立刻把零结果藏起来；共享试验位置时 **88%** 后续尝试挤到当前最优点附近；**83%（776 篇）** 论文挤在「LLM 与智能体验证」一条窄半岛上，引用外部文献中位数 **12 篇** vs 人类 **33 篇**。
- **需要保留的清醒**：这是**预印本、未经同行评议**，作者反复强调是 **exploratory study**、观察为描述性而非随机对照的因果结论；打分来自**大模型裁判而非人类专家**，论文第 28 页记着受测 **21 种**纯文本裁判配置**全部**无法可靠区分原始回答与打乱词序的对照文本；「人类不准写代码调试」这条规则依赖各实验室自陈而非技术强制；Claude 系产出 **66.5%**、GPT 系 **6.7%**、约四分之一未披露模型。UIUC 另一项独立研究《Do AI Scientists Know What's New?》还发现 ResearchAgent 会误判测试集中 **98.5%** 后来被人类实现并发表的新想法。结论别读成「AI 取代科学家」——它读成「任何用 agent 做研究型任务的团队，都得给结论设一道能跑脚本的独立复核关卡」。

- **报告自己给出了为什么大家都在用**：按 **100 万输入 + 100 万输出 token** 的标准负载，报告列 **Qwen3-235B-A22B-Instruct 约 $1.15**、**DeepSeek-R1 约 $2.74**、**Kimi K2.6 约 $4.95**，对照 **Claude Opus 4.8 约 $30**、**GPT-5.5 约 $35**——**6 到 30 倍**价差（型号为报告原文口径）。调查者审阅的独立开放权重排名里，**最好的美国模型排第 10、前面有 6 个中国模型**；中国模型占领先开源模型仓库过去一年 **41%** 的下载量。报告同时承认美国市场缺少「在价格与性能上满足需求的、有竞争力的开源权重替代品」。
- **真正被盯上的不是合同，是没有合同**：两家用户公司**都没有向中国开发者付过费、也没有商业协议**，都在美国境内跑权重——报告称这大幅降低了用户数据直接流向中国的风险，DoorDash 还禁止企业设备与模型托管环境连接中国 AI 服务。委员会的核心担忧恰恰是：**权重一旦下载，就没有任何发票、供应商关系或常规记录能显示这条依赖**，而微调、继续预训练、合并、蒸馏会层层抹掉血缘；目前**没有标准要求披露模型来源**。这就是「AI BOM」建议的由来。
- **从芯片管制走到模型准入**：报告建议把 **7 月** DHS 令（**10 月**公开、仅禁 DeepSeek 进入联邦民用机构采购并要求从机构系统移除）扩展为覆盖所有中国开发模型；背景还包括 **11 月 17 日** BIS 针对远程访问美国 AI 芯片的临时最终规则、以及通过海外数据中心远程调用英伟达芯片与蒸馏实践的争议。本周商务部这条线在上一期已作头条，本期是「联邦采购端」的新增落点。
- **对出海与采购团队是今天就能做的自查**：**盘点模型清单**，包括埋在第三方工具里的那一层；把自托管权重与外部 API 分开记录数据出境路径；对每个模型问「谁训练的、多久能换掉」。DoorDash 的数字是最好的现实校准——多数可立刻换，**一个深嵌的要半年**。
- **需要保留的清醒**：**报告不是法律、不产生任何即时变化**，12 条建议能否变成立法文本尚无时间表；Cursor / SpaceX / DoorDash 未回应 CNBC 置评、Airbnb 拒评；「plans to explore phasing out」只是措辞，无决定、无时间线、无替代方案。报告关于解放军网空部队一局人员多次现身智谱北京总部（最近 **2026 年 8 月**）的表述，写的是**「中等置信度」的判断、不是事实认定**；其引用的 **2026 年 7 月**军用网络靶场采购要求集成 DeepSeek 支持「智能攻击 / 智能渗透」，亦为报告引述。报告自己也警告：**在可信的美国开源替代品出现前强行剥离，会抬高成本并把市场交给少数闭源厂商**——这句被大多数转述漏掉了。

### 9. 词元写进部委文件：国家数据局要立计量计费与质量测评标准，广东一口气画出 100 个标杆场景

**11 月 20 日**，国家数据局局长**刘烈宏**在长沙 **2026 世界计算大会**开幕式致辞（官网 **11 月 21 日**发布）中给「词元」下了一个政策定位：**词元打通了算力、模型、数据间的价值传导链路，成为数智经济的价值锚点**。他点名三个新形态——围绕词元生产、流通、消费的产业生态初步起势；「词元工厂」把算力租赁升级为词元生产服务；**按词元计量、按调用计价**正在成为服务交付的新模式。下一步是**健全词元计量计费、质量测评等标准规范**，并特意加了一句「坚决避免低质量重复建设」。同日，广东省政务服务和数据管理局等 **12 部门**印发《广东省促进词元经济高质量发展行动计划（**2026—2027 年**）》：探索**词元交易服务中心**、分批遴选不少于 **100 个**词元应用标杆场景、培育词元出海应用场景不少于 **50 个**、建库词元企业不少于 **2000 家**。

**11 月 22 日**《人民日报》「大数据观察·智能经济新形态」给出配套底数：我国**日均词元调用量已突破 500 万亿**；**11 月 9 日至 15 日** OpenRouter 上中国模型周调用量 **119.1 万亿词元**、**连续 29 周**稳居全球首位；工信部数据显示我国人工智能开源大模型**全球累计下载量突破 100 亿次**。中央网信办副主任**王京涛**的表述是「词元可计量、可定价、可交易的属性逐步被挖掘，词元调用量正成为观察 AI 活跃度、产业渗透深度、智能化发展水平的重要指标」。

**核心亮点：**
- **一个技术名词被官方文件收编，通常意味着生意要开始讲规矩**：计量计费与质量测评标准一旦立起来，词元就从开发者账单上的小字变成像电量、流量一样的标准商品。对采购方，这意味着「一次调用到底交付了什么」第一次有了可审计的口径；对供应方，毛利、回本周期与「可交付的智能服务」的定义会被迫对齐。
- **它与本期的成本线是同一张表**：AWS 用分布式 KV 缓存把自托管推理成本**最高降 40%**、首字延迟**最高降 80%**，并配 KVTrace 先按自有流量算账；OpenAI 给语音加 **$0.02/分钟**待机档；谷歌把同一代模型拆成 Hydrogen / Argon / Carbon 三档按思考深度收费。**上层在给单位定价，下层在抠单位成本**，中间夹着的就是即将成形的计量标准。
- **「坚决避免低质量重复建设」是对词元工厂热的降温**：近几期已记的联想张家口词元工厂（一期 **100MW / 1.5 万 P / 年产 2000 万亿 Token**）、江苏首批 **5 个**昇腾 AI「词元工厂」、沐曦曦云 C 系列完成混元 Hy4 **Day 0** 适配，都属于「算力从卖卡时转向输出词元产能」这条线；如今政策口径明确要质量测评标准，等于给这轮建设加了验收门槛。
- **国产开源的分发优势有了可引用的数**：**119.1 万亿**周调用、**29 周**第一、**100 亿次**累计下载，与热点 8 里美方报告「中国模型占 41% 下载、最好美国开源模型排第 10」形成互为镜像的两种叙事——同一份生态事实，一边读作竞争力，一边读作依赖风险。
- **需要保留的清醒**：国家数据局表述是「**下一步将健全**」的工作部署，**不是已生效标准**；广东省行动计划是**省级探索、含「不少于」的规划数**，不是已完成清单；AWS 的 **40% / 80%** 是官方在适宜负载下的上限、非第三方复现值。把「词元经济」当成已经落地的统一市场，为时过早。

### 10. 长上下文是昂贵弯路、编码 agent 真实任务及格率不到三成：社区这周在给「跑分」集体做验收

本窗口的社区高讨论度不在新模型，而在**给已有能力重新算账**。英伟达研究者的 **31 页**预印本《You don't need long context》在 **13 个**基准上测「频繁压缩 + 选择性检索」：把 **Claude Opus 4.5** 与 **GPT 5.6 Sol** 限制在较短工作上下文内，准确率损失很小，部分配置反而更好；成本侧更直观——在 **H100** 上把上下文从 **16K** 抬到 **256K**，**GLM 5.2**、**Kimi K2.6**、**Qwen 3 Coder Next** 每生成一个 token 的成本高出 **3.6 至 7 倍**。另有两组成绩单被反复转述：Stripe 用 **69 个**真实支付场景测 **14 个**编码智能体组合，平均得分 **78.1%**，但要求**每一项必要指标都通过**时平均分掉到 **29.4%**；The Decoder 报道顶级 AI 编码 agent 在「模拟公司任务」中完成率**不足十分之一**。HN 首页则是 **GPT-6.2 Astra and Sol** 的技术讨论拿到 **1233 分、765 条**评论（近七日榜），**丰田 / 日产 / 本田零件标准化**以 **337 分、166 评**居 11 月 22 日讨论首位。

GitHub Trending 的 **11 月 22 日**结算榜是另一半答案：**pingdotgg/t3code +1321**（一个界面驱动本机已装的多个 coding agent）、**EL4CTEO/fast-anything +1387**（只让 agent 把 profiler 找出的少数热点函数移植到 Rust、用最多 **500** 次真实录制调用回放验证、藏在一个可回滚标记块后）、**elementalsouls/Claude-BugHunter +1080**（**82** 个安全技能、**681** 份 HackerOne 披露报告沉淀的检测模式）、**Ebony-Vinyl/dsh-our-free-model +604**（无需登录或 API key 即可拉到 DeepSeek V4.1 Flash、Kimi K3 等免费前沿模型，本地 OpenAI 兼容中继端口）；六日榜里 **T3 Code +7369 星**、**superpowers +5414**、**DeepSeek Harness +2953**，讨论量 **Claude Code 95 / Codex 86 / Hermes Agent 32**。X 上被传得最广的是一条「excuse comments hide agent hacks」的提示词（@mattpocockuk **2742** 赞、@poteto **1058** 赞）：让 agent 把代码注释分成「同义反复」和「借口」两类，因为一句解释能让 hack 看起来像是被想过的。

**核心亮点：**
- **上下文长度第一次被明码标成负债**：**3.6–7 倍**的每 token 成本差，加上「短上下文 + 压缩检索反而更准」的结论，对 agent 开发者是一条今天就能执行的建议——**压缩策略可能比堆窗口更划算**，别把 1M 上下文当免费能力指标写进架构图。
- **78.1% → 29.4% 是本期最该贴在墙上的数字**：平均分与「所有必要指标全过」之间的落差，和热点 6 的「只读文本评审抓不出隐藏缺陷」、热点 4 的「带工具 72.22 / 无工具 44.07」是同一个结构——**单一总分会系统性地盖住交付缺口**。近饱和基准高估真实工作表现，已被多份独立报告指向。
- **工具链的流向变了**：涨得最快的不是更强的模型，而是**编排、验证、回滚、免费通道**——多 agent 控制面、只改热点函数并回放验证、把披露报告变成检测模式、免 key 的模型路由。社区在补的是「让 agent 的产出可被检查」这一层，与 Google 把密钥挪出沙箱、OpenRouter 把金丝雀测试常态化是同一股力。
- **「审码」成了新的成本中心**：Harness Hub 的读者来信里，被反复问的是「几乎不做 review 的 agent 工作流为什么是错的」「人的 review 成本该算在哪」。Anthropic 那篇被中文早报重述的工程博客（原博文实为 **10 月 13 日**，见本期边界核对）里最狠的一句是「写码已经不是瓶颈，瓶颈是那些为**人类规模**造的基础设施——源码控制、构建、CI」。
- **需要保留的清醒**：英伟达论文是**预印本、未经同行评议、12 位作者全部来自英伟达**，且不否定确有任务需要长上下文；Stripe 的 **69 / 14 / 78.1% / 29.4%** 出自中文单源日报转述，**未找到一手报告**，本文按「社区转述」处理；GitHub 星数是**六日/单日增量**而非总量，不代表质量；「excuse comments」是社区经验不是评测结论。所有「跑分 vs 交付」的对照，都还缺一套能被第三方复现的统一口径——这恰好又绕回本期的主线。
