### 1. Claude Code 的「别再问我」按钮，把 1,379 个真密钥写进了公开仓库

应用安全公司 **Apiiro** 11 月 7 日公布的研究显示：Claude Code 在用户点击「Yes, and don't ask again」时，会把整条 shell 命令——包括命令里明文写着的密码——写进项目内的 **`.claude/settings.local.json`**。研究团队在 **11 月 1 日至 3 日**扫描 GitHub，发现该文件有 **104,185** 份公开副本，其中 **1,122 份至少含一个真实密钥**，去重后共 **1,379** 个；把 git 历史、团队共享的 `settings.json` 与保存的会话记录一并计入，密钥总数升到 **2,539** 个，分布在 **1,994** 个公开仓库、**63 家组织**（多为软件公司）。这是本月 Claude Code 第二起隐私事件，上一回是 User-Agent 里带出用户邮箱。

泄漏清单读起来像一份反面教材：某数据库厂商把自己**管理员级、无过期时间**的云 API Key 连同集群地址一起公开；某 B2B 创业公司泄漏了生产环境 Azure Postgres 密码；某软件代理公司泄漏 Square 生产环境访问令牌；某做病历系统的 IT 服务商把数据库 owner 密码提交了上去；一个 **1,000+ star** 的开源项目公开了 OpenAI 格式的 API Key，另一个公开了 npm token。

**核心亮点：**

- **机制不是漏洞，是「字面主义」**：权限规则保存的是完整命令字符串，而不是命令的意图。开发者让 agent 去排查数据库连接，命令里必然带凭据——Claude Code 忠实地把它当作 allow rule 存了下来。
- **保护只覆盖其中一小段路**：Claude Code 首次在 git 仓库内写该文件时，会把它加入开发者的**全局** git ignore；但这条保护不会随仓库走、不覆盖已被追踪的文件、也不覆盖「后来才变成仓库」的目录。更糟的是，**1,105** 个可溯源仓库里有 **539** 个是 Claude 自己共同署名的提交改动了这个文件——agent 提交了自己泄漏的密钥，涉及模型从 Sonnet 4.5 到 Opus 5.5。
- **传统密钥扫描器对这一类基本失明**：gitleaks 只命中 **564** 份、TruffleHog 命中 **643** 份，**215** 份两个工具都没抓到。原因是 `PGPASSWORD=...`、`sshpass -p ...`、请求头里的密码看起来就是普通单词，不符合「高熵令牌」的识别逻辑。
- **已经有人在用它**：Apiiro 指出 Shai-Hulud npm 蠕虫就是用 TruffleHog 扫受害者机器——同一把扫描器会命中这 1,122 份文件里的 643 份，意味着这些凭据早已进入批量窃取的射程；研究还发现部分文件已暴露超过 **217 天**。
- **对开发者的落点**：自查顺序不能反——先轮换、再清理。在 GitHub 组织内搜 `.claude/settings.local.json` 与 `.claude/settings.json`，用 `git log --all --full-history` 查历史（fork 和 clone 都会保留），然后 `git rm --cached` + 写进仓库自己的 `.gitignore`。日常改两件事：命令里用环境变量引用（`psql "$DB_URL"`）而不是字面密码；授权时给**模式**（`Bash(npm run:*)`）而不是给**具体命令**。
- **需要保留的清醒**：研究者没有逐一验证 1,379 个密钥是否仍然有效，只有一家受影响公司确认自己的 Key 当时还活着；「63 家组织」是扫描到的公开痕迹，不等于 63 起已确认事故。但这一类的修复成本几乎是零，先查再争论值不值。

### 2. 让模型「忘掉」十个客户：一次改 17 个权重矩阵，不重训，精度只掉 2.5 分

MIT CSAIL 的论文《Sparks of Weight-Space Programming》（Takehi、Teoh、Zhang、Khattab）给了一个模型直接读写另一个模型权重的 Python 内核，让「编辑者」模型像改代码一样改参数——不重训，只读权重、做小范围直接编辑。论文里用的是 OpenAI 的 **GPT-6 Astra**，把 Qwen 的 MATH-500 从 **7.9%** 拉到 **48.1%**。11 月 7 日至 8 日，社区把这个方法从「提分」推向两个更实用的方向：**定向遗忘**与**效率重写**。

**Claude Opus 5.5** 在一个 **4.94 亿参数**的模型上改动了 **17 个权重矩阵**，改完之后该模型「忘掉」了 **20 个客户**和 **10 个密钥**——行为上像一个从未见过它们的新模型；其余客户的抽取准确率只掉 **2.5 个点**。作者的对照实验说，三种标准重训办法做不到这两件事同时成立：要么只是把事实藏起来，要么为了删掉事实把模型改坏。另一条线是效率：社区开源的 **Qwen Concept 27B** 直接对 Qwen 3.8 基座做权重空间编辑，思考 token 减少 **54%**、GPQA Diamond 提升 **3%**、每焦耳有效 token 提升 **30%**，发布 BF16/FP8/NVFP4 三版，开发机是一台本地 DGX Spark。

**核心亮点：**

- **跳过的是「训练」这一整层**：模型改进历来经过外部优化器 + 人设计的训练流水线，这条路径改成「模型自己推理问题落在对方哪个 MLP 层，然后就地改」。如果可泛化，这是第一个完全绕开训练的 AI-for-AI 方法。
- **精度可达「位级」而不是「统计级」**：同一思路的另一组演示用 **10 个冻结卷积层**把虹膜检测器布线进去，让左眼虹膜 **42%** 变蓝，而图像其余像素位移不超过 **1.6e-7**；只在冻结布线内训练检测器则达 **78%**。冻结补丁在其前方可训练层感受野之外保持精确——这是「可验证的网络手术」的前提。
- **合规场景立刻有了技术落点**：GDPR 删除权、客户数据退出、密钥撤销，过去只有重训或加一层屏蔽两条路。现在有了第三条：定点切开再缝合。
- **对开发者的落点**：短期最现实的两个用法是「小模型提分」与「推理省 token」，都已有可下载权重；但要复现，你必须能拿到编辑者模型的权重级访问权限，这决定了它先在开源模型上开花，而不是在闭源 API 上。
- **需要保留的清醒**：MATH-500 从 7.9 到 48.1 是一个**极低基线**上的跃升，不等于「接近前沿」；Opus 的 17 个矩阵、2.5 分损失都是单个实践者的单次实验，没有第三方复现；「忘了 20 个客户」也可能是让模型在特定问法下不再输出，而这与「权重里真的没有」是两件事——这一点 39 个预注册实验里约三分之一预测失败，作者自己也如实报告了。

### 3. libghostty 1.0：终端模拟内核冻结 C ABI，JetBrains 1,250 万用户的终端换了地基

Mitchell Hashimoto 于 **11 月 6 日**发布 **libghostty-vt 1.0**，把 Ghostty 的终端模拟内核抽成一个可移植的 C 库，并宣布库本身与 C ABI 同时稳定。标志性证据是采用面：JetBrains 系列 IDE 的终端（此前是 JediTerm）现在跑在 libghostty 上，按 JetBrains 报告的口径覆盖 **1,250 万以上**活跃用户；Neovim 已有一个**通过审核**的 PR 用 libghostty-vt 替换 libvterm，顺带关掉一个挂了十年的老 issue——窗口 resize 后回滚缓冲区重排。11 月 7 日该消息在 Hacker News 冲到 **1,015 分 / 176 条评论**。

**核心亮点：**

- **1.0 卖的是「以后不会炸」而不是功能**：所有对象都是不透明句柄，几百个值走一小组 enum-keyed 的 getter/setter，新增值不需要新符号；用新头文件编译、链到旧库会返回 `GHOSTTY_UNSUPPORTED` 而不是崩溃；非不透明结构体自带 size 或保留填充以便追加字段；ELF 平台每个导出符号都做了版本化。CI 用 libabigail 对着提交基线逐次校验。
- **打包者第一次被当成用户**：独立于应用的发布节奏、签名源码包 + 依赖包（可离线构建）、带 SONAME 的共享库与静态库、headers、pkg-config、CMake config，尊重 `--prefix`/`DESTDIR`/`lib64`，默认保留 debug info 以便发行版拆分。
- **资源占用是可验证的**：库不创建线程，只通过你提供的分配器申请内存。作者称在一台 **4 核 8GB** 的 Linux 服务器上跑过 **10,000 个**带活动 shell 的终端。
- **采用名单比新闻稿更有说服力**：除 JetBrains、Neovim，还有 KDE 在试做的 Konsole 替代品、Vercel 的 Turborepo（渲染 TUI 任务输出）、devenv、Antithesis（拿它 fuzz TUI 程序，在 btop 等软件里挖到了真 bug）、Emacs 的 Ghostel、WASM 版 ghostty-web（Xterm.js 兼容 API）、OrbStack，以及 herdr、cmux 这类**智能体编码工具**。Rust/Go/JS/Swift/Python/.NET/Elixir/Dart/Java 都有社区绑定。
- **对开发者的落点**：如果你在做 TUI、IDE、云终端，或者一个需要给用户看 shell 输出的 agent 工具，不必再自己写转义序列解析器——作者的说法是约 **1,500 行 C** 就能拼出比 2025 年多数终端更全、更快的终端。许可证 MIT，依赖只有 simdutf、Google Highway、一张 Unicode 表和 Wuffs，树里没有 copyleft。
- **需要保留的清醒**：Linux/macOS/iOS/FreeBSD/Windows x86_64/Android/WASM 是 CI 里真正跑过测试的，其余平台（bare-metal riscv32/thumb、WASI、Windows arm64、illumos、32 位 x86）只是**构建通过、没有自动测试**，出问题自负；「1,250 万用户」是 JetBrains 的整体活跃数，不是终端使用数；Ghostty 1.5 应用排期在 **2027 年 3 月**。

### 4. 开放权重进入「许可证时代」：一个真 Apache 2.0，一个把欧盟英国韩国写进排除条款

11 月 4 日至 7 日，三份开放权重放在一起看，比任何榜单都清楚：**Ricursive Intelligence 的 Ripple-65B Preview**（650 亿稠密、**12 万亿**训练 token、1M 上下文）自 11 月 4 日起就以 **Apache 2.0** 可下载，自称 TerminalBench 2.1 得 **80.52**、总研发成本 **3,200 万美元**；**Nous Research 的 Arete-27B** 于 11 月 6 日晚在 Hugging Face 放出，是 Qwen3.8-27B 的微调，权重、评测、训练数据全给，社区 GGUF 与 EXL3 量化在两小时内出现；而**百度 ERNIE 5.5 Flash Base** 仓库里的 LICENSE 文件把「Territory」定义为「全世界，除欧盟、英国、韩国之外」——这份许可证文本自 10 月 21 日就在，但直到这轮盘点才被逐字读出来。

**核心亮点：**

- **「开放权重」和「部署自由」是两个产品**：柏林或伦敦的团队可以合法下载 ERNIE 的权重，却不能在本地推理服务里合法对外提供——对做欧洲数据中心推理、多区域产品的团队，这是一条会直接卡住上线的条款。
- **可以下载的模型，胜过声称更好的模型**：Thinking Machines 的 Inkling 2 Small 在 Artificial Analysis 指数上更高（**31**），但权重仍只在 Tinker 里，承诺的 Apache 2.0 还没落地、仓库都不存在；Ripple-65B 已经在 Hugging Face 上。选「这周到底跑什么」时，答案由许可证而非榜单决定。
- **全开放仍然是差异化卖点**：Arete-27B 一次给齐权重、评测和训练数据，27B 单节点就能微调与复现评测，这种「拿回家就能验证」的姿态在 2026 年下半年反而稀缺。
- **对开发者的落点**：做选型时把三件事写进同一张表——能不能商用、能不能在目标地区提供服务、权重是否真的存在（不是「下周开放」）。前两项看 LICENSE 原文，第三项看仓库有没有 commit。
- **需要保留的清醒**：Ripple 的 80.52 与 3,200 万美元都是公司自报，没有第三方复现；Arete「对齐西方价值观」是实验室自己的描述，独立评测出来前只是一个标签；ERNIE 的排除条款是许可证文本事实，但百度是否会对欧盟客户另发授权，目前没有公开说明。

### 5. Anthropic 的估值被买家砍到 1.1 万亿：路演还没开始，价格先跌了三成

彭博 11 月 7 日消息，在 Anthropic 下周正式启动 IPO 路演之前，潜在买家正在讨论 **1.2 万亿至 1.3 万亿美元**的估值区间，其中有人甚至在考虑低至 **1.1 万亿**。此前的口径是 10 月初的 **2 万亿**，公司 10 月简报财务后回落到 **1.4 万亿至 1.5 万亿**，纳斯达克 100 指数周四大跌 **6.4%**、单日蒸发 **2.3 万亿美元**之后再次下移。同一天，**OpenAI** 新一轮融资首期约 **110 亿美元**到账，对应估值 **1.25 万亿美元**，整轮上限约 **200 亿美元**——原计划是 1.4 万亿估值募至少 300 亿。

**核心亮点：**

- **降价不是因为业绩，是因为分母**：Anthropic 招股书显示前九个月营收同比增长约 **1,200%** 至 **332 亿美元**，手上现金及等价物超过 **1,120 亿美元**；压价来自 AI 板块的公开市场重估，以及民主党拿下国会后对数据中心扩张更严审查的预期。
- **出资结构在悄悄变**：累计投入约 **650 亿美元**的软银本轮只商讨投入数亿美元，Coatue 的讨论金额也在数亿美元级，阿联酋投资者联合体预计成为最大出资方——钱从「战略重仓」变成「分批试水」。
- **评级是下一个关口**：Anthropic 计划到 2045 年在算力基础设施上投入超 **8,000 亿美元**，这依赖投资级信用评级；但黑石预计其 IPO 后只能拿到**垃圾级中较高档位**，而很多保险与养老基金受投资限制无法大量持有这类债务。
- **对开发者的落点**：估值下修会传导到两件你最关心的事——API 定价的补贴空间，以及「前沿模型永远更便宜」的假设。Ramp 的 10 月数据已经显示企业 token 支出增速从 7 月的环比 **42%** 降到 8—9 月的 **1.5%** 时，两家都在用降价换量。
- **需要保留的清醒**：全部数字来自匿名信源，Anthropic 未确认；讨论仍在进行、没有最终决定；汇丰策略师认为约 **1 万亿美元**才是「更舒服」的水平，这属于卖方观点而非定价事实。另一个选项是推迟 IPO——公开递交后等数周甚至数月再路演，历史上 Cerebras 与 Figma 都用了上调发行的打法，但两者现价都远低于发行价。

### 6. Meta 给 Muse 装上「空间」：用自然语言搭一个任务房间，顺手把企业级记忆下放到个人

11 月 7 日，Meta 为智能体 **Muse** 上线 **Spaces** 功能：用自然语言描述就能搭一个专属任务空间，可接入 Notion、日历、邮箱等外部应用，后台自动更新动态信息；同时把原本企业级的 **Muse Wonder** 记忆模型下放到消费级用户，官方称升级后主动记忆准确率提升至 **90%**，可跨应用自动提取用户偏好、任务进度与关键信息，无需手动指令即可续上上下文，并新增多任务后台并行处理。

**核心亮点：**

- **从「会聊天」转向「有房间」**：Spaces 的本质是给智能体一个持久的作用域——哪些应用可读、哪些任务常驻、什么条件下触发。这比再叠一层 prompt 更接近真实工作流。
- **记忆从功能变成产品分层**：把企业级记忆模型下沉到个人版，说明 Meta 判断「长期记忆」已经是留存的主战场，而不是差异化卖点。
- **对开发者的落点**：如果你的 agent 产品还在用「每次会话重建上下文」，Spaces 这个形态提供了一个可抄的界面范式：空间 = 应用白名单 + 任务队列 + 后台刷新；同时它也在挤压第三方「个人知识管理 + agent」的生存空间。
- **需要保留的清醒**：「主动记忆准确率 90%」是自己的口径，没有说明测试集、任务类型与错误分布；跨应用自动提取意味着权限面被放大，而 Meta 目前没有公开细粒度的数据留存与撤销说明——对隐私敏感场景，这一条比准确率更重要。

### 7. 员工用 AI 做 PPT 被辞退，法院判公司赔 4.6 万：AI 办公的第一份判例

央视财经 11 月 7 日报道，北京朝阳法院审结一起劳动争议：吴女士在某保险公司任法务，**2024 年 7 月**为提升 PPT 与数据分析效率，把**自行整理加工后**的公司稽核问题数据表上传到她所称「部门领导和直属领导多次推荐」的第三方 AI 平台，一个月后被公司以「严重违反信息安全等相关规定」解除劳动合同。法院认为她**无泄漏公司秘密的主观故意**，不足以认定严重违反工作纪律；公司虽有保密与信息安全制度，但**未明确禁止使用第三方 AI 工具**，也未就 AI 工具使用开展专项培训与规范指引，且未能证明上传信息属于保密信息、也未能举证实际损失。判决撤销解除通知、继续履行劳动合同，支付工资损失、年终奖差额等共计 **46,000 余元**；公司上诉，二审维持原判，判决已生效。

**核心亮点：**

- **争点不是「能不能用 AI」，而是「制度有没有写」**：法院的推理链条很清楚——有制度、但制度没覆盖这个行为、也没做培训，就不构成「严重违纪」。对企业来说，这是一份成本很低的合规清单。
- **举证责任落在公司一侧**：要证明「属于保密信息」和「造成实际损失」，两件事都得有证据。单靠一份信息安全制度，不足以支撑解除劳动合同这种最重的处分。
- **法官的公开提示很具体**：企业要划清文件秘密等级，明确告诉员工什么绝对不能上传；不能只靠事后追责。
- **对开发者的落点**：做企业侧 AI 工具的团队，这份判决几乎是在要求你提供三样东西——**敏感信息识别与拦截**、**上传审计日志**、**按部门/文件等级的允许清单**。这三项从「加分项」变成「采购门槛」。
- **需要保留的清醒**：这是一审 + 二审维持的个案，不是指导性案例，对其他法院只有参考价值；报道未披露上传文件的具体内容与平台名称，「领导推荐」也是原告陈述经法院采信的部分；把它读成「员工可以随便上传公司文件」是彻底的误读——判决否定的是**解除劳动合同**这一处分的合法性，不是行为的合规性。

### 8. 智能体开始有了「回归测试」：Gauge、Paradev、devvm 三件工具，加上腾讯开源的 LoopForge

11 月 7 日前后，围绕「让 agent 稳定干活」的工具层集中冒头：开源 CLI **Gauge** 用 Docker 起干净会话，把 Skills、SDK、CLI 的本地工作区版本喂给真实 agent，用「爬坡法」（改一点、量一次、再改）测指令改动的效果，支持 Claude Code、Codex、Pi、OpenCode，数据落在私有 `.gauge/` 目录的本地 SQLite；**Paradev v2.0.5** 用隔离的 Git worktree 并行跑多个 CLI agent，自带终端、diff 查看器与应用内浏览器预览，支持远程访问、任务调度与 iPhone/iPad 同步；**devvm.dev** 则是「一个项目一台 VM」，把密钥和危险操作关在虚拟机里，支持多 agent、网络限制、端口转发与自定义层。

**核心亮点：**

- **卡点从「能不能写」变成「改了以后有没有变差」**：Gauge 解决的正是编码 agent 落地的真实痛点——SDK 换代、CLI 参数废弃、文档过期，agent 会在这些摩擦点上悄悄退化，而人肉发现不了。它把「agent 体验」（AX）做成了可回归的指标。
- **并行不是目的，隔离才是**：Paradev 用 worktree 解决的是「两个 agent 抢同一个分支」的低级冲突，这比再做一个调度器更务实。
- **安全边界被产品化**：devvm 的思路与本周 Claude Code 密钥泄漏形成正面对照——如果 agent 的凭据天然只存在于 VM 内，settings 文件被提交出去也不至于直接暴露宿主机的密钥库。
- **国内也在做同一件事**：腾讯轻量云开源 **LoopForge**，定位是云端自进化 AI 研发平台，针对单机代码智能体「上下文断裂、代码失控、重复踩坑」，提供 7×24 小时云端工作区与多角色协作。
- **需要保留的清醒**：Gauge 要求 Node.js 22.13+、npm 与跑 Linux 容器的 Docker，环境门槛不低；Paradev 与 LoopForge 都还没有公开的横向评测，「并行更快」在多数团队里是假设而非测量结果；三件工具都在早期，接口变更会比 libghostty 那样的 1.0 更频繁。

### 10. 9B 模型装进手机：飞行模式下 230 tokens/s 输入，5GB，Apache 2.0

11 月 8 日凌晨，作者以 **Alpie Seed** 之名发布一个 **90 亿参数**多模态模型，完全离线跑在手机与笔记本上。按作者自述：在 **iPhone 17 Pro** 上输入速度 **230 tokens/s**、输出约 **9.6 tokens/s**，飞行模式下正常工作；同一模型在 16GB M2 MacBook Pro 上约 **14 tokens/s**，接工作站级 GPU 可达 **110 tokens/s**。整体体积约 **5GB**，支持文本、文档、图像、视频输入，提供 2/3/4 位量化，首发即支持 GGUF、Ollama、MLX、Kaggle 等格式，许可证 **Apache 2.0**，无需 API Key、无有效期。它同时是 Alpie Local 私有助手的核心引擎。

**核心亮点：**

- **「230 tokens/s 输入」是预填充速度，不是生成速度**：这个数字真正说明的是长上下文在端侧可以被快速读完——对「把一整份文档丢给手机」这类场景，瓶颈从读变成了写。
- **5GB 是一个工程门槛**：它意味着模型能躺在中端机的可用存储里，而不需要用户为它清空相册；2/3/4 位量化齐全，等于把「跑得动」和「跑得好」拆成两个可选档。
- **许可证选择比参数更重要**：Apache 2.0 + 无 API Key + 无有效期，意味着「别人无法随意关掉你的模型」——这正是端侧私有 AI 的核心卖点，也是云端服务给不了的东西。
- **对开发者的落点**：端侧模型的现实用法不是替代云端，而是承接「不能出设备」的那部分请求——隐私文档、离线场景、实时响应。如果你的产品有一条「数据不出本地」的需求，5GB/9B 已经进入可用区间。
- **需要保留的清醒**：「编码与推理基准达到最先进水平」是作者自述，没有任何第三方评测编号；iPhone 17 Pro 的 230 tokens/s 与 M2 上的 14 tokens/s 相差一个数量级，说明这组数字高度依赖具体硬件与量化档位；这是一个个人/小团队发布，不是大厂产品，长期维护与安全更新都还没有承诺。把它当作「端侧可行性的一个样本」，而不是「可以上生产的选型」。

## 💡 一句话观点
