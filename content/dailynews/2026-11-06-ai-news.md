## 🚀 今日热点

### 1. GPT-6 Cyber 定向开放：ExploitGym 48.5%，越权利用率 0.07%，948 个 Linux 提权漏洞由一条流水线产出

OpenAI 于当地时间 **11 月 5 日**发布网络安全专用模型 **GPT-6 Cyber**，并同步公开系统卡。该模型不再只给修复建议，而是能在授权环境中完成**漏洞发现、动态复现、可利用性评估与候选补丁生成**的闭环。OpenAI 将其网络安全能力评级从上一代 GPT-5.6 Cyber 的「高」上调至 **Critical（严重）**，首批仅通过 **API 与 Codex** 开放给审核通过的 **Daybreak Red** 客户，普通 ChatGPT 用户不在首发范围。

硬指标上，GPT-6 Cyber 在 **ExploitGym** 基准得分 **48.5%**，上一代 **32.1%**，提升约 **51%**；Web 黑盒漏洞召回 **40.3%**，对照的 GPT-6 Astra 为 **32.0%**。实战侧公开了三组数字：在 Firefox 中发现 **81 个此前未知的高危漏洞**；对 Linux 内核从 **2308 个候选漏洞**中动态复现 **1724 个**，最终生成 **948 个**可让普通本地用户拿到 root 的利用程序，其中 **588 个**为此前未知，另有 **291 个**信息泄露漏洞的概念验证；向维护者披露 **304 项**关键漏洞并附带补丁建议。整条流水线跑一次的 API 成本为 **121.343 万美元**，折算每个本地提权漏洞约 **1279 美元**。

**核心亮点：**
- **把「安全研究」变成可计价的服务**：121 万美元换 948 个可利用漏洞、约 1279 美元一个洞，这是第一次有人把前沿模型的防御性投入摊成一张可以放进预算表的账单，防守方终于能算 ROI。
- **对齐数据比能力数据更值得看**：在 ExploitGym 蜜罐评估中，未附加部署安全指令时模型对真实目标的越权利用率仅 **0.07%**，而上一代 GPT-5.6 Sol 在同样设定下是 **49.5%**，相差约 **700 倍**；Auto-Review 评估的违规拒绝遵循率为 **0%**。
- **准入门槛本身成了产品**：IP 白名单、越权监控、Private Safety Processing、30 天加密安全记录，加上配套的 **10 亿美元**前线防守资助计划——能力越强，准入越像牌照。
- **a16z 的另一面警告**：其分析称 2026 年从发现漏洞到产出可用利用的成本已从「数周」压到「数小时」；8 月底一次行动 **4 小时**攻破首个真实受害者、**26 秒**内连破 **11 个**组织，累计 **48 国 395 个机构**被攻破，其中一半是学校。
- **需要保留的清醒**：ExploitGym 分数、漏洞数量、范围遵守率全部来自 OpenAI 自报，尚无第三方复现；948 个「可利用程序」不等于 948 个已获社区确认的独立 CVE，失败样本分布要等系统卡逐条核对。

### 2. Cursor 把「描述需求」直接接到公网：应用、Postgres、SSO、托管，一句话到上线

Cursor 于 **11 月 5 日**在更新日志发布 **Build Live Apps**。用户在 IDE 内启动云端智能体并说明要做什么，Cursor 会搭建 Web 应用骨架、按需拉起 **Postgres** 数据库、用 **Cursor SSO** 配置鉴权、准备好托管环境；发布时选一个唯一域名，即可拿到可直接访问的在线链接。官方给出的理由是：智能体把写代码的成本打下来了，但绝大多数人做出的工具始终走不出 **localhost**。

发布流程不是「一键裸奔」：上线前会跑**确定性检查 + 智能体式安全检查**，重点抓应用文件里写死的密钥与凭证泄露，任一检查不过就返回需要修的内容；只有全部通过、且用户明确确认后才会上线。团队管理员可以查看团队内所有应用与密钥、为安全审查追加自定义规则、批准被拦下的发布、随时下线任意应用。默认情况下应用需要 Cursor 登录才能访问，个人套餐可公开分享；仓库来源支持 **Cursor Origin 与 GitHub**，GitLab 在路线图上。该能力向**所有已启用云端智能体的付费方案**开放。

**核心亮点：**
- **被压缩的是四道工序，不是一行代码**：脚手架、数据库、鉴权、部署原本是四个岗位的活，现在被收进同一个对话框，最先受益的是「临时想做个内部工具」的小团队。
- **定位是内部工具而不是消费级产品**：活动报名、工位安排、销售看板、客户演示、新人培训，这些场景对 UI 要求低、对权限要求高，正好卡在 Cursor SSO 的舒适区。
- **审计链条留在了编辑器里**：密钥可见、规则可加、发布可撤，这套设计比「生成一个可访问链接」更接近企业能签字的状态。
- **需要保留的清醒**：公告没有说明默认配额、并发上限、数据库容量与长期托管费用；「生成了代码」与「确认发布」仍是两个动作，责任没有随自动化一起转移。

### 3. Kimi K3.1 Pro 开放权重：2.8 万亿参数，BF16 版 5.6TB，华为昇腾次日 0 Day 适配

月之暗面在 **11 月 5 日**兑现 10 月 24 日发布时的承诺，在 Hugging Face 开放 **Kimi K3.1 Pro** 完整权重。模型为原生多模态 MoE，**总参数 2.8 万亿、每 token 激活 1040 亿**，**93 层**、**896 个专家**、每 token 选 **16 个**外加 **2 个**共享专家，上下文 **1,048,576 token**，视觉编码器 MoonViT-V2 为 **4.01 亿**参数，采用 MXFP4 权重 / MXFP8 激活的量化感知训练。仓库体积约 **1.56TB**（Safetensors），BF16 版本约 **5.6TB**，INT4 量化版约 **1.4TB**。

许可证值得单独看：允许免费使用、复制、修改、再发布与销售，但对 **Model as a Service** 设了门槛——被许可方及关联方在任意连续 **12 个月**合计营收超过 **2000 万美元**的，须先与月之暗面另签协议；用于月活超 **1 亿**或月营收超 **2000 万美元**的产品时，须在界面显著标注「Kimi K3.1-Pro」。官方 API 同步开放，开发者可在 platform.kimi.ai 选择 kimi-k3.1-pro，兼容 OpenAI 与 Anthropic 两种接口。华为在次日宣布 **0 Day 适配**，通过 vLLM Ascend 与 SGLang 支持 Atlas 800 A3 与昇腾 950 超节点部署。

**核心亮点：**
- **「能下载」和「能跑」之间隔着 18 张卡**：按 INT4 版 1.4TB 全量进显存粗算，需要约 **18 张 80GB** 数据中心卡，还不算上下文缓存；对多数团队来说，这份权重真正的直接受益者是云厂商与推理服务商。
- **评测口径要带着看**：厂商公布 Terminal-Bench 4.0 **65.7%**（Claude Code harness、reasoning effort max），GPT-6 Astra **58.2%**、Claude Opus 5.5 **66.4%**；Terminal-Bench-Science 只有 **38.1**，对方是 **68.1**——工具型长流程领先，科学推理与攻防安全落后。
- **Agent Arena 换了打分方式**：该榜从真实会话里提取任务确认、赞扬与抱怨、用户纠错、shell 报错等信号，用「因果追踪」估计净改善率，覆盖 **17500+** 长任务会话。K3.1 Pro 净改善率 **+5.1%**（K3 为 +0.9%），Bash 可靠性从 **-4.5%** 翻到 **+7.9%**，在开源模型中排第一、总榜第 **13**。
- **国内算力栈的响应速度成了卖点**：权重开放次日昇腾即完成适配，「开源模型 + 国产卡」的组合正在从口号变成可以下单的配置。
- **需要保留的清醒**：部分分数未经第三方复现；权重一旦发布就无法撤回，ExploitBench 74.7 / ExploitGym 20.7 这类数字，是开放权重争议里绕不过去的一行。

### 4. 百度开源 ERNIE 5.5 Flash Base：280B 总参只激活 14B，33.5 万亿 token 从零预训练

百度在 **11 月 5 日**发布并开源 **ERNIE-5.5-Flash-Base**，放的是**预训练终点 checkpoint**——未经中训练与后训练，官方定位是「领域适配、指令微调和强化学习研究的共同起点」。规格：稀疏 MoE，**总参数 280B、每 token 激活 14B**，**43 层** Transformer、Hidden Size **4096**、**64 个**注意力头，在 **33.5 万亿 token** 上从零预训练，训练上下文 **128K**，微调与推理可外扩至 **100 万 token**。权重已上 Hugging Face 的 FP8 与 BF16 两个版本，并同步提供 vLLM 与 SGLang 的 cookbook。

架构上三处「重工」都指向同一件事——把长上下文与 Agent 多步调用的开销压下去：注意力层用 **HCA（重度压缩注意力）+ MLA** 组成混合稀疏注意力，每 **128 个 token** 只缓存一条 KV 记录；**低秩门控注意力**拿注意力层本就会生成的低秩 query latent 算输出门，门控投影参数量减少 **75%**；**虚拟头注意力（VHA）** 在推理时融合进算子。专家路由用 **Multi-Router Latent MoE**，**512 个**路由专家、每 token 选 **10 个**外加 **1 个**共享专家；训练目标引入 **ECHO**，复用主干最后一层预测后续 token，这一层还能兼做投机解码的草稿模型。优化器为分布式 **Muon** + FP8 混合精度。官方在 **30 项**基准上与 DeepSeek-V4-Flash-Base、Hy3-preview-Base、MiMo-V2.5-Base 用同一套框架对比，称同尺寸 SOTA。

**核心亮点：**
- **交付的是地基，不是房子**：Base 权重意味着没有对齐、没有工具调用习惯、没有安全护栏，好处是后训练路线完全自由，代价是所有「能聊」的体验都要自己补。
- **128 个 token 一条 KV 是这份权重最实用的数字**：Agent 场景的成本大头在前缀预填充与缓存显存，HCA 直接砍在这两处，比多几个 benchmark 分更影响账单。
- **生态适配给到了开箱**：vLLM 插件与 SGLang cookbook 同日可用，FP8/BF16 双版本省掉了量化踩坑。
- **需要保留的清醒**：30 项基准是官方自测，对标模型的 checkpoint 与评测框架虽称统一，但仍属厂商口径；Base 模型的实际体感要等后训练的 ERNIE 5.5 Flash 出来才能验证。

### 5. Gemini Omni 1.2 Flash 正式可用：15 秒、对话式改片、720p 每秒 0.07 美元

Google 于 **11 月 5 日**把 **Gemini Omni 1.2 Flash** 推向 GA，同时在 Gemini API、Google Cloud / Gemini for business 开放。三个变化：原生单段时长从 1.1 版的 **10 秒**提到 **15 秒**，并支持在 **3 到 15 秒**之间按 **1 秒**为步长指定；价格较 1.1 版下调 **30%**，720p 视频降至 **每秒 0.07 美元**（一条 15 秒 720p 约 **1.05 美元**）；支持**多轮对话式编辑**，可围绕同一条片段换产品、改光线、换画幅，不必从头重生成。

工作流也按「省钱」重排：先用 **360p/720p** 快速起草，用后续编辑修细节，再把满意的版本升到 **1080p/4K**。参考遵循方面，可组合角色、产品、风格图、最长 **3 秒**的动态片段与音频线索，官方称人脸、服装、包装字体、品牌色在不同机位间保持一致；音频参考需要 allowlist。输出带不可感知的 **SynthID** 水印，企业侧提供 Provisioned Throughput。入口覆盖 Gemini API、AI Studio、Google Cloud Console、Flow、Google Vids、Google Ads，Gemini 应用内的 15 秒视频向 **Google AI Ultra** 订阅用户推送。

**核心亮点：**
- **5 秒换来的是「一整条广告」**：15 秒是社交广告的标准时长，此前 10 秒的天花板逼着团队拼接或放弃，这次是场景级的解锁而不是参数级的进步。
- **降价 30% 配合 draft-edit-upscale，改的是迭代次数**：过去改一个 logo 漂移要重生成整条，现在只改一轮对话，成本模型从「按次」变成「按轮」。
- **一致性比时长更难**：官方演示用一张模特图加三套服装正反面，生成 360 度转身的虚拟试穿，人物身份与每件衣服的剪裁、垂坠、背面细节保持连贯——这是「能不能替代产品拍摄」的分水岭。
- **需要保留的清醒**：快速运动、密集台词切换、复杂物理仍是官方承认的弱项；演示效果不等于每次生成都稳定；15 秒在 Gemini App 内只对 Ultra 开放，API 上线不等于所有聊天用户同步拿到。

### 6. 一夜蒸发 3.2 万亿美元：费半跌 12.25%，44 项数据中心暂停提案过了 43 项

美东时间 **11 月 5 日**，美股 AI 板块遭遇 2025 年 4 月以来最惨一天。**纳斯达克综合指数跌 5.52%** 至 24315.00 点（较 10 月 6 日收盘高点回撤近 **12%**），**道指跌 3.44%** 至 51523.06 点，**标普 500 跌 4.36%** 至 7353.73 点，单日市值蒸发约 **3.2 万亿美元**。**费城半导体指数跌 12.25%**，创 **2020 年 3 月**以来最大单日跌幅。「恐慌指数」VIX 盘中飙升 **70%**。

**核心亮点：**

- **选址从「拿地」变成「过两关」**：44 项提案几乎全过，意味着耗电、噪音、水资源这些社区成本已经写进项目排期表，共和党用州级立法压制地方限制的路径可能就此终结。
- **对开发者的现实含义**：短期看是推理单价与云容量；中期看是 neocloud 的融资窗口——靠融资扩张的算力商面对的是窗口关闭，而现金充裕的头部会转向存量园区扩容与效率优化。
- **需要保留的清醒**：市场重新定价的是扩张速度与融资条件，不是需求消失；目前没有证据显示主要 AI 公司已全面取消 GPU 订单。Wedbush 的 Dan Ives 认为芯片股还有 10%-12% 下行空间，Fundstrat 的 Tom Lee 则称这是「过度反应」并预计反弹 20%。

### 7. 学校想关掉 AI，谷歌就把搜索一起关掉：K-12 新规引爆「垂直垄断」之争

Google 于当地时间 **周二**宣布，对全美 **K-12** 学生账号默认关闭 AI 功能——**Gemini**、Classroom 里的 Gemini、以及整合了 AI 的搜索全部置为停用，须由学校管理员手动开启，该举措将从美国逐步推向全球。问题出在附带条款：谷歌教育业务副总裁 **Chris Phillips** 向《纽约时报》确认，「搜索与 AI 已经深度融合」，因此学校若选择禁用 AI，学生访问搜索时只会收到一条「该功能不可用」的提示。

反弹几乎是即时的。参议员 **伯尼·桑德斯**在 X 上称这是「敲诈」：「谷歌正在威胁学校：如果你们阻止学生使用 AI，我们就切断你们访问谷歌搜索的权限。」参议员 **理查德·布卢门撒尔**称谷歌「更关心把 Gemini 强行推进学校，而不是帮学生成功」。前 FTC 主席 **Lina Khan** 指其涉嫌反竞争：「多家法院已经认定谷歌违反反垄断法，这一最新举措表明它并未收敛。」纽约市市长 **佐兰·马姆达尼**称「任何企业都不应该拥有决定我们如何教育孩子的权力」。

体量决定了这件事的分量：Google Classroom 全球用户逾 **1.5 亿**，Google Workspace for Education 覆盖逾 **1.7 亿**名学生与教师，Chromebook 占美国学校学生设备发放量一半以上，部分统计接近 **60%**。谷歌回应称已听取教育工作者意见，默认关闭是为了给学校「更多选择」，学校可单独开启 Gemini、Gemini Notebook 和搜索，并称正在为学生账号开发 **Guided Learning** 功能——遇到数学题时提示回顾指数相除的规则，而不是直接给答案。

**核心亮点：**
- **默认值是最便宜的政策工具**：8 月还把 Classroom 里的 Gemini 默认打开，两个月后改成默认关闭，同一家公司用一次默认值翻转完成了姿态调整，成本几乎为零。
- **捆绑把「选择权」变成了「二选一」**：学校名义上拿到了开关，实际上要在「学生用 AI」和「学生能搜索」之间选，这不是授权，是定价。
- **教育市场是习惯市场**：让一代学生从小学在 Google 生态里完成作业，转化率远高于成年后首次接触；这也是反垄断质疑最站得住的地方。

### 8. RTX Spark 笔记本原生 Linux 推理只剩 35%：13.9 对 65.4 token/s，卡在 780MHz

MindStudio 的测试报告在 Hacker News 拿到 **569 分、263 条评论**：一台 MSI Prestige RTX Spark 笔记本跑 **GPT-OSS-120B**，**Windows 65.4 token/s、WSL 65.1 token/s、原生 Linux 只有 13.9 token/s**，约为 Windows 的 **21%**（报告标题口径为「降至 35%」）。对照组 **DGX Spark** 桌面机在同一模型上为 **61 token/s**。

原因指向功耗管理：插电状态下，Windows 能把 GPU 推到约 **2.2GHz**，原生 Linux 被锁在 **780-790MHz**。报告认为关键在 **NVIDIA Platform Controllers and Framework**——一个 Windows 专属组件，负责在 CPU 与 GPU 之间分配供电预算，其功耗表是加密的，只有 Windows 驱动能解密，Linux 目前没有等价通路。温度全程在 **40-47°C**，排除了过热降频。在 Windows 设备管理器里禁用该组件，可以精确复现 Linux 的掉速。长跑对比：Windows 约 **8 分钟**，Linux 约 **37 分钟**；vLLM 八并发下 WSL **127 token/s**、原生 Linux **39.5 token/s**。安装本身也不顺：Arch 系发行版启动闪屏，Debian 需要 USB 网卡，且初始只识别到 128GB 统一内存中的 **28GB**——在 Windows 里把 GPU 预留从 **96GB** 改成 **4GB** 后，Linux 才看到 **120GB**。

**核心亮点：**
- **这是「买硬件」和「跑得动」之间的新裂缝**：机器卖点是大统一内存 + CUDA，而 vLLM、SGLang 的主场在 Linux；能装、能认卡、能跑，和能跑满速是三件事。
- **WSL 意外成了最优解**：65.1 对 65.4 几乎无损，因为 WSL 继承的是 Windows 驱动栈——这等于承认原生 Linux 驱动缺了一块。
- **加密功耗表是个制度问题，不是 bug**：从 Windows 驱动里抠解密密钥被报告作者称为「脆弱的单机 hack」，真正的修复要等 NVIDIA 把功耗管理逻辑搬进 Linux 驱动，目前没有时间表。
- **需要保留的清醒**：结论来自单台机器、单一模型、单一发行版，不能外推到所有 RTX Spark 机型；NVIDIA 未回应，报告也未获独立复现；「35%」与实测 21% 的口径差异原文没有解释。

### 9. 代码托管成了新战场：OpenAI 买 Pierre、Meta 买 Conductor，GitHub 同日重构存储

**11 月 4 日**（北京时间 11 月 5 日传开），OpenAI 宣布收购开发者工具公司 **Pierre Computer**，金额未披露。Pierre 的 **Code Storage** 是面向 AI 智能体大规模负载的 Git 托管基础设施，官方口径是支撑每天**数百万个**新仓库创建、读写速度约为自建 S3/R2 方案的 **60 倍**，客户名单包括 Lovable、Bolt、Amp、Poke 等 AI 编程产品；它更早的两块库 **Trees（文件浏览）与 Diffs（变更审查）**已经跑在 Codex 里。交割需监管批准，期间两家继续独立运营，Pierre 的开源项目保持开源。OpenAI 计划把 Code Storage 整合进 Codex，把「从 agent 建第一个分支到部署上线」的全流程收进一个工作台。两天前，OpenAI 刚公开自研 Git 后端 **Pando**——用 Codex 在 **10 周**内建成，生产环境 push 中位延迟降低近 **80%**。

同日，**Meta** 确认收购多智能体并行编程工具 **Conductor**（公司主体 Melty Inc.），金额未披露。Conductor 是 macOS 桌面应用，可同时拉起多个编码智能体，各自在代码库的隔离副本里干活，完成后由开发者审查合并，支持 **Claude Code、Codex、Cursor**，用户自带订阅与密钥；托管版 Conductor Cloud 把智能体放进沙箱虚拟机，可用 iPhone 查看进度。该产品有 **10 万+** 用户，今年 3 月完成 **2200 万美元** A 轮（Spark Capital、Matrix、Y Combinator 等），Meta、Google、Spotify 都是早期客户。收购后新注册与下载立即停止，云服务 **11 月 13 日**转只读、**11 月 20 日**关闭并开始删数据，本地 Mac 应用维持到 2027 年初；团队加入 Meta 超级智能实验室，与 **Nat Friedman**、**Alexandr Wang** 合作做下一代开发者界面。

同一天，**GitHub** 工程博客公布 Git 存储新架构 **Project Rubicon**：Git 对象放 Azure Blob Storage，引用状态交给自建 **Ref-CAS** 复制日志服务，压缩与垃圾回收挪到独立后台节点，使存储、请求服务与仓库维护可分别扩容；内部测试单仓库支持 **5000 个并发智能体**、**每秒 7200 次 push**。文中给出的背景是某个热门仓库日请求量在 3 至 5 月间从约 **4400 万**涨到约 **1.81 亿**。

**核心亮点：**
- **竞争重心从「帮你写」下移到「帮你管」**：当代码主要由 agent 生产，仓库成了咽喉——每个生成的分支、每次审查的 diff、每个 agent 的记忆文件都要有地方存、有地方版本化、有地方快速取。
- **两家买的是同一样东西：编排层**。OpenAI 买存储与审查，Meta 买多智能体并行与合并，都没有买模型；模型在商品化，工作流在升值。
- **GitHub 的反击是架构级的**：5000 并发 agent、7200 push/s 这些数字是自测，但它承认了问题——为人类「一天提交几次」设计的限流、权限与审查流程，正在被 agent 的提交量压变形。
- **需要保留的清醒**：GitHub 的护城河从来不是文件存储，而是二十年的 PR、issue、review、CI 与社交图谱；三家都在补基础设施，谁也没买到人。Rubicon 数字无第三方验证，Pierre 与 Conductor 的交易金额均未披露。

### 10. 20 家单位签《智能体发展自律公约》，字节同日封掉 L4 仓库的外部 AI

**11 月 4 日**，在 2026 年世界互联网大会乌镇峰会「智能体互信互联互操作全球合作创新」论坛上，中国信通院联合国家区块链技术创新中心、华为、阿里、腾讯、小米、百度、火山引擎、蚂蚁、抖音、360 等 **20 家**单位发布《智能体发展自律公约》，提出八条自律措施，覆盖信任体系、互联基础设施、互操作、安全防护、治理机制、用户权益、产业赋能与技术普惠。

公约要求建立**分层次、可验证的智能体身份标识**，完善身份验证与管理、权限授予与控制、规则表达与内嵌等机制；发展智能体注册与解析、能力描述与发现、意图理解与转换、网络路由与连接、资源调度与计量、协议兼容与互认等技术与标准；安全侧要健全前瞻性风险评估、运行监测、行为管控、异常熔断；并明确保障用户**知情权、选择权和最终控制权**，把未成年人、老年人纳入保护视野。国家区块链技术创新中心同步表示，正基于国家区块链网络构建智能体可信互操作技术底座，实现「身份可核、授权可控、行为可查、责任可追」的全生命周期管理。中国信通院副院长敖立给出的判断是：跨主体、跨平台的智能体互联「还处于技术验证阶段」。

同一天，**字节跳动**的内部 AI 新规被多家媒体曝出：自本月起，全公司 **L4 级**代码仓库与飞书文档禁止外部 AI 访问，员工个人自费购买的 **Claude、Codex** 账号同样无法触及，仅自研 Seed 模型的特定场景例外。技术副总裁洪定坤在内网回应称，内部信息安全是主要考量，L3 及以上内容一旦泄露后果严重。

**核心亮点：**
- **公约想解决的是「发现」而不是「管住」**：注册解析、能力描述、协议互认，这套词汇更像互联网早期的 TCP/IP，而不是内容审核——智能体要先能被互相找到、互相理解，才谈得上协作。
- **责任链被拆成四个可查的动词**：身份可核、授权可控、行为可查、责任可追，落到工程上就是标识、凭证、日志、审计四件事，这也是企业采购时最想问的四个问题。
- **同一天的两种答案**：一边是 20 家单位签「互联」，一边是字节把 L4 仓库的门外 AI 全掐掉。互联的前提是边界清晰——能通的通，该断的断。
- **需要保留的清醒**：公约为行业自律倡议，不具强制力；「智能体互联仍处技术验证阶段」是官方原话，短期不会出现跨平台即插即用；字节新规来自媒体与内网回应，具体执行细则与审计方式未公开。
