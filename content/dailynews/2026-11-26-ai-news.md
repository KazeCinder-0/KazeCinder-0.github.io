## 🚀 今日热点

### 1. Cloudflare 给网站加一个开关：Agent 不用再逐页爬，直接调用你的站内搜索

**11 月 25 日**，Cloudflare 官方发布 **Search for Agents**：站点所有者只需在控制台 **Quick Actions** 打开一个开关（或调用 API），Cloudflare 就会自动创建 **AI Search** 实例、抓取并索引该 zone 的内容，并把搜索端点挂在站点自己的域名下。端点形如 `/.well-known/search`，返回的是**检索到的 Markdown 片段**，而不是另一个模型生成的答案——Agent 自己已有模型和对话上下文，它需要的只是材料。所有客户可用，**包括 Free 计划**（受套餐额度与限制约束）。

**核心亮点：**

- **让 Agent 发现端点靠的是 4 个 meta 标签**：页面 `<head>` 自动写入 `agent:instructions`、`agent:endpoint`、`agent:method`（GET）与 `agent:documentation`；同时开启 Markdown for Agents 时，`Accept: text/markdown` 请求会在 YAML front matter 里拿到同样信息。官方演示中，一个 **OpenCode** 会话从首页发现端点后，直接带着问题查询 `/.well-known/search` 并给出正确答案。
- **支持 IETF 新方法一并落地**：HTTP **QUERY** 是 **2026 年 6 月**发布的 **RFC 10008** 提案标准，允许把检索条件放进请求体且安全、幂等、不修改服务端状态；该端点原生支持纯文本与 JSON 两种 QUERY 请求体，`curl` 与 undici 等客户端已开始跟进。
- **治理权仍在站长手里**：是否放行仍受站点 bot management、**AI Crawl Control** 与 WAF 配置约束；实例创建后可自行开启 reranking、改缓存策略，也可另外开放公开 REST 端点、MCP 端点、Workers 绑定或在网页里嵌入面向人类的搜索框。
- **计费口径要分开看**：官方原文是"沿用 AI Search 定价，包含摄取、索引存储与查询服务，受 Workers Free / Paid 套餐内用量与限制约束"；部分聚合简报写成"**12 月 1 日起收费**"，两处口径并列，实际账单以官方定价页为准。
- **需要保留的清醒**：官方没有公布索引新鲜度、召回率与排序质量的量化指标，"打开开关就有好搜索"仍依赖站点内容结构与配置；返回的 Markdown 是检索结果而非裁决，Agent 仍可能误读或二次加工。这是把"被找到"变成基础设施，不是把"答得对"外包给 Cloudflare。

### 2. JetBrains 开源 Mellum2.1 Instruct：不输出思维链，SWE-bench 翻倍、每任务少一半 token

**11 月 25 日**，JetBrains 发布并开源 **Mellum2.1 Instruct**：**120 亿总参数、每 token 激活 25 亿**的 MoE 模型，**Apache 2.0** 许可，权重、GGUF 量化版与多 token 预测（MTP）投机解码检查点同步上架 Hugging Face。它是 10 月发布的 Mellum2.1 Thinking 的"直答"版本，明确不为 Agent 输出思维链，面向子智能体、工具调用循环与低延迟 IDE 对话。

**核心亮点：**

- **分数确实翻倍，但对手是自己的上一代**：官方自测 **SWE-bench Verified 40.4**，上一代 Mellum2 Instruct 为 **20.2**，正好翻倍；Thinking 版本为 **47.0**。同组对比里 **Qwen3.5 9B 为 49.8**，仍高于它——"翻倍"不等于"同级最强"。
- **省的是 token，不是参数**：Agentic 编程任务平均每次生成约 **5,600 token**，Thinking 版约 **10,100**，减少约 **45%**；不带工具调用时差距拉大到 **2,400 对 8,800（约 73%）**。单请求生成速度约 **1.4 倍**，负载下约 **1.8 倍**。
- **架构与训练细节可复核**：28 层、**64 个专家每 token 激活 8 个**、GQA **32 个查询头 / 4 个 KV 头**、词表 **98,304**、上下文 **131,072 token**；后训练沿用 NeMo RL 两阶段流程，单次运行从 **10,000 个并发沙箱**收集约 **50 万条**智能体轨迹，Hidden Test 通过才给奖励。
- **其他分数一并记录**：MultiPL-E **73.7**、ToolHop **51.4**、WorkBench **38.0**、IFEval **87.2**、AIME 25/26 **61.1**；全部为 JetBrains 用同一套开源 harness 自测。
- **今天就能用**：Hugging Face 有 BF16 safetensors、GGUF 与 MTP 检查点，模型卡附 vLLM 部署示例；官方定位是"跑在自己基础设施上的快速工人"，可放在强推理模型旁边做子智能体。
- **需要保留的清醒**：**所有基准均为厂商自报，尚无第三方复现**；官方自己建议难题与数学仍用 Thinking 版；目前没有 Hugging Face Inference Providers 托管成 API，想用就得自己部署。

### 3. 英伟达同一天给 Agent 两件底座：会话整容器 fork 提速 84 倍，NVFP4 注意力合进 FlashInfer

**11 月 25 日**，两条来自英伟达系的技术材料同日发布。其一是论文 **arXiv 2611.32255** 提出的 **TimeTravelContainer（TTC）**：无需 root、无需内核改动与硬件虚拟化，就能对正在运行的会话做整容器实时 fork——进程、内存、文件系统与网络全部按写时复制共享，代码已开源。其二是英伟达开发者博客公开的 **RTX Blackwell NVFP4 注意力优化**，核心改动已合入 **FlashInfer 主分支（PR #4502）**。

**核心亮点：**

- **TTC 把"分支/回退"变成廉价原语**：在 **MAGE（Innovus）**与 **EvoDRC（KLayout）**两条电子设计自动化流程中，作者报告环境克隆提速 **84.1 倍**、内存减少 **31%–72%**、端到端提速 **1.7–9.4 倍**；支持 Linux、macOS（Apple Silicon）与 Windows WSL 2。编码 Agent 做并行试错时，不必再把有状态工具序列化到磁盘重启。
- **NVFP4 的具体手法是"寄存器回收"**：把 **N128** score tile 拆成两个 **N64** 寄存器槽，某个半块完成指数化与 NVFP4 量化后立刻复用它的寄存器算下一个 tile 的 QK，形成 **N64/N64 交叉 ping-pong**，在不追加大 buffer 的前提下减少 Tensor Core 空转。
- **加速数字要分两层记**：在 **RTX PRO 6000 Blackwell Server Edition 96GB（SM120）**上，核心 kernel 最高 **1.64 倍**（synthetic 8192 causal 从 **0.76466 ms 降到 0.46659 ms**）；端到端延迟最高下降 **15.34%**（OmniDreams moving、2045 帧、256 chunks 从 **155.92 s 降到 132.00 s**）。
- **边界写得很诚实**：kernel 计时不含 Q/K/V 量化与输出 stride 恢复；端到端数据排除了模型加载、预热、网络与排队；不同模型收益差异很大，Helios 某些场景只降 **1.11%**。
- **需要保留的清醒**：TTC 数字为论文作者自报、尚待独立验证，收益与任务状态大小强相关；NVFP4 优化只在特定硬件与精度路径上成立。两者都是"运行时工程"，不是模型能力提升。

### 4. OpenAI 把聊天与编码并成一条 token 额度线，同时试点"连自己都看不到数据"的私有推理

**11 月 25 日**，TechCrunch 等多方确认：OpenAI 将从 **2026 年 12 月**起，把 **Plus / Pro / Business** 方案中 ChatGPT（含合并后的 Chat 与 Work 界面）与编程工具 **Codex** 的用量合并为**一个按 token 计算的共用额度**；**Instant 对话不计入额度**，耗尽后仍可使用。**11 月 24 日**起已向一小部分 Pro 订阅者灰度，OpenAI 承认极少数重度用户会更早触顶，**具体上限尚未公布**。同日另有报道称 OpenAI 开始与企业试点 **Private Inference**。

**核心亮点：**

- **计费单位从"席位/次数"转向"token 预算"**：聊天与长编码任务会互相挤占同一条额度线，企业使用 AI Coding 需要重新核算单位任务成本与配额治理；Anthropic 在 9 月把 Claude 与 Cowork 合入同一入口，收敛方向一致。
- **"无限"只覆盖 Instant**：官方口径是 Instant 对话不进共用额度、耗尽后仍可用；其余场景不再彼此隔离，重度编码用户受冲击最直接。
- **Private Inference 瞄准合规最后一公里**：企业可在 OpenAI 最强模型上执行查询，而 OpenAI 自身无法访问数据，首批企业客户已进入试点；目前**没有公开价格、SLA 与适用模型清单**。
- **不是新模型的日子**：同一周的 **11 月 24 日** OpenAI 已在 Responses API 加入四个医疗专用配置，该条上期快讯已记，本期不重复。OpenAI 内部还在推进 Chat 与 Work 的界面融合，Thibault Sottiaux 称答案质量会有明显提升，属于产品方向表态。
- **需要保留的清醒**：额度上限与加购规则未公开，"更早触顶"没有量化；Private Inference 的"看不到"具体依赖什么隔离技术、能否通过审计，均未有可核查材料。开发团队在 12 月前应先把编码会话与日常对话的用量拆账。

### 5. Anthropic 把 Messages API 迁到 Rust：一周写出第一版，验证花了几个月

**11 月 25 日**，Anthropic 发布工程复盘：Messages API 流量从 **2024 年初到 2026 年秋增长约 1,800 倍**，团队把核心请求路径从 **Python 迁至 Rust**。Claude 约**一周**写出第一版；到 **2026 年 5 月**，公司合并代码中的 **80% 以上**由 Claude 编写。真正的难点不是写，而是验证：团队把仍在线上运行的 Python API 当作校验器，用真实影子流量比对——模型只调用一次、把输出回放给 Rust，不读取客户请求原文。

**核心亮点：**

- **用 checkpoint 与 fingerprint 定位差异**：回放发现不一致时，系统自动派 Agent 修复；**4 月**时 Rust 版通过约 **98%** 测试，但与生产输入的匹配率只有约 **四分之一**，到 **8 月升至 99.6%**。这组数字比"一次写完"更能说明重构的真实成本。
- **结果是可量化的**：每请求 **CPU 降低约 70%**、首 token 中位时间**缩短约 20%**，全程**未停服、未冻结功能开发**。
- **方法论比结果更值得抄**：先建立可信的校验信号（线上旧系统 + 影子流量 + 回放），再让 Agent 在快/慢/记忆三层循环里自行试错，人类只定义"什么算正确"。对自建编码 Agent 的团队，投入重点应从提示词转向校验器与回放机制。
- **与今天另一条落地研究互为注脚**：Anthropic 同日发布的《Working with AI》指出人审不过来是头号瓶颈；这里给出的答案恰好是"把校验做成系统"，而不是加人肉复核。
- **需要保留的清醒**：全部数字来自 Anthropic 自述，尚无第三方复现；校验器只覆盖其自身服务环境与流量分布，换个系统不能直接照搬通过率。

### 6. 微软把 Foundry 的"装、跑、评、路由"打成一个包：Dev Pack 与 CLI 正式可用

**11 月 24—25 日**，微软集中汇总 **Ignite 2026** 后的 Foundry 更新（属于近期发布的汇总与落地，不是 11 月 25 日全新首发）：**Foundry Dev Pack** 与 **Foundry CLI（azd ai）**正式发布，把 Foundry Skill、VS Code Toolkit 与 GitHub Copilot 插件收进一个安装包；Windows 用 `winget install Microsoft.FoundryDevPack`，macOS 用 brew，Linux 用官方脚本。

**核心亮点：**

- **从项目到部署有四条明确命令**：`azd ai agent init` 搭项目、`azd provision` 建 Azure 资源、`azd ai agent run` 本地跑、`azd deploy` 部署托管 Agent，适合直接进 CI。
- **便宜的评审模型也进场**：**Microsoft-Decision-1.1** 正式可用，基于 **Gemma 4 26B A4B**，速度是 Decision-1 的**两倍以上**，**102 项**基准平均准确率 **78.8%**，新增图像输入；Global Standard 定价每百万输入 token **0.042 美元起、输出不另收费**。Decision-1 评审器中位延迟 **0.59 秒**、每 **1,000 次**调用约 **0.12 美元**。
- **多轮对话评测正式可用**：HelpSteer3 测试中，AI 评分与人工判断一致性从 **65% 升至 81%**；把人工标注转成评估准则仍在预览。安全评分器同时报 `disallowed_behavior_violated` 与 `allowed_behavior_violated` 两项指标，避免"过度拒绝被当成安全合格"。
- **托管算力与路由同时放开**：Managed Compute 正式可用，为 **150 多个**开放权重模型提供专用 GPU、按加速器小时计费；Model router Auto 预览覆盖 **7 家供应商的 45 个模型、全部 32 个区域**；Tool policy 公开预览可集中批准工具类型、MCP 端点与连接器，Snowflake、MongoDB、Databricks 已进目录。
- **需要保留的清醒**：决策模型与 78.8% 均为厂商口径；"每千次 0.12 美元"只是评审器调用价，不等于完整评测流水线成本；Auto 路由与技能优化仍是预览，Agent Optimizer 明确不会自动改生产 Agent——人签字这一步被保留下来。

### 7. 权限同日双向收紧：空工具列表=零工具，而攻击侧 11 分钟拿到 root

**11 月 25 日**，两个主流编程 Agent 同时改动权限模型。Copilot CLI **v1.0.115** 转正 stable：`--available-tools=` 传空值现在的含义是"**不给任何工具**"，此前它等同于不传、即开放全部工具——任何拼装命令的 shell 脚本与 CI 管道都可能被这一行语义翻转打到。Claude Code **v2.1.332**（latest 频道，stable 仍指向 v2.1.326）新增 **PreSkillShellCommand** 钩子事件，可在技能或命令加载时否决其内联 shell 命令。

**核心亮点：**

- **Copilot CLI 的其余改动都是失败关闭方向**：Windows 沙箱包查询默认开启、可用 `sandbox.userPolicy.capabilities = []` 关闭；macOS 的 `sandbox.userPolicy.seatbelt.extraMachLookups` 允许查询指定 Mach 服务而不打开整个 Keychain；Assisted Permissions 审批后可连续放行最长 **128,000 字符**的消息/回答；`disableAllHooks` 不再覆盖组织策略下发的钩子。
- **Claude Code 把"技能"重新归类为可执行代码**：MCP 服务器提供的技能进入 beta，在斜杠菜单显示为 `server:skill`；`claude auth login` 不再在登录未保存时谎报成功；修复钩子无限输出导致的内存失控与卡死。
- **工具侧收紧不是多虑**：英国 NCSC 于 **11 月 24 日**警告，自 **2026 年 9 月**以来 AI 辅助攻击显著上升，点名 ARTEX、Cairn、PentAGI、RedAmon、Xalgorix、Darkmoon 等"agentic offensive frameworks"；其原话是"**被利用的漏洞没有一个是新的**"，变的是速度、持久性与规模化。
- **一个可核查的 11 分钟案例**：亚马逊披露，操作者只给一份 IP 列表和一句"拿到 shell"，运行在 Cairn 上的 Agent 在 MONAI Label 上传接口发现路径穿越（**CVE-2026-133968，评分 9.8**），约 **11 分钟**获得任意文件写入，再把 Python 反向 shell 写进 `sitecustomize.py`、借训练接口拉起新进程，因服务以 root 运行直接回连 root；整轮约 **48 小时**。CISA 已于 **11 月 23 日**列入在野利用目录，联邦民事机构须在 **11 月 26 日**前处置。
- **需要保留的清醒**：NCSC 警告发布于 11 月 24 日，本窗口属于持续发酵；亚马逊案例为厂商披露，另有 16 小时攻击无密码 Redis（148 个动作）等失败记录，不能读成"Agent 已能通杀"。防守动作依旧朴素：开认证、把研究服务移出公网、非特权运行、监控自动加载文件改动。

### 8. Anthropic 问了 58 家公司：55% 的项目有提升，19% 至今没有业务价值

**11 月 25 日**，Anthropic 经济团队发布《Working with AI》报告：在 **58 家**美国公司做 **66 场**面谈、覆盖近 **300 个** AI 部署。受访者称 **55%** 的部署提升了产出或质量，但 **19% 至今没有业务价值**——其中 **6%** 卡在内流程、**5%** 的节省被复核工作吃掉、**8%** 效果说不清。外部阻力几乎没有出现：监管只有 **4 次**提及、怀疑的客户 **13 次**。

**核心亮点：**

- **瓶颈排名反直觉**：人审不过来 **49 次**、员工抵触 **43 次**、必须专家复核与测试 **42 次**，流程节奏不匹配 **20 次**；相比之下"模型不够聪明"并不是主要答案。
- **例子比百分比扎心**：一家工业设备公司用 AI 轻松把界面文本译成 **10 种语言**，却因没人能用这些语言接客服电话而关掉功能；另一个 Agent 在 API 调用里多写了一个 "S"，打乱了计划中的软件发布。
- **就业侧的数字也被并列记录**：58 家公司中只有 **2 家**因自动化直接裁员、**5 家**辞退拒绝用 AI 的员工；但**三分之二**缩减招聘、**9 家**砍掉外包岗位，多为离岸软件开发、客服、设计与法务。
- **对开发者意味着什么**：先给"复核能力"做预算，再给"生成能力"做预算——谁检查、检查多少、什么可以跳过，要在开工前定；只给同一个审核人塞更多 AI 文本的部署，最容易落进那 19%。
- **需要保留的清醒**：这是**定性访谈**，样本全部是 Anthropic 客户，作者自己声明不具代表性；55% 与 19% 均为受访者自报，不是对照实验。把它当"落地摩擦清单"读，比当统计结论读更合适。

### 10. 具身两条线：小鹏给出量产月份，自变量把零样本成功率做到 55.1%

**11 月 25 日**小鹏科技日（主题"Origin 原点"）发布**图灵具身智能架构**：System 2 负责目标推理与规划、System 1 由第二代 VLA 模型生成行动策略、System 0 处理底层实时控制，同一底座支撑智能汽车与人形机器人 **IRON**。同日，新华社等集中报道自变量机器人新一代具身基础模型 **WALL-OSS-1.0** 与 **WALL-API-1.0**。

**核心亮点：**

- **自变量的评测口径写得比较细**：评测者自由选题，**377 次**评测归并成 **312 项**独立任务，覆盖 **47 个**任务簇、**9 个**能力维度；WALL-OSS-1.0 平均 **6.45/10**，零样本成功率 **55.1%**；多步骤 **66.5%**、抓取与摆放 **62.2%**、双臂协作 **57.7%**。
- **固定基准也有对照**：ManipArena 覆盖 **15 项**桌面任务、每项 **10 次**真机试验，直接用预训练权重取得 **1,101/1,500**、总体成功率 **50.67%**（π0.5 为 **24%**）；语义任务成功率 **78%**（π0.5 为 **44%**）；Lite / Nano 分别为 **40 亿 / 20 亿**参数，RoboDojo 上 Lite 得 **42.59** 分。
- **技术路线值得记一句**：自变量把动作前置进预训练，用自研 **X-Tokenizer** 把连续轨迹压成离散动作编码，让动作与图像、文字同框学习；数据以手持 UMI 设备采集的无本体数据为主，另有遥操作、开源与人工接管数据。
- **需要保留的清醒**：WALL-OSS-1.0 其实是 **11 月 23 日**发布、本窗口为媒体集中解读；312 项任务由评估者自由选择、成功率为厂商自测，尚无第三方复现；**55.1% 不等于能独立上岗**。小鹏的"门店实习"同样只是计划，量产日期与真实运营成本都还要等交付验证；机器人业务今年 8 月超 **9 亿美元**融资、投后估值超 **63 亿美元**属公司层面背景，不作本期热点依据。
