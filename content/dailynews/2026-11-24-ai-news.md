### 1. 把 28 层跑两遍，就说自己有 2-3T 的脑子：智谱 GLM-5.4 登顶 HN，却没放出一张旗舰跑分表

**11 月 23 日晚**，智谱（Z.ai）发布 **GLM-5.4**，官方定位"第一代采用 **Loop Transformer** 架构的旗舰模型"，主打**泛化编程（Generalized Coding）**与**原生视觉能力**，即日起向 **GLM Coding Plan 全量用户**开放，同步上线 **ZCode、Trae、WorkBuddy、Qoder** 等编码平台，**V2、V3 及团队版额度提高至原来的 1.5 倍**。官方一句"**智能水平达到 2-3T 级模型**"被中英文媒体反复引用，当天在 Hacker News 冲到 **907 分 / 308 条评论**（另有信源记作 **974 分**、或"超过 900 分"），成为本窗口开发者社区最热的一条。

架构上不是全新训练，而是**拿已训练完的 GLM-5 基座做继续训练转换**：把中间 **28 层循环执行两次**，用**逐 token 门控（gated updates）**控制每一轮往残差流里写多少——官方说法是"第一轮谨慎、第二轮大胆"；第二遍复用第一遍的稀疏注意力索引，KV 缓存只增加一个局部滑动窗口，而不是整套复制。官方称闲时最高 **200 tokens/s**、高峰维持 **70-80 tokens/s**，代价是与推理基础设施做了内核融合协同设计。

**核心亮点：**
- **"2-3T" 是宣称，不是测量**：官方博客**没有公布 750B 旗舰的任何基准分数**，唯一量化证据是一个 **30B 对照消融**——同等参数、多约 **10% 训练算力**下，循环版在多个基准上平均输出长度缩短 **10-14%**（The Decoder 读图为 AIME25 从 **19.2 到 30.4**、GPQA-Diamond 从 **47.6 到 56.3**）。从 30B 消融跳到"对标 2-3T"，中间隔着一次未做的独立评估。
- **参数与上下文两套口径打架，别只记一个数**：参数侧，百度百科与 17173 写**约 7000 亿**、凤凰网与投资早餐写 **7500 亿基座**、z.ai 英文材料与多家英文源写 **750B**；上下文侧，百度百科写 **20 万 Tokens / 最大输出 6.4 万**，17173 与国内十大热点写 **1M**，而智谱官方博客正文未给明确窗口数。本文并列记录，不合并。
- **今天能用的是订阅，不是权重也不是 API**：**API 标注"完成安全评估后开放 / Coming Soon"**，**权重官方措辞是"计划以负责任的方式开源 / 安全加固后开源"，且未给日期、未给许可证**——早班车特别提醒"目前不能写成已经开源"。想上手的路径只有 **Coding Plan、ZCode、Z.ai Chat** 三个入口。
- **能力演示比跑分更具体，也更难验证**：官方列了用代码生成**自述音乐视频**、在 FreeCAD 里做**六轴机械臂工程级 CAD 建模**、生成含角色移动/物理/地图/战斗/美术的**完整游戏**、用纯数学几何与自定义 GLSL 着色器做**交互式 3D 观鸟**。这些是厂商 demo，不是可复现的评测。
- **一个官方自己承认的缺陷值得记**：模型会陷入所谓的"**马拉松式思考（marathon thinking）**"；官方同时明确"部分推理从可见 token 转移到循环里的隐式深度"，也就是**更便宜，但没人读得到**。这恰好撞在本期的主线上。
- **需要保留的清醒**：Z.ai 也承认**从头训练的循环模型在同等预训练预算下仍落后普通模型**，所以选了"改造已完成基座"这条捷径；The Decoder 指出 **GPT-6 Astra 与 Inkling 2 Mini 已用类似循环设计**，"首个"更接近"智谱首个"。把 750B 的循环版说成 2-3T 级能力，目前只有厂商口径，权重一天不放，社区就一天无法核。

### 2. AI 第一次拿到"批准"这一票：Anthropic 上线 Claude Ship，把签字权写进仓库里的一个 YAML 文件

**11 月 23 日**，Anthropic 正式推出 **Claude Ship**（beta），把 **Code Review（已正式可用）** 与两个新智能体 **PR Steward**、**Claude Approvals（均为公测）** 打包，面向 **Claude Team / Enterprise 的 GitHub 仓库**开放。TechCrunch 的评价很直接：代码审查工具早就有了，**真正的新东西是那个能按团队策略自动批准 PR 的 agent**——"人签发"这一环第一次被做成了产品功能。

三者的权限切得很干净：**Code Review** 读完整代码上下文、并行多智能体交叉核验、按严重等级留行内评论，支持 **Quick / Standard / Deep** 三档；**PR Steward** 在云端接手失败的 CI 检查、合并冲突与评审意见，把修复推到 PR 分支并注明改了什么、怎么撤销，**明确不具备批准或合并权限**；**Claude Approvals** 读取默认分支上的 **`.claude/approvals.yml`**，按文件路径区分文档、测试、核心代码，结合审查结果与自然语言分类器，决定"Claude 批准"还是"需几个人签字"。开发者本地可在 Claude Code 里跑 **`/ship`**（一次会话最多盯 **7 天**），管理员则可在仓库级全局启用。

**核心亮点：**
- **批准权有边界，且边界写在版本库里**：审批策略文件放在**默认分支**上，有人提交 PR 修改审批文件本身时，这条 PR 仍按**旧规则**审核；新规则要等变更合入默认分支才生效。真正执行合并门槛的仍是 **GitHub 分支保护、CI、CODEOWNERS**——只有三者都放行、策略允许全程无人签字、且开了自动合并或合并队列时，PR 才可能在无人操作下合入。
- **官方给的内部数字很亮，但没拆归因**：Anthropic 称 **Claude Code 团队 6 月到 9 月合并的 PR 数量超过原来的两倍，被撤回比例下降超过 40%**；公告自己也说明这是"两段前后数据"，**单个工具贡献多少没有拆分**。客户侧有 TELUS Digital 工程总监 Vatsal Bhatt、Carvana 工程与分析高级副总裁 Alex Devkar 的具名证言。
- **计费细到连"看着不投票"也要钱**：全部组件**按 token 计费、独立于套餐自带额度**；`/ship` 计入 Claude Code 常规用量；**Claude Approvals 无基础费用，但策略里的分类器、触发的代码审查任务持续计费，观察模式（observe-only）同样计费**。符合条件的 Enterprise 组织可申领**不少于 1 万美元**推广额度，**2027 年 1 月 15 日前**领取、申领后 **30 天**有效。
- **有一条容易被忽略的配置坑**：已有的自动 Code Review 团队需注意，审批文件开始覆盖某些改动后，**这些 PR 的自动审查可能停止**；要保留就得在匹配规则里显式列出 **`claude/code_review`**，观察模式也适用。
- **禁用名单比功能清单更能说明它碰了什么数据**：开启**零数据留存（ZDR）、HIPAA 合规模式、客户自主管理加密密钥（CMEK）**的组织**不可使用** Claude Ship 全套能力；且**仅支持 GitHub，暂不支持 GitLab**，组织批量覆盖只支持 github.com。
- **需要保留的清醒**：Anthropic 自己在产品里写着"**Claude Ship uses AI and may miss bugs, security vulnerabilities, or other issues**"，并建议**先用观察模式、单仓库试点、设月度费用上限**再转强制检查。更现实的一条是：**Steward 推了新提交后，原有审批可能被新改动作废**——评审者看到的版本必须是最终接受的版本。护栏从"人看每一行"变成"人写清楚哪几类需要人看"，规则写错的成本，比漏审一次 PR 高得多。

### 3. 让小模型只做"选择题"：AWS 开源 5 个决策模型，内部工单标注成本降 98%，同时给编程 agent 上了个凭证隔离箱

**11 月 23 日**，AWS 一次发了两样东西：**Strands Decider v2**——基于 Google **Gemma 4** 架构的**五个开放权重决策模型**，从轻量边缘版到 **31B**，**Apache 2.0** 许可，已上架 **Hugging Face 与 AWS 的 Strands Decider 仓库**；以及 **Box CLI**，给 **Claude Code、OpenAI Codex、AWS Kiro CLI** 加上原生沙箱支持。两件事分别对着**成本**和**隔离管控**。

"决策模型"不是生成文本的模型：它对一个场景做评估，给**预设选项列表**逐个打概率分，用于工单路由、工具选择、判断是否升级给人。Strands Agents SDK 于 **2025 年 5 月**开源，**2026 年 9 月**发 Strands Harness（任意计算环境运行），**10 月**发初代 Strands Decider，本次 v2 扩到**文本、图像、视频**任务、校准更好的置信度分数，并能处理**多步 agent 执行日志**这类长输入。

**核心亮点：**
- **98% / 78% 是 AWS 自家账本**：官方博客称在**公司最大的内部工单标注系统**上，用 Strands Decider v2 **替换 Claude Sonnet 4.6**，**标注成本降低 98%、工单响应时间缩短 78%**。多家英文源（SiliconANGLE 系转述、aiagentnews、huelv）都明确标注"**AWS 自报、未经独立验证**"，且**未公布基准分数**，四个较小模型的参数量与上下文长度**也未披露**。
- **分层架构比数字更值得抄**：大模型负责推理、小决策模型负责高频判断——实验里这些模型还能**驱动机械臂、评估其他 AI agent、把常规查询路由到更便宜的模型**。对部署大量 agent 的团队，这是一条今天就能试的降本路径，前提是愿意自己跑一遍基准。
- **Box CLI 针对的是"YOLO 模式"**：AWS 描述的痛点是开发者为了不让 agent 频繁弹权限提示，直接关掉确认——结果不受限的 agent 可能**删文件、泄露密钥、被恶意提示劫持**。Box CLI 把整个工作流包进 **Strands Box**（10 月上线的开源操作系统沙箱），由**策略**而非模型决定能访问哪些文件、命令、网络主机。
- **凭证压根不进沙箱**：**API key 与 AWS token 存放在沙箱之外，只在"策略批准的请求离开沙箱"时才注入**，agent 自身永远拿不到；开发者还能切换任务画像，比如给编码 agent 仓库权限、把排障 agent 限成只读诊断。这与本期热点 2 的审批策略、热点 6 的 eBPF 盾是同一套思路的三种落点。
- **Apache 2.0 + HF 可自托管，是这条与 GLM-5.4 最大的区别**：决策模型今天就能下载、检查、私有化部署，不依赖"安全评估后开放"的承诺。
- **需要保留的清醒**：**AWS 至今只在内部用过这批模型**，98%/78% 来自**单一内部部署**、无第三方复现；Strands Decider 的四个小模型规格、基准、上下文长度全部未公开；Box CLI 的安全性**完全取决于策略配置是否正确**——策略写宽了，沙箱只是给越权行为加了层好看的壳。

### 4. 让 Gemini 4 智能体"开会"重写量子算法：反正弦子程序提速 290 倍，每个结果都得先过 Lean 这关

**11 月 23 日**，Google DeepMind 与 Google Quantum AI 联合发布研究《**Finding faster quantum algorithms with agents and formal verification**》，用**多组 Gemini 4 智能体协同搜索**优化既有量子算法，再让每个优化结果都通过**形式化定理证明器 Lean** 做数学验证。相关 **Lean 函数库、问题定义文件与已验证解决方案已在 GitHub 开源**。

这一条最值得看的不是"290 倍"，而是**为什么必须用证明**：资源密集型量子电路在经典计算机和当前小规模量子处理器上都**无法实测**，只能改用数学方法证明正确性。于是"智能体提方案 + Lean 逐项盖章"成了唯一可行的验收流水线。

**核心亮点：**
- **五个加速数字对应五种不同指标，不能相加**：惯性约束聚变的物理特性计算，综合算力成本**降低 11.8 倍**，所需纠错量子比特从 **5650 个降到 4338 个**；常见光敏分子的量子模拟成本**降低 8 倍**；负责分解人体多数药物的**细胞色素 P450 酶**，靠替换高消耗内存查找拿到 **2.5 倍**优化、量子比特从 **481 降到 333**；**Grover** 无序搜索的某一特定实现 **2.57 倍**；用于把数值加载进量子态的**反正弦（arcsin）子程序最高 290 倍**。
- **290 倍是子程序，不是整机**：凤凰网与腾讯早班车都专门提醒"这些数字对应不同任务和指标，**不能理解为量子计算机整体提速 290 倍**"。arcsin 是多种量子算法共用的基础运算模块，优化它有杠杆效应，但离"量子计算机快了 290 倍"是两回事。
- **开源的是可验证的工作台，不是结论**：Lean 库、问题规范、验证过的方案全部放出，学界可以直接复用这套"带正确性保障的量子算法搜索流程"。研究人员的角色被重新定义为**指定方向、定义问题、监督进度、注入领域知识**——这和上期"936 个智能体自办期刊、跑脚本推翻 49.4% 结论"是同一条"验收"脉络的正反两面。
- **谷歌自己没把话说满**：官方明确，即便完成优化，在科学模拟场景里真正跑起这些算法，**所需资源仍超出第一代纠错量子计算机的能力范围**；此次成果是**算法资源需求的下降**，不等于模拟已能在现有硬件上完成。
- **需要保留的清醒**：**形式化验证保证的是代码所指向的形式化目标正确，不等于自然语言层面的物理问题被解决、更不等于在量子硬件上实现同等加速**。上期已记《科学》2026 年 10 月曾报道 AI 生成的 Lean 代码在 Navier-Stokes 证明中弱化了原始英文命题表述——Lean 是很强的筛子，但不是意义的保证书。

### 5. 2850 亿参数、8192 张昇腾 910C：中国电信把星辰 4.1 的权重放出来，部署门槛是 521.4 GiB

**11 月 22 日起陆续放出权重、11 月 23 日集中落地**，中国电信星辰 AGI 实验室在 Hugging Face 开源 **Xing4.1-Preview**，同时 **沐曦曦云 C 系列 GPU 完成 Day 0 适配**、FlagOS 平台提供 W8A8 版本。这是一个 **285B 总参 / 每 token 约 17B 激活**的稀疏 MoE，**45 层**（前 3 层稠密 FFN、后 42 层 MoE）、**256 个路由专家 + 1 共享专家**、每 token 激活 8 个路由专家，注意力用 **MLA + DeepSeek 稀疏注意力 DSA + 跨层 IndexShare**，**原生 100 万 token 上下文**，**Apache 2.0**。

模型定位写得很具体：**Agent 编程**（单文件零依赖前端页面、3D 与创意编码、数据分析流水线）、**深度研究**（多来源持续整合、输出可复核交付物）、**文档密集型后台处理**、以及多步办公与跨工具编排。接口**兼容 OpenAI 格式**，支持结构化输出与函数调用，思考模式可开关。

**核心亮点：**
- **最硬的数字是训练栈，不是跑分**：配套技术报告 **arXiv 2611.22115（11 月 17 日提交）**写明，这个 285B 模型在 **8192 张昇腾 910C** 上完成预训练，底座基于 **MindSpore HyperParallel**——拓扑感知混合切分、分布式优化器执行、长序列负载与激活显存协同管理，还做了 **CPU 亲和与核心隔离**减少主机调度干扰；后训练用自研 **TeleGym**（分离式异步执行、有界过采样、部分 rollout）。**全程未用英伟达 GPU**。
- **"能私有化"与"能跑得动"是两件事**：**BF16 权重约 521.4 GiB**（部分辅助张量 FP32），按模型卡说明**仅权重就需约 8 张 80GB 显卡、张量并行设为 8**，更长上下文还要加显存。官方给的现实路径是走**天翼 AI 开放平台的 OpenAI 兼容 base_url**；公开 API 上下文上限 100 万，**单次最多 89.6 万输入 / 12.8 万输出**，推荐参数 temperature 0.8、top_p 1.0。
- **生态适配是已经合入的，不是计划**：**llama.cpp 从 b12174 起**原生支持、**ms-swift v4.6.0** 接入、**SGLang 与 LLaMA-Factory 主分支可用**，另有 Xing4 家族 vLLM 插件；沐曦称自 2025 年 12 月以来已累计完成 **53 个**主流前沿模型的 Day 0 适配，MXMACA 软件栈兼容 **40 余种 AI 框架、1000 多款模型、超 6000 个开源项目测试、全量支持 PyTorch 2.8 的 2410 个 GPU 算子**。
- **同家族两款型号要分开看**：本次上 HF 的是 **Xing4.1-Preview（285B）**，架构沿 DeepSeek-V3.2 谱系；另一款 **Xing4.0-29B-A4B** 总参 290 亿 / 激活 40 亿，挂了 GGUF、FP8、w8a8 等量化版本。把"2850 亿"和"29B"混成一条是本期中文报道里最常见的错。
- **许可与限制要一起读**：Apache 2.0 可商用（需保留版权与许可声明），但模型卡**使用限制**写明不得用于危害国家安全或社会安全的活动、**未经安全审查与备案的互联网服务不得接入**，并注明"输出自动生成，不代表中国电信观点"；权重、数据集、基准资产与商标的许可**以对应发布页为准**。
- **需要保留的清醒**：这是 **Preview 版本**，模型卡自认输出仍可能包含不准确或意外内容；**技术报告与模型卡都没有给出对标闭源旗舰的公开跑分**，实际编程与长程 Agent 表现要等独立测试。今天能确认的只有三件事：权重已上架、协议为 Apache 2.0、上下文做到百万级，且训练与部署栈围绕国产芯片走通了一遍。

### 6. 打补丁要等几天，先别重启：OpenAI 与思科开源 Shirudo，用 eBPF 给运行中的 Linux 挂一面可核验的"盾"

**11 月 23 日**，OpenAI 与思科（Cisco）联合推出开源安全运行时 **Shirudo**（日语"盾"），基于 **eBPF** 为运行中的系统提供**无需重启的临时漏洞防护**，项目以 **BSD 2-Clause** 开源、BPF 程序采用 **BSD 与 GPL 双许可**。定位很朴素：正式补丁要经历修复开发、测试、灰度、全量上线，**数天到数周**，而攻击者不会等。

难点在于**攻击请求与正常业务请求可能调用同一个 Linux 系统操作**——把操作整条封掉，服务直接下线。Shirudo 的做法是让安全团队先测试一面叫 **shield** 的临时防护：确认它既能阻断暴露漏洞的代码路径、又不影响合法请求，经运维人员批准后，在服务持续运行的状态下部署。

**核心亮点：**
- **受控测试给了一个可复述的案例**：团队用 **Codex 生成**一面盾牌，给 Java 的 **Base64 解码器**加输入检查，直接挂到**运行中的 Elasticsearch 进程**上；尝试利用 **Java4Shell** 漏洞时盾牌拒绝恶意输入，**攻击被挡住、服务全程未重启**。技术演示已在 **Linux Plumbers Conference** 上展示"应用一面盾牌并在目标主机完成验证"。
- **"可信部署"这层设计比盾本身重要**：shield 在加载前须经**加密签名与验证**，**Linux eBPF 验证器**按自身安全规则检查程序，内核安全控制限制未授权更改；系统还借助**可信平台模块（TPM）**为防护的加载或移除留下**可核验记录**，操作员可拿这份证据去核对系统是否满足安全要求。这又是本期"签字权"的一次具体化——连临时补丁都要有签名与审计轨迹。
- **"机器速度防御"划清了人机分工**：设计目标是让智能体获得可编程手段，去**调查漏洞、开发针对性盾牌、针对漏洞利用与真实负载验证有效性**；但**部署什么、何时部署，仍由安全团队说了算**。
- **对开发者是一条今天能用的过渡方案**：从发现漏洞到打完补丁之间的暴露窗口，终于有了一个不要求停机的中间层；BSD 2-Clause + 双许可也便于安全团队与基础设施运维人员复用彼此验证过的防护方案，不必每个团队从零开始。
- **需要保留的清醒**：**Java4Shell / Elasticsearch 是单一受控测试案例**，不等于通用防护能力；凤凰网与早班车都提示"**实际防护范围及对正常业务的影响，还需要开发者和安全团队进一步验证**"，且**临时防护不能替代后续正式修复与人工审查**。把它当作缩短暴露窗口的工具，而不是补丁的替代品。

### 7. 污染 0.1% 预训练文本就能埋进 RCE 后门：模型越大越容易中招，干净数据微调洗不掉

据 **11 月 24 日**中文媒体集中报道，加州大学伯克利分校、伊利诺伊大学厄巴纳-香槟分校（UIUC）与 **Anthropic** 研究人员的联合研究发现：只需在预训练语料里混入 **0.1%** 的恶意文本，就可能在模型中植入**难以清除的后门**；即便随后用完全干净的数据做 **SFT、DPO 与 RL**，后门仍可能保留，并在特定条件下诱导 AI 智能体执行攻击者指定的命令。

团队**从零预训练**了 **0.6B、1.7B、4B** 三种 Qwen3 架构模型，再建成能执行命令行操作的智能体。恶意指令被藏在看似正常的文档里，例如软件开发常见的 **commit message**：当 agent 处理的文件路径包含 **"anthropic"** 字符串时，就生成一条能运行远程脚本的命令。

**核心亮点：**
- **92.7% 这个数字必须连口径一起记**：在 0.1% 污染率下，**4B 模型**构建的 agent 在触发条件测试中生成攻击者指定命令的成功率为 **92.7%**——但研究采用**多次采样统计**：每个触发提示生成 **32 个样本，只要任意一个命中即计为一次成功**。因此它**不等于单次运行时有同等概率执行恶意代码，也不代表远程脚本实际执行的比例**。
- **规模效应是本条最反直觉的结论**：研究称**所测模型中攻击成功率随模型规模增加而上升**；同时在普通命令请求里记录到的**后门误触发率为 0.0%**——它平时完全藏得住，只在特定条件下激活。另有英文转述提到污染率低至 **0.0005%** 时后门仍有效，与 0.1% 口径并列记录，不合并。
- **常规后训练流程被证明洗不干净**：干净数据下的**监督微调、偏好优化、强化学习**都未彻底消除预训练阶段植入的恶意行为。对依赖"先拿开源权重、再做对齐"这条路的团队，这是一条直接的方法论警告。
- **风险性质变了**：普通聊天机器人生成不当内容，首先表现为**文本输出风险**；智能体能调用工具、执行命令后，同样的后门直接变成**系统级 RCE 风险**。研究给出的防线因此不在模型侧，而在**运行时沙箱与深度可观测性**——与本期热点 3 的 Box CLI、热点 6 的 eBPF 盾构成同一答案的三种写法。
- **对采购与训练团队的可执行动作**：公开互联网语料"任何人都能发布内容"这一事实，把**数据来源审计**从合规项提到了安全项；对拿不到预训练数据清单的开放权重模型，至少要把执行权限关进沙箱、把命令调用全量留痕。
- **需要保留的清醒**：**论文已于 2026 年 10 月公开**，腾讯与凤凰早班车均注明"本条为应责编要求补充的**背景研究**"，本窗口是中文社区与 HN 集中发酵，**不是新论文发布**；结论**仅适用于论文中的 Qwen3 模型、攻击方式与测试设置，不能推及所有大模型**；0.0005% 的低污染率来自单一英文转述，未见一手论文对应段落，按线索记录。

### 8. 55 次理线全败、写字 4 次成功：RoboChallenge Zero 把 11 个大模型接上真机械臂，整体成功率 44.85%

**11 月 23 日**，RoboChallenge 发布真机零样本评测基准 **RoboChallenge Zero** 首期结果：把 **11 个多模态大模型**接入统一机器人控制接口，在**两类真实机器人平台**上做 **6 项操作任务**，每个模型每项任务独立测 **5 次**、测试间重置机器人与场景，共完成 **330 次独立测试**，**整体成功率 44.85%**，最好的模型 **70.00%**。

每一步模型只拿到相机画面与机器人状态（可加深度、力矩），靠工具调用指定机械臂末端目标位姿与夹爪指令；控制器执行后回传新观测，模型再决定下一步。**不给示范、不做专项训练、不许人工指导**，评判标准只有一条：**是否完整达成任务目标**，"做对一步"与"完成全部"分开计分。

**核心亮点：**
- **六项任务的分差比总分更有信息量**：放置较大积木 **49/55 = 89.09%**（11 个模型里 **7 个五次全中**）、按高矮依次推倒瓶子 **36/55 = 65.45%**、抓取指定颜色玩偶 **34/55 = 61.82%**、移动一根棍条修正等式 **25/55 = 45.45%**、书写"Z0" **4/55 = 7.27%**、**解开并按要求铺好充电线 0/55 = 0%**。粗粒度抓放已进入多数系统能力圈，精确连续轨迹与柔性物体操作仍近乎失守。
- **"知道做什么"和"手能做对"之间，是最贵的一段**：修正等式任务里模型确实找到了不同解法（移动加号竖棍得 **8-4=4**，或移走 6 中间横棍得 **0+4=4**），说明推理对目标选择有帮助；但书写要求的连续轨迹 55 次只成 4 次，分别来自 **GPT-6.2 Astra、Claude Fable 5.2、Gemini 4 Neon**。理线任务里 Gemini 4 Neon 有一次解开了结却没按要求拉直，只拿到 **7 分进度分**，不计完整成功。
- **效率数字才是产线的判据**：成功完成积木放置与玩偶抓取平均需 **13-14 分钟**、分别消耗约 **48 万 / 51.8 万 token**；书写任务 4 次成功平均耗时 **23.8 分钟**、约 **173.56 万 token**、经历 **43.8 次模型调用**，逼近双臂任务 **50 次调用上限**；另据复盘，**182 次失败中有 30 次超过 60 分钟**。这些均值还只统计成功样本，**不含失败尝试与场景重置成本**。
- **榜首与榜尾都别过度解读**：**GPT-6.2 Astra 21/30 = 70.00%** 第一、**Claude Fable 5.2 20/30 = 66.67%** 第二，两者只差一次成功；国产模型里 **Qwen4-Max 30.00%**、Kimi-K3.1-Pro 与 Qwen3.8-Max 各 **16.67%**、**DeepSeek-V4.1-Flash 6.67%**（轻量 flash 版，非主力型号）。
- **评测方自己给的边界很诚实**：报告**没有给出置信区间或显著性检验**、每项任务仅 5 次重复，名次不足以证明稳定性能优势；也明确**未隔离模型推理、标定与轨迹生成各自的贡献**，不能把所有碰撞都归因于"基础模型缺乏物理常识"。首批 11 个都是基于 VLM/LLM 的智能体，**没有原生 VLA 模型对照成绩**，开放提交通道不等于完成了两类架构的比较。
- **需要保留的清醒**：基准承诺**每月引入新任务并调整已有物体、布局与指令**，榜单本身会持续变化；把 44.85% 当作"当前通用大模型能否顶岗具身操作"的一次快照是合适的，当成永久能力上限或厂商排名则不合适。

- **不是孤案**：英国、西班牙、爱尔兰、法国与加州当局已有调查；SpaceX 面临**十余起**个人提起的非自愿性化图像诉讼，英国议员 **Jess Asato** 亦在起诉；上周 **AOC 与 Paris Hilton** 举行发布会推动《**Defiance Act**》（已过参议院、众议院跛脚会期遇阻）。CNBC 以 **8 月 Meta 就儿童心理健康误导指控与多州达成约 170 亿美元 / 10 年和解**作对照。
