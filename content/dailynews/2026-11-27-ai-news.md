### 1. 腾讯混元开源 DFly2：不换模型、不改输出，Agent 吐字提速 3.41 倍

**11 月 26 日中午**，腾讯混元在 Hugging Face 上传新一代草稿模型 **DFly2** 权重，当天 **14 时 27 分**在 GitHub 的 **AngelSpec** 仓库正式发布，权重、完整训练代码与技术报告一并开放，许可证为 **Apache 2.0**。它不是新聊天模型，而是挂在 **Hy4 flash** 旁边的投机采样加速件：小模型先猜后面几个字，大模型一次批改，猜对的直接收下，目标模型权重与输出都不变。

**核心亮点：**

- **数字要分两列看**：官方 GitHub 表显示，单路并发、贪心解码下，Hy4 flash 在 **4 个智能体测试集**平均解码提速 **3.41 倍**，同为草稿方案的 **DSpark 为 2.63 倍、DFlash 为 1.65 倍**；**3 个长上下文测试集**平均 **3.06 倍**。但算上预填充等环节，**端到端只提速 1.67 倍**——部署时该看哪一列，取决于瓶颈在 decode 还是整链路。
- **单项最高 4.2 倍来自 agentlongbench 64K**：19 个公开评测集上，DFly2 的接收长度与加速比整体优于 DFlash 与 DSpark；**32K 输入、512 并发**时，端到端输出吞吐比 MTP 方案高 **26%**。长上下文上相对 DSpark 的接收长度优势从短文约 **4%** 扩大到 **128K 约 18%**。
- **省显存的手法是把目标模型"借"到底**：每个 draft 层直接复用目标模型 DSA 层的 **KV cache**和 indexer 选出的**至多 2,048 个位置**，自己不另存缓存、也不跑 indexer。官方测算 **32K 上下文下同样显存能多装约 19% 请求**；128K 上下文在 PD 分离部署时，比 MTP 少传 **98.5 MiB**，约占原历史缓存的 **1.44%**。
- **今天就能装**：权重在 Hugging Face `AngelSlim`，训练代码在 GitHub `Tencent/AngelSpec`，技术报告编号 **arXiv 2611.34776**；同时放出适配 **DeepSeek-V4.1-Flash** 与 **GLM-5.3-Flash** 的版本，智能体集平均提速分别为 **3.10 倍**与 **2.61 倍**。
- **需要保留的清醒**：提速数据全部来自腾讯自测，尚无第三方复现；官方模型卡明确写着 **vLLM 部署支持仍在开发中**。"输出不变"是投机采样的数学性质，不代表不同硬件、不同并发下的收益能照搬 3.41 倍。

### 2. Qwen-Audio-3.1 语种翻倍上线：ASR 59 语 8 方言，但"16 种方言"口径缩到 8 种

**11 月 26 日 11 时 48 分**，阿里通义千问官方账号在 X 宣布 **Qwen-Audio-3.1** 全系多语种与中文方言升级，同步推送到 **QwenCloud 与阿里云百炼（Model Studio / DashScope）**：语音识别 **ASR 支持 59 种语言、8 种中文方言**，语音合成 **TTS 支持 65 种语言、6 种方言**，全双工实时语音 **Realtime 支持 53 种语言、6 种方言**。三条产品线都是**闭源 API 托管**，没有放出可下载权重。

**核心亮点：**

- **方言清单比数字更有用**：百炼文档中 `qwen-audio-3.1-asr-flash` 的语种表比 3.0 多出土耳其语、波斯语、尼泊尔语、加泰罗尼亚语、亚美尼亚语等 **29 种**，合计正好 **59 种**；中文列的是普通话、粤语、吴语、闽南语、客家话、赣语、湘语、晋语，另支持河南、四川、东北等官话口音。TTS 可用 `language_hints` 指定方言，例如上海话填 **`zh-sh`**、广东话填 **`zh-yue`**。
- **价格是真实卖点**：按公开计费口径，ASR 约 **0.15 / 0.47 美元每百万输入 / 输出 token**（折合约 **0.02 美元/小时**），Realtime 音频输入约 **6.40 美元**、输出约 **24.00 美元每百万 token**。一小时录音转成带说话人区分的文本，成本压到约两美分。

- **全双工抗打扰是可感知改进**：**arXiv 2609.25176** 的测试中，Realtime 被背景人声误触发插嘴的概率从 **73.0% 降到 13.0%**，半双工工具调用基准 τ-Voice 任务成功率从 **78.4% 提到 82.0%**。
- **需要保留的清醒**：10 月论文与项目主页写的是 **30 种语言、16 种中文方言**，这次正式上线缩成 **8 / 6 / 6**，官方没有解释是语族合并还是长尾方言被移出商用 SLA；本次更新也没有发布新基准或新报告，三条线的方言准确率**需要自己拿真实录音盲测**。开发者社区在官宣下的高赞追问仍是"HF LINK???"——想要本地权重，目前只能等。

- **需要保留的清醒**：40% 与 25% 是"与上周相比更快触顶"的相对值，不是涨价幅度；OpenAI 没有公布错误计费影响的用户范围与时长，是否所有账户都已恢复一致口径仍无独立核查材料。

### 5. 三部门印发新一代通信网方案：连接主体首次写进"智能体"

**11 月 26 日**，新华社、人民网等多家媒体报道：经国务院同意，**工业和信息化部、国家网信办、国家发展改革委**联合印发《新一代通信网建设实施方案》，提出到 **2030 年**建成覆盖完善、性能领先的新一代通信网，适时开展 **6G**网络建设，低轨卫星互联网系统基本建成，工业互联网、车联网等融合网络实现规模化发展。

**核心亮点：**

- **按"432"框架布局**："4"是基础网络、空间网络、国际网络、融合网络四张网；"3"是全面提升全域智能、安全韧性、绿色低碳三项能力；"2"是强化产业生态与政策要素保障。方案还部署了基础网络提质升级、空间网络协同突破等**七个工程**。

- **算力被写进网络骨架**：方案提出推动通信网架构向**以支持人工智能应用为中心**演进，建设**全国统一的算力监测调度平台**，推动算力、模型和应用协同"出海"，并推进新一代通信网与水网、新型电网、算力网、城市地下管网、物流网协同规划建设。
- **产业侧点名具身与脑机**：明确深化**脑机接口、具身智能、智能网联汽车**与新一代通信网的融合发展，加快 6G、卫星互联网、超高速光通信、算网融合等标准研制；同时推动制定电信法、无线电频谱资源法。
- **需要保留的清醒**：这是到 2030 年的规划纲要，不是本周可调用的 API 或可申报的项目细则；"智能体互联网络"目前只有方向描述，没有协议、接口与时延指标。把规划文本当成已落地基础设施，是这类政策新闻最常见的误读。

### 6. 两起开发链路入侵同期披露：员工 GitHub 账号成了生产凭证的入口

**11 月 26 日**，多家安全媒体报道密码管理服务 **1Password** 的安全事件：公司 **11 月 19 日**开始调查一起入侵——攻击者利用一名员工的**公司 GitHub 账户**访问私有源代码，并向后端服务**推送恶意代码**，借此下载部分客户的账户记录。公司于 **11 月 25 日**发布公告。同日披露的还有 **Defang**：攻击者 **11 月 12 日**进入其 Deploy 构建系统，**11 月 23 日**确认复制了主数据库副本与生产凭证。

**核心亮点：**

- **1Password 泄露的是元数据，不是保险库**：被下载内容包括姓名、登录邮箱、账户与用户标识符、创建及最近登录时间、公钥、**SRP 协议参数**，以及部分邀请、配置和账户恢复邮件链接中的 **token**。公司强调保险库内容、保护密钥与 Secret Key 均未受影响，且 1Password 本身不存储用户账户密码。
- **令牌有二次门槛，但公司仍加码**：完成邀请或恢复流程还需 **SSO 或注册邮箱的 6 位验证码**，仅凭链接 token 不能接管账户；事件后验证码从 **6 位数字改为 10 位字母数字组合**，涉事 GitHub 账号被停用，可能暴露的凭证被轮换或吊销。受影响用户数量未公布。
- **Defang 的链条更值得工程团队复盘**：攻击者利用一个**权限过大的开发用 GitHub App** 推送提交并打上发布标签，生产环境**信任发布标签**并让代码在 CI 中运行，进而泄露生产凭证。凭证从 **11 月 12 日**有效到 **11 月 23 日**确认，期间部分日志不足以排除后续使用。
- **对开发者意味着什么**：代码仓库、CI/CD 与发布标签已经构成一条可执行的基础设施链。最小权限、发布标签人工审批或签名验证、仓库与终端设备的检测规则，优先级应高于再堆一层模型护栏。
- **需要保留的清醒**：1Password 称未发现账户被劫持证据，这是**厂商自查口径**，且"通知了多少人"没有公开；两起事件都不是模型自主攻击，把它们并入"AI 安全"叙事会掩盖最朴素的原因——凭证权限过大。

### 7. 黎曼证明从 1740 万行压到 7.6 万行：AI 交的卷，终于到了人能翻开的长度

**11 月 25 日**，Anthropic 研究员 **Luke Sernau** 与同事及 **Claude** 在 GitHub 放出重写版仓库 **`lsernau/grh-lean`**，把上期报道的黎曼猜想与广义黎曼猜想 Lean 形式化证明大幅精简；**11 月 26 日凌晨**起在中英文社区集中发酵。仓库同时提供约 **30 万行**的可读版和约 **7.6 万行**的紧凑版，许可证为 **Apache 2.0**。

**核心亮点：**

- **两套行数口径并列**：原版按社区常见口径是 **1,740 万行、175,188 个文件**，Sernau 原帖写的是"约 **1,500 万行**减到约 **76,000 行**"。按 1,740 万行计算，代码量减少 **99.56%**、约 **228 倍**；紧凑版 **792 个文件**，可读版 **801 个文件、约 30 万行代码（总计 47.7 万行）**。
- **真正被验证的是"可复核性"**：MIT 数学教授 **Andrew Sutherland** 用 Claude Code 在隔离沙箱中复核，紧凑版 **9,843 个 job、33 分 32 秒**，可读版 **9,852 个 job、32 分 12 秒**；五个定理的声明文件与原版**逐字节一致**，只依赖 `propext`、`Classical.choice`、`Quot.sound` 三条标准公理，无 `sorry`，并通过 Comparator v4.35.0 与 nanoda、con-leche、con-ron 等独立检查器。
- **方法本身很有工程味**：Sernau 的公开说法是把定义全部"拍扁"成长链，跨模块找冗余后再折叠回去；对无法剪枝的部分换用新论证，例如**移除对 Vandiver 猜想弱形式的依赖**、筛法步骤改用 **Poisson 求和**。社区此前靠删死代码最多只能减约 **8%**，且删完编译不过。
- **7.6 万行恰好塞进 1M token 上下文**：按原版"1,470 万行约等于 25 万页论文"的比例粗算，紧凑版对应不到 **1,300 页**——从"没人能读完"变成"有人开始能读完"。有社区开发者用 100 美元订阅、单 Agent 写到 **3.5 万行**，仍被团队抢先；这是算力与预算差距，不是智力差距。
- **需要保留的清醒**：Sernau 在仓库里明确写着：**目前只有机器检查通过，没有任何数学家从头通读，也没有配套论文**。Claude 负责全部 Lean 代码与文档、人类负责方向，恰恰说明"验证"与"理解"仍是两关；形式化通过不等于数学界接受。

### 8. ω=9/4 之后：数学突破先点燃的是密码焦虑，不是新内核

**11 月 24 日**，OpenAI 数学仓库发布 **111 页**预印本《The matrix multiplication exponent is nine fourths》，主张任意域上方阵乘法渐近指数 **ω 精确等于 9/4（2.25）**；**11 月 26 日**，相关讨论冲上 Hacker News——Scott Aaronson 的评论帖拿到 **1,298 分、1,146 条评论**，另有"实验室可能已在多项式时间破解因式分解"的传闻帖 **484 分、355 条评论**。**11 月 27 日 03 时**，新浪转载报道，英国央行行长 **Andrew Bailey** 也就未公开模型可能威胁加密体系发出警示。

**核心亮点：**

- **上下界第一次夹到同一个数**：文献中的最好上界从 1969 年 Strassen 之后一路降到 **2.371177**（2026 年 8 月口径），OpenAI 在 **10 月**把上界推进到 **2.25**；新论文补上下界——对任意 **n ≥ 2**，形式算术电路至少需要 **⌈n^(9/4)/2⌉** 个非标量乘除门，学界长期猜测的 **ω=2** 被否定。外部学者 **Alimzhan Amanov、Maxim van den Berg、Jeroen Zuiddam** 此前已把上界推广到所有数域。
- **"极限"是渐近的，不是明天跑得更快**：ω 描述矩阵规模趋于无穷时的复杂度增长，现实性能仍受常数因子、存储访问、并行通信与硬件结构制约；钛媒体的评价是"一张新地图而非一台新发动机"，产业回报取决于谁先把理论结构做成可靠工具。
- **加密焦虑有真实引子，但没有实证**：Bailey 的原话是相关企业"技术发展正处在指数增长区间"，同时承认**目前没有任何 AI 企业公开发布可佐证"已破解加密算法"的材料**；因式分解传闻的源头是 Reddit 转述推特截图，HN 高赞评论直接称其为"葡萄藤上说的，100% 保真"。
- **同窗口的 274 页论文加剧了这种情绪**：谷歌研究团队 **11 月 25 日**在 GitHub 上传 **6 篇、合计 274 页**的 Cogentic 数学预印本，其中整数分解论文宣称把有严格保证的复杂度指数从 **1992 年的 1/2** 压到 **1/3**，但常数 **105** 远大于工程数域筛法的约 **1.9**，只能算理论进展；Lean 4 形式化文件尚未公开。
- **需要保留的清醒**：OpenAI 论文仍是**未经同行评议的预印本**，Lean 形式化只覆盖部分结论；"矩阵指数确定"与"RSA 已破"是两件完全不同的事。把匿名传闻、央行表态与论文结论串成一条因果链，是本周最容易出现的信息失真。

### 9. VAST 把 3D 评测剥掉贴图：Tripo H3.5 Preview 的素模文字识别率翻倍

**11 月 25 日上线、11 月 26—27 日中文社区集中解读**，VAST 发布 3D 生成基座新旗舰 **Tripo H3.5 Preview**（部分聚合早报写作"T2"，本文化解为多源一致的 Tripo H3.5 Preview 口径）。它的主张很具体：文字、齿轮、扣件这类细节要**长在几何体本身**，而不是靠贴图假装，正式版随后跟进。

**核心亮点：**

- **评测方式本身就是卖点**：资深 3D 美术师对 **192 组去掉贴图的素模**做盲评，H3.5 Preview 拿下 **82 次第一，占 42.8%**，是第二名的 **2.3 倍**；与上一代 **H3.1** 及另外 **5 款**主流模型同台，**五类评测全部第一**。
- **浮雕文字是最直观的指标**：剥掉贴图后，浮雕文字的 OCR 识别率从 H3.1 的 **46.1%** 升到 **90.7%**，几乎翻倍——识别的是网格形状，不是纹理图案。
- **工程管线配套同步上线**：可打印性检测与自动修复可直接检出薄壁、水密性、非流形边问题，并一键修补孔洞、按工艺调整壁厚；导出支持 **STL、OBJ、3MF**，可对接 Bambu Studio 等切片工具，重拓扑、拆件、绑骨也已具备。
- **对开发者意味着什么**：3D 生成的验收标准正从"渲染图好不好看"转向"几何能不能直接进生产"；做电商素材、游戏道具或 3D 打印的团队，可以拿"去贴图 OCR + 水密性检测"当低成本回归测试。
- **需要保留的清醒**：参与对比的其他模型在评测中以代号出现，**全部数字为厂商自测**，没有第三方复现；Preview 版本与正式版的能力、价格都未定，盲评样本也只有 192 组。

### 10. AMD 显卡上的 llama.cpp 提速 85%，但 HN 更关心"是不是偷偷改了模型"

**11 月 26 日**，Hacker News 一篇关于 AMD 专用 **`stew675/llama-cpp-rdna-boosts`** 的实测帖获得 **247 分**讨论。作者实测在 AMD 卡上把 prefill 从约 **700 t/s 提到约 1,300 t/s**、token 生成从约 **35 t/s 提到约 55 t/s**，认为它走的是正常硬件适配路线，值得推荐。

**核心亮点：**

- **真正引发争论的是另一类"优化"**：作者点名 2026 下半年冒出的专用引擎（Strata、Basalt、RustingStrata、vllm-radiance 等），共同套路是只针对特定硬件/模型、大量用前沿模型 vibe-coding、死磕 tok/s。
- **最典型的例子是把"选谁"改成"谁在显存里"**：Strata 可以把 **1,800 亿参数**的量化 Qwen 3.8 Flash Next 塞进 **16GB 显存 + 16GB 系统内存**，手段是优先挑已在显存里的专家，哪怕别的专家本该被选中。作者判断这不是硬件适配，而是**改变了模型怎么想**，会静默降质。
- **结论对本地部署很实用**：评估任何新推理引擎，先问三件事——有没有动路由策略、有没有改量化精度、测的是 prefill 还是 decode；只看 tok/s 排行榜，很容易把"更快但不一样"当成"更快且一样"。
- **作者也有取舍**：他推荐 rdna-boosts，但因构建太麻烦放弃了 vllm-radiance；这是个人实测与主观取舍，不是横评结论。
- **需要保留的清醒**：247 分与 35→55 t/s 都来自单个 HN 帖子和作者自己的机器，缺少统一模型、统一量化、统一并发的对照；把"作坊化"批评扩大到所有专用引擎，同样是以偏概全。
