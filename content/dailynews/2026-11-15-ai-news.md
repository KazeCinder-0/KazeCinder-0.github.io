### 1. 一个 goal 裂成一群线程：Claude Code Projects 把"拆活"交给协调器，代价是每个线程都按完整会话计费

Anthropic 在 **11 月 13 日 22:51 UTC** 由 Claude Developers 账号发布更新、**11 月 14 日**上线产品说明，Claude Code Projects 的协调器从"你要问才汇报"变成主动在项目聊天里回答问题、跟进各线程进度，同时加入 **/btw**（开一条旁支线程，不打断当前线程）与 **/fork**（从当前线程分叉出第二种做法）、线程提醒、以及单线程的**只读分享链接**（访问过本地计算机的线程不可分享）。官方给的使用姿势是：设定 goal、挂上仓库或文档，Claude 自己划定范围、拆解、开并行线程、审阅产物并拼装结果；用户可在项目主对话里盯进度，也能钻进单条线程改细节，关掉电脑后工作继续，手机上可继续指挥。

底层约束值得先读：每条线程都是一个独立的 Claude Code 云 session，跑在自己的分支和仓库副本上；两条线程改到同一处代码，重叠按普通 PR 的**合并冲突**处理，而不是靠某种自动合并。所有线程读写同一份共享 memory（例如"发布改期到周五""为什么砍掉导出"），另有 library 收集加入的文件与生成的产物。beta 首批只面向"使用 Claude Code 云 session、且网页/桌面端尚无既有 project"的 Pro/Max 订阅者，之后一周逐步扩围，Team 与 Enterprise 排在更后面；新项目默认协调器与线程都用 Opus。

**核心亮点：**
- **今天就能改的是分工方式，不是提示词**：官方示例给的是把"降低结账 p75 延迟"设成 goal，让各线程分别 profile 端点、测优化、开 PR；另一个示例挂 API/Web/Mobile 三个仓库退役 v1 端点，每仓一条线程迁移调用方、跑测试、报合并顺序。两个示例都是基础设施杂活，不是演示玩具。
- **配额是这次更新最硬的边界**：因为每个线程都是完整会话，Anthropic 明说项目会更快触及用量上限。Claude Code 团队的 Boris Cherny 在 Hacker News 答复称协调器本身只增加**不到 10%** 用量，但有人问了一句"聊天机器人该选哪个现成框架"，Claude 起了 **7 个 helper、约 10 分钟**烧完订阅额度；他给出的临时办法是在 goal 里写死一个约 **30 万 token** 的预算。AlphaSignal 另称每账号每天上限 **200 条新线程**。
- **共享 memory 是"少写提示词"的真正落点**：决策与被否掉的方案跨线程累积，减少把上下文在窗口之间手工搬运；这和上期本栏写过的"压缩层"是同一条思路，只是压缩对象从 token 换成了组织记忆。
- **只读分享把评审拉进来了**：任何登录 Claude 的人都能看单条线程，但碰过本地机器的线程被明确排除，等于把"可分享"与"可访问本地"做成互斥开关。
- **需要保留的清醒**：把整套"从文件夹改成会话"当成 11 月 14 日首发是**口径合并**——goal→并行线程的基本形态在 **9 月 17 日**改版时已上线，本窗口新增的是主动协调器、/btw、/fork、只读分享与 beta 扩围，多家中文日报把两者写成同一天。此外线程**目前只在云端**，官方称本地运行、使用本地工具与代码、跑在用户网络之后"即将推出"；HN 上 **91 条**讨论里最主要的质疑正是云侧锁定与并行线程加速吃配额。上述配额数字、200 线程上限与 Boris 的 10% 均为社区或官方口头口径，未见公开计费文档复核。

### 2. Anthropic 叫停"仔细想想"：Opus 5.5 成为全部付费计划默认，七条旧提示词习惯被一次性作废

**11 月 14—15 日**，Anthropic 把 **Claude Opus 5.5** 设为 **Pro、Max、Ultra、Team** 四个付费计划的默认模型，并同步发布一份知识工作指南，核心主张是：模型自身持续推理、按任务与所选 effort 档位自动调节推理深度，因此 **"think hard" / "think carefully"** 这类从约**一年半前**推理模型早期带过来的措辞只是死重量——内部测试中去掉这些短语后回复**开始得更早、质量没有可测下降**。第二项建议是从 **Medium**（新默认）起步，内部测试称 Opus 5.5 在 Medium 已追平上一代 Opus 5 在 High 的表现，更高档位更贵且"不总是更好"。

指南列出七条要更新的习惯：把 Claude 接到工作文件与系统；在第一条消息里一次说清目标、输出格式与何时该回头提问；删掉"think hard"；默认停在 Medium；直接附上图表而非手打转录表格数值；点名不想要的具体设计元素（例如米色背景、药丸按钮）而不是笼统禁止"通用设计"；把自己的行文风格告诉它。价格页同页给出对照：Opus 5.5 每百万输入/输出 **4 美元 / 20 美元**，Fable 5.2 为 **8 / 40**，Sonnet 5.5 为 **2 / 10**，Haiku 5.5 为 **0.10 / 0.50**。

**核心亮点：**
- **把"推理深度"从提示词挪到设置项**：对搭 Agent 的团队，这意味着链路里那些"请深入思考"的模板句该删，延迟能直接降一截；effort 档位可在发送键旁的模型菜单里改。
- **成本账被重新算了一遍**：Anthropic 称常用 Sonnet 跑日常、只在复杂项目才上 Opus 的分工该复核——更强的模型步数更少，且把 Sonnet 拧到 Extra High 或 Max 的花费"与 Opus 5.5 差不多"。
- **内部测试给了三个可复现的锚**：**18 份**生成报告中 **16 份**通过针对每个数字与引文的自动检查；一份虚构并购分析耗时 **63 分钟**、Opus 5 需 **93 分钟**，成本约一半；Factory 一位早期测试者报告输出 token 少 **20%—25%** 而效果与 Opus 5 的 High 相当。另称 Opus 5.5 在最低 effort 下读密集图表的数值，比 Opus 5 在最高 effort 下更准。
- **"一次给全"取代逐轮追问**：官方称模型已能自己把多步任务走完、从请求直达成品文档或表格，建议直接要成品而不是先要草稿；换句话说，编排权从人转给了模型，与热点 1 的协调器是同一方向。
- **需要保留的清醒**：所有基准对比**均为 Anthropic 内部测试，指南未附任何分数或测试细节**，The Decoder、TPS Report、TokenFeed、AI Agent News 多家转述都点明这一点；"Medium 追平 High""Sonnet 高档≈Opus 5.5"因此不能当成可移植到你自己工作负载的结论，换默认值前应先在自己的任务上量一次 token 与步数。把"删掉 think hard"读成"模型不需要你给约束"也属误读——指南同时强调要说清目标、格式与检查点。

### 3. DeepSeek 把自家 App 拆成可单买的零件：全家桶 API 于 11-13 晚发布，本窗口为中文开发者接入与实测

需要先标清时间：DeepSeek 在 **11 月 13 日**的 API 更新日志里发布"全家桶应用 API"，**11 月 14 日**全天到 15 日早晨，中文开发者社区完成了密集接入、定价换算与实测，量子位以"周五晚上搞事"记述、Pandaily 与 GPTOnline 同日给出英文细节。本窗口不是发布日，而是**这批接口真正被开发者拆开用的第一天**。载体是 **deepseek-flash**（DeepSeek-V4.1-Flash-1017），在 **Messages、Responses、Chat Completions** 三类接口下统一支持扩展能力，上下文最高 **100 万 token**、最大输出 **38.4 万 token**。

对话内能力有五项：关闭思考并打开 `deepseek_web_search` 时自动发起网页/图片搜索并附引用作答；开启思考后同一工具可在多步推理中自主搜索与阅读链接；文件输入支持 PDF、Office、图片，做纯文本提取或图文混排解析后拼入上下文；`deepseek_read_url` 自动抓取消息里的链接；安全校验参数审核输入输出、命中风险返回拒答标识，官方要求对外提供应用服务者必须开启并自行承担内容审核、大模型登记与 AI 标识义务。底层能力另开独立接口：**Search、Fetch、OCR、ASR、TTS**。为演示效果，官方以 **MIT** 协议开源了静态前端 `chat-demo`（`github.com/deepseek-ai/chat-demo`，体验入口 `cdn.deepseek.com/chat-demo`），支持导入 DeepSeek 历史对话、深度思考、搜索、链接阅读、附件与语音输入，密钥与会话留在设备本地，官方自称是参考原型而非生产可用。

**核心亮点：**
- **价格已经能直接写进成本模型**：文字/图片搜索与网页抓取各 **5 元/千次成功调用**（约 **$0.75/千次**），OCR **1.5 元/千页**（约 **$0.225/千页**），ASR **0.39 元/小时**（原价 0.78 元，限时五折；约 **$0.116/小时**），TTS **1.5 元/万字符**（原价 3 元，五折；约 **$0.45/万字符**）；工具调用在 token 之外单独计费，失败与无结果的 Search/Fetch 不计费。模型侧价格不变：cache miss 输入 **$0.30/百万**、cache hit **$0.006/百万**、输出 **$1.20/百万**，闲时半价。
- **语音这次是"官方独立接口"而非外挂**：ASR 支持 **21 种语言**，TTS 支持 **10 种语言**、两个音色 **Stella 与 Tide**、可走 WebSocket 流式；Search 标称最高 **100 RPS**、Fetch **25 RPS**。此前做"能听会说的 DeepSeek 助手"要另接一家语音供应商，现在一家闭环。
- **和 10 月 17 日那次是承接关系**：Search 与 Fetch 独立端点在 **10 月 17 日**已开放、跑在 DeepSeek 自研搜索引擎上；当时开发者仍需自己写代码串"判断要不要搜→Search→Fetch→回灌模型→总结"，本次把工具调用与上下文拼装移到服务端自动完成，并补齐 OCR、语音与开源前端。
- **价差是给采购看的语言**：中文换算把 0.39 元/小时对照 OpenAI GPT-Transcribe **$0.27/小时**（约 1.81 元）、GPT-4o mini Transcribe **$0.18/小时**（约 1.21 元）、Google Cloud 标准语音识别按 **$0.016/分钟**折一小时约 **$0.96**（约 6.43 元），得出约 **1/4.6、1/3.1、1/16.5**。官方在公告末尾写"现有的对话产品只是较为基础的一种形态"，甚至说开发者可 **1:1 复刻**完整 App。
- **需要保留的清醒**：上述能力清单与定价来自官方更新日志与定价页、经 Pandaily / GPTOnline / 量子位 / 香港商报 / Emergent 多源转述，但**性能、识别准确率与并发上限均无第三方实测**；五折被标注为"限时"、未给截止日；安全校验只是基础风控与拒答标识，合规责任仍归应用方。把"1:1 复刻"读成"复制了模型能力"也不成立——开放的只是工具层与前端，权重与 App 的排序、记忆策略不在其中。

### 4. Antigravity 把额度全部清零，并让 Agent 自己写 Python 去指挥一群 Agent

**11 月 14 日**，Google Antigravity 负责人 **Varun Mohan** 宣布**重置所有用户的 Gemini 使用额度**，理由是"纪念一周内的密集发布"，并鼓励用户用 swarms 构建项目。同日推出的 **Dynamic Workflows** 把编排再往上抬了一层：用户描述任务后，agent 会**编写 Python 脚本**，并发或分阶段运行多个 agent；目前已支持 Antigravity **App 与 CLI**。这是本窗口里最直接的"今天就能试"的入口变化——既有额度被抹平，也有了新的多 agent 编排面。

放在一周的脉络里看更清楚：**11 月 12 日**本栏写过的 Gemini 4 Hydrogen 已在 GitHub Copilot 全量上线（11 月 15 日中文早报重述），Antigravity 的 Orchestrator 则在 Carbon 负责规划、Hydrogen 负责执行之间切换，Google 称这样可少耗 **24%** 配额、任务快近 **20%**。额度重置相当于给这套"规划—执行"分层发了一次免费试用装。

**核心亮点：**
- **编排权从配置移到代码**：过去多 agent 靠界面或 YAML 编排，Dynamic Workflows 让 agent 自己产出可执行的 Python 脚本决定并发与阶段，脚本本身可 review、可版本化、可复跑，比黑盒编排更接近工程实践。
- **App 与 CLI 同时可用**：CLI 支持意味着能挂进现有 CI、定时任务与本地脚本，不必把工作流锁在桌面端；配合 swarms 鼓励语，官方显然想让"一群 agent 干一个项目"变成默认用法。
- **额度重置是可量化的试错窗口**：过去一周 Carbon、Hydrogen、Decisions API 连续放出，配额是开发者尝新的主要摩擦点，清零后可以在同一预算下把 Orchestrator 的分层效果自己跑一遍。
- **和热点 1 构成两种编排哲学**：Claude Code Projects 用产品内的协调器与共享 memory 管线程，Antigravity 让 agent 写脚本管 agent；前者强在状态与记忆，后者强在可检查、可改的执行计划。
- **需要保留的清醒**：额度重置、Dynamic Workflows 与"鼓励 swarms"均来自 Varun Mohan 的公告与 TechDaily / 中文早报转述，**未见官方帮助文档给出重置的具体数额、生效时点与是否覆盖全部付费档**；24% 配额与近 20% 提速是 Google 自报、上期已述，本次不是新数据；agent 生成的 Python 脚本在本地或 CI 执行，权限边界、失败重跑与成本上限仍需团队自己设，脚本可审查不等于脚本安全。

### 5. "29GB 跑 145B" 的账算不平：Edge0-145B 被 Hacker News 和一份逐字节拆解同时按住了

Edge0（署名 AutoArk）在 **11 月 11 日**放出四个 checkpoint 与推理框架、**11 月 12 日**写博客，宣称 Edge0-145B 是"世界首个开源 145B 端侧模型"，在"一台兼容的笔记本"上峰值 **29GB** 内存、解码 **80+ tokens/s**、prefill **1,100+ tokens/s**、典型功耗约 **120W**、**128K—256K** 上下文长输入"速度基本一致"。**11 月 14 日**，这个帖子在 Hacker News 拿到 **334 分**，争论焦点从"能不能跑"变成"这个数字描述的是能力还是记账方式"；同日 Traictory 逐文件核对了 Hugging Face 仓库，把争议推到可验证层面。

拆解结果并不站在营销口径一边：四个仓库（均创建于 11 月 11 日、均未设门控）实际下载量为 **Edge0-145B-q3k 105.4GB（93 文件）**、**145B-NVFP4 112.9GB（45 文件）**、**120B-q3k 92.3GB**、**120B-NVFP4 97.6GB**，其中 145B NVFP4 截至 11 月 14 日已有 **14,000+** 次下载。文件不是常规 GGUF/safetensors：包含一个 **5.99GB** 的 `model-skeleton.gguf`、原始 `experts.bin`、**51.2GB** 的 `ple-fp8.gguf` 表与独立的潜变量投影文件，Hugging Face 的参数计数器只读到 skeleton，对名为 145B 的仓库报出 **4.95B** 参数。许可名为 `edge0-community-model-1.0`（GitHub 归类 `other`），允许个人与研究使用、修改及商用输出，但**模型销售、付费推理服务、"独立商业编码或办公助手"需另行书面许可**，且上游 Qwen Community License 同样适用——属开放权重，不属 OSI 意义的开源。

**核心亮点：**
- **一个除法就够**：29GB 摊到 145B 参数是 **0.2 字节/参数、约 1.6 bits**，而 3-bit、4-bit 格式都到不了 1.6 bits；105.4GB 摊下来是 **0.73 字节/参数、约 5.8 bits**。两个量级对不上，"29GB"更像活跃工作集而非完整权重体积。
- **分层结构解释了差额**：专家池 **84.6B** 参数、latent width 从 2560 降到 **1792**，每条 expert 记录 **1,630,720 字节**承载 **3,440,640 参数**（Q3_K 下约 **3.79 bits**）；`experts.bin` **40.08GB** 被官方称"约 40GB 专家库常驻系统内存"，另有 **51.2B** 参数的 n-gram 表以 **51.2GB** 的 fp8 文件交付。把常驻内存、磁盘表与峰值显存分开记账，才是可复现的说法。
- **规格表自己也在漂移**：表格写 29GB，对照段写 **28GB**，基准表结论又写 29GB"可在 **48GB 笔记本**上本地使用"；硬件一栏只写"如 MacBook Pro"这类类别，**未给 GPU、CPU、内存总量、操作系统或构建版本**。对照段里 Edge0-35B 在 iPhone 18 Pro Max 上 **<2.5GB / 37+ tokens/s**，随后官方自己补了一句"这些测量适用于不同模型与硬件"。
- **许可证比跑分更该先读**：一个自称"开源"的项目不命名 OSI 许可，且明确禁止付费推理与独立商业助手，对想拿它做产品底座的团队是硬约束；这和上期本栏写过"Qwen Community License 并非 Apache 2.0"是同一类坑。
- **需要保留的清醒**：以上数字来自 Traictory 对 11 月 14 日仓库树的逐个文件求和（十进制 GB）与官方帖子，**属单一第三方拆解，未见 Edge0 回应或独立复跑**；BYOBot 11 月 15 日仍按官方口径转述"约 10B 激活参数、48GB 笔记本 29GB 峰值、80+ tokens/s、未命名许可"，说明社区尚未形成统一结论。在作者给出技术报告、明确硬件与许可之前，不宜把 29GB 当成采购或部署依据。

### 6. 26 个测试室、300 次计划、30 美元预算：Portal2Bench 让 Agent 真的去通关《传送门 2》

**11 月 15 日**的 Show HN 上，Portal2Bench 把 3D 空间推理与长程规划放进一个封闭考场：让 Agent 实际操作《传送门 2》**第 2 至第 5 章的 26 个测试室**。规则设计得刻意干净——模型思考时游戏暂停，Agent 只能发送按键与视角转向，拿回截图与自身坐标；它有一个笔记文件夹，但**没有 shell、没有网络、没有控制台**，因此无法作弊，另有 QA 检查兜底。每个测试室是全新独立的一局，必须在 **300 次计划**、**30 美元预算**内到达下一张地图才算解决；死亡后按普通游戏规则在上个检查点复活，且只告知它"你死了"。

结果把"会写代码"和"能在物理规则下持续试错"清楚分成了两件事：**GPT-6.1 Sol 20/26**、**GPT-6 Astra 20**、**GPT-6.1 Terra 19**、**Claude Opus 5.5 11**、**Sonnet 5.5 6**、**Fable 5.1 目前 3/15**、**GPT-6 Luna 0**。单个通关关卡的中位成本从 **0.74 美元**（GPT-6.1 Terra）到 **13.12 美元**（Fable 5.1），跨度近 **18 倍**。

**核心亮点：**
- **这是少见的"过程不可伪造"基准**：没有终端与网络就意味着不能查攻略、不能读源码、不能写脚本代跑，只剩截图、坐标与笔记，评测的是持续空间建模而非工具链熟练度。
- **成本与成功率同时被计价**：30 美元预算与 300 次计划把"多试几次总会对"这条路堵住，13.12 美元的单关中位成本说明长程试错仍是按次烧钱的活。
- **榜单顺序和编码榜不重合**：在热点 2 里被 Anthropic 设为全付费计划默认、内部测试表现出色的 Opus 5.5 在这里只有 11/26，低于 GPT-6.1 Sol 的 20/26；这与本窗口 Gemini 4 Carbon 登顶 MathArena 却成本约为 GPT-6.1 Sol **15 倍**、且测试中被指忽略时限，是同一类提醒——单项第一不等于通用最优。
- **给做 Agent 的团队一个可直接抄的评测骨架**：限定动作空间、隔离外部信息、设置预算与步数上限、死亡只给最小反馈，比"让模型自己说完成了"可靠得多。
- **需要保留的清醒**：Portal2Bench 来自 **11 月 15 日中文技术日报转述的 Show HN 项目**，本窗口**未见独立第三方复现、完整论文或统一的模型版本/温度设置**；Fable 5.1 的 3/15 明确是"目前"进度，属未完成采样，不能直接与 20/26 横比；成本区间横跨不同模型与不同关卡，也不能读成单价对比。

### 7. 推理拉满 4.8 倍耗时、5.3 倍成本，分数没动：SPU 把"实验前那个判断"单独拎出来考

**11 月 15 日**，UniPat AI 联合**斯坦福、康奈尔、哈佛、北大、港科大**等发布 **SPU** 基准，考的不是"解释实验"，而是实验之前最贵的一步：**哪个条件更可能成功**。数据集含 **116 个任务、4,207 个真实湿实验结果**，来自 **85 篇论文**加 **4 组未发表合作实验**，覆盖 VHH 纳米抗体、反应条件、电解液、抗体变体等 **32 个子领域**。评测环境限制为 **8 小时、8 核 / 16GB 内存 / 单卡 H20**，允许联网装依赖，评分在断网容器内完成并扫描 DOI 与标题防污染；每题随机排序生成 **4,000 份**基准取 **95 百分位**。**12 款前沿模型、13 种配置**参战，最高平均分是 Claude Opus 5.5 的 **0.486**，**只有一半任务超过随机水平**。

最刺眼的是预算实验：把 **GPT-6 Astra** 的推理强度从 medium 拉到 max，耗时中位数涨 **4.8 倍**、API 成本涨 **5.3 倍**，**成绩无显著差异**；模型常在中位 **26%** 的步数就给出答案。私有任务上更不客气——同一批电解液，预测离子电导率的相关系数 **0.89—0.95**，换成预测电化学窗口就掉到 **-0.55 至 0.07**。数据集与代码已开源。

**核心亮点：**
- **"加算力不加分"被做成了可复现数字**：这与热点 2 里 Anthropic 让 Medium 成为默认、劝用户别乱拧高档位，从两个方向指向同一结论——推理预算不是万能旋钮，任务类型决定它是否兑现。
- **防污染设计比分数更值得抄**：断网评分、扫描 DOI 与标题、每题随机排序生成 4,000 份取 95 百分位，把"背过论文"这条捷径尽量堵住；对做垂类评测的团队，这套流程本身比榜单有用。
- **跨任务泛化崩塌给出了边界**：0.89—0.95 到 -0.55—0.07 的落差说明模型可能抓到了数据里的浅层相关而非机理，一旦换预测目标就失效，这正是湿实验最不能接受的错误类型。
- **"一半任务超随机"是给自动化实验室的止损线**：把前沿模型直接接到实验排期前，等于把一半决策交给接近随机的判断；更现实的用法是先当候选生成器，再走人工或形式化复核。
- **需要保留的清醒**：全部数字来自 **11 月 15 日中文技术日报对一项研究的转述**，本窗口未检索到独立复现、同行评议或完整论文；0.486 是"平均分"而非成功率，与 Portal2Bench 的通关数不可横比；8 小时 / 单卡 H20 的统一环境对更大模型是否公平、4 组未发表实验如何脱敏，均有待原文披露。

### 8. 绿电进、Token 出：联想把"万全混合词元工厂"落到张家口，一期 100 兆瓦、年产 2000 万亿词元

**11 月 15 日**多家中文财经媒体集中报道，联想发布**万全混合词元工厂**品牌，并与张家口市政府签约，首个**母本工厂**落地当地。一期包括一座约 **100 兆瓦**的智算中心和 **1.5 万 P（15000P）**异构算力集群，建成后预计**年产超过 2000 万亿 Token**、**峰值每秒产出 2 亿词元**、**单日承载 10 万用户并发**，官方口径称 **Token 综合成本下降 70%**。规划是 **2027 年**一期建成投产，到 **2030 年**算力与产能规模扩大 **10 倍以上**。张家口数智产业联合会秘书长王建新的说法点出地方诉求：当地算力产业长期以机架租赁、基础算力输出为主，需向词元生产、模型优化等中游环节延伸。

需求侧的数字来自中国信通院：**2026 年 6 月**国内日均词元消耗量约 **500 万亿**，接近 **2025 年 12 月的 4 倍**；国家数据局口径亦称全国日均词元调用量已突破 **500 万亿**。联想集团执行副总裁兼中国区总裁刘军判断，国内算力供给跟不上需求的局面**可能延续到 2028 年**，理由是海外芯片供应受限、国产芯片扩产需要时间。

**核心亮点：**
- **卖的是"计量过的智能"，不是机架**：按联想定义，这套系统集中提供算力、运行大模型、调用智能体、按需处理请求——企业发来请求，系统挑模型、排设备、跑完返回结果，直接交付解决方案而非裸算力。
- **"混合"落在数据与模型两侧**：敏感任务留在企业私有环境，允许外发的按需调用公共服务，高峰期再借额外资源；模型与芯片同样按需调用，开放权重与闭源商业模型都可选，简单问答交给小模型甚至边缘节点，复杂任务才上大集群。路由由联想的"**词元中枢**"按任务要求与资源负载决定，官方称依托"三层混合动力"体系。
- **把能耗账写进商业模型**：绿电进、Token 出，加上 70% 的综合成本降幅口径，本质是把 AI 最贵的部分做成水电煤式计量商品；戴炜把降本拆成算力、运营、场景三级优化，其中算力层用问天异构智算方案融合超节点、高密系统与多芯多模训推引擎。
- **对开发者的含义是"多一层调度可选"**：如果这类母本工厂真能按 Token 稳定供货，中小团队在自建集群与公有云之外多了第三种采购口径；但接口兼容、SLA 与计量透明度将决定它是不是真的能被写进成本模型。
- **需要保留的清醒**：**100 兆瓦、1.5 万 P、2000 万亿、2 亿/秒、10 万并发、成本 -70% 全部是规划值与公司自报**，一期 2027 年才投产，2000 万亿是设计产能而非已产出，70% 降本无第三方验证；"日均 500 万亿"是信通院/国家数据局两个口径的月度与全国数据，与本工厂产能不是同一量纲，不能相除得出市占率。本栏按用户偏好对公司层面的盘子降权，本条之所以留下，是因为它给出了开发者能直接核算的"每百万 Token 成本"口径。

## 💡 一句话观点

> 「这一天最整齐的动作是**把活拆开交出去**：Claude Code 让一个 goal 裂成各自跑在独立分支上的线程，Antigravity 让 agent 自己写 Python 去指挥一群 agent，DeepSeek 把自家 App 拆成搜索、抓取、OCR、语音可按次单买的零件，联想干脆把算力叫成按吨出货的词元工厂；Anthropic 更直接，让 Opus 5.5 当上四个付费计划的默认，并劝你删掉"仔细想想"——推理深度归设置项，别再写在提示词里。可同一天的另一半，全是**拆完之后还得有人把账算回来**：Edge0 宣称的 29GB 被逐文件摊成 105.4GB 权重、40GB 常驻专家库和 51.2GB 的 n-gram 表，"开源"二字也卡在一个禁售付费推理的自家许可上；SPU 把推理强度从 medium 拧到 max，耗时涨 4.8 倍、成本涨 5.3 倍，分数纹丝不动，最高分也只有 0.486；Portal2Bench 把模型关进没有 shell 和网络的传送门测试室，26 关里最好的也只过 20 关，Opus 5.5 停在 11 关；Cursor 用了两周才查清那 11 小时的恶意扩展最多波及 5,000 人、链路追踪泄露不到 0.05%，而路透翻了 150 多份采购公告，才在 230 亿元的项目清单里重新看见 H100。**拆分越来越便宜，验收越来越贵**：协调器只多吃不到 10% 的额度，七个 helper 却能在十分钟里烧完一个人的订阅；工具调用按千次几块钱计，证明它没跑偏的评测却要按 30 美元一局、300 次计划地烧。行业级的追问因此不是"Agent 还能替我们多做一件事吗"，而是——当判断、执行、记忆、支付、路由都被拆成可以单买、可以并发、可以自动重跑的零件，**那张写着"这次整体到底做对了没有"的收据，该由谁签、按什么粒度签、又能在多长时间内被一键收回？**」—— 彭祖曰 AI 宜忌（2026-11-15）
