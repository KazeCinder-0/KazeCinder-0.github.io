### 1. 7700 亿参数今天就摆上四个平台：腾讯混元把 Hy4 旗舰权重全交出去，但许可证藏了一道 5000 万美元的门槛

**2026 年 11 月 20 日**，**腾讯混元**宣布 **Hy4 正式开源**，权重同步上线 **GitHub、Hugging Face、ModelScope、GitCode** 四个平台，并同时发布 **Hy4 System Card** 披露安全评估方法、测试结果与已知风险。模型为 **MoE 架构、7700 亿总参数、每 Token 激活约 490 亿、78 层、约 100 万 Token 上下文**，支持文本、图像、视频理解与 computer-use、图形界面工作流；开放的是 **三个 checkpoint**——指令模型约 **1.55 TB**、**FP8** 版约 **0.79 TB**、预训练 base 约 **1.54 TB**，另放出 **vLLM / SGLang** 部署说明与预构建镜像、微调资源。至此混元 LLM 全系（Hy3 preview、Hy3、Hy4 preview、Hy4、Hy4 flash）均已开放权重。

需要分清与上期的关系：**11 月 18 日**开源的是 **224B 的 Hy4 flash**（含 64B Engram 参数、激活 12B），**11 月 4 日**上线 API 的是 Hy4 正式版，本窗口落地的是 **770B 旗舰本体**的权重与 System Card，属同一路线上的第三级台阶。官方 few-shot 自评给出 **MMLU 91.6、MMLU-Pro 73.9**，称多数行领先 DeepSeek-V4-Pro base、但一项编码基准落后，并称相比 preview 大幅降低幻觉率；腾讯自己列出的短板包括研究级数学与长程编码。

**核心亮点：**
- **今天就能下，不必再等 API 排期**：四个平台同时可拉，含 FP8 与 base 两个额外 checkpoint，官方给了 vLLM / SGLang 镜像与微调资源，内网自托管、审计、微调第一次在旗舰级国产模型上成为可选项。
- **但「开源」两个字有两套口径**：多家中文媒体写 **Apache 2.0 可商用**，而英文实测报道核对 HF 上的许可证文件后指出，正式版用的是派生自 Apache 2.0 的 **Tencent Hy License 1.0**，新增 **Section 10**——若以推理 / 微调对外提供远程服务且 **12 个月全球营收超 5000 万美元**，或产品 **月活超 1 亿**，须另行取得腾讯书面许可；内部使用豁免，微调版本算衍生作品。**8 月的 Hy4 preview 才是 Apache 2.0**，这是最容易被一句「Apache 2.0」带过去的地方。
- **权重免费不等于部署便宜**：单是 FP8 版就约 0.79 TB，原版约 1.55 TB，要按激活参数、并发与显存重算 GPU 账；对多数团队，先用 API 或较小版本验证、再决定是否自建更现实。
- **System Card 是这次真正的新增交付**：官方把安全评估与已知风险一并公开，延续其近几期「发模型就发评估」的做法，也让自建方第一次有可对照的能力边界文档。
- **需要保留的清醒**：MMLU 91.6 / 73.9 及「幻觉率大幅下降」全部为腾讯自评，**尚无任何第三方复现**；许可证两套口径冲突时，做商业部署应以 HF 上的 LICENSE 文件为准而非早报标题，这是今天最该先花十分钟确认的一件事。

### 2. 26.4B 塞进 20GB 笔记本：Thinking Machines 把「同一层跑三遍」做成开源模型，还顺手承认它让推理更难被看见

**2026 年 11 月 20 日**，**Thinking Machines Lab** 发布 **Inkling 2 Mini** 并开放权重（**Apache 2.0**），定位「小到能在笔记本上跑」的 **looped transformer**——**24 层中的中间 12 层对每个 Token 跑 3 次**，等效约 **48 层**计算，却不增加权重存储。模型为 **MoE、264 亿总参数、34 亿激活参数、每 Token 54 亿权重激活（含循环）**，大部分权重原生 **NVFP4**、最后 **4 层 MXFP8**，总内存占用约 **20GB**，支持文本与图像输入、**100 万 Token 上下文**。官方给出的自评是 **DeepSWE v1.1 48.2%**、**Vals Index v2.2 46.5%**，称为百亿总参以下开源权重模型的第一。

生态跟进速度与硬件账同样值得记：发布当天 **sglang 与 vLLM 即合并支持配方**，**unsloth** 放出 **9.14GB 的 UD-Q2_K_XL GGUF**；官方称可在 **32GB 以上内存的 Apple Silicon** 与 **DGX Spark** 上跑，Ollama 库已收录但需预发布版 **v0.40.17-rc3**，sglang 配方在 **RTX 5090 TP1** 下上下文限 **65536**。研究者在 **M5 Pro / 48GB MacBook Pro** 的飞行模式里，几分钟内让它写出一个可玩的飞行模拟器。

**核心亮点：**
- **价格与速度是硬指标**：按官方 Tinker 定价（每百万输入 / 缓存命中 / 输出 **$0.15 / $0.015 / $0.50**），Artificial Analysis 测得每项智能指数任务 **$0.59、9.0 分钟**，对照 **Qwen3.8-27B 的 $3.53、38.2 分钟**；智能指数同为 **20**，计算量约少 **2.8 倍**。训练另计 **$0.75 / 百万 token（64K）或 $1.50（256K）**。
- **「循环」换的是推理深度，不是知识量**：官方明确写 looping 能让模型「不把推理写下来地多想一会儿」，变量循环研究版的 no-CoT 时间跨度从单遍 **16 秒**升到三遍 **37 秒**，串行推理基准到 **10 次循环**仍在提升，而 AA-Omniscience、SimpleQA Verified 这类知识密集项不随遍数改善——知识仍主要由总参数决定。
- **工具与搜索是对策**：官方称它在 BrowseComp、DeepSearchQA、MCP Atlas 上领先同尺寸开源权重模型，靠高效用搜索补齐知识短板；另发布一份变量循环研究版权重，用于可监控性对照实验。
- **运维坑已经有人踩过**：混合 **GDN / Mamba** 架构要求 chunked prefill 大小为 **64 的倍数**，否则前缀缓存命中率归零——这条比跑分更影响今天下午能不能跑顺。
- **需要保留的清醒**：官方自己承认循环「影响我们通过阅读思维链来理解模型在做什么」，也承认多轮聊天与一项指令跟随基准不如 **Qwen3.8-27B**；**SWE-bench Verified 79.2% vs 77.8%** 出自本地模型社区摘要而非官方博客、评测设置不同，不宜与官方的 DeepSWE 48.2% 混为一谈。用更少 token 换更深的思考，代价是把可监督性一起压薄了。

### 3. 1737 万行 Lean 代码换一页都没公开的论文：Anthropic 数学家宣称与 Claude 证明黎曼猜想，陶哲轩说「验证还需要一段时间」

**当地时间 2026 年 11 月 20 日**，**Anthropic 研究员 Levent Alpöge**（哈佛本科、普林斯顿数学博士、曾任哈佛学会青年研究员）在个人网站发布声明，称与 **Claude** 合作找到 **黎曼猜想**及其更强版本 **广义黎曼猜想（GRH）** 的证明。公开材料只有一份 **4 页说明** 与分 **14 个压缩包** 的 Lean 形式化代码：约 **1737 万行**、**175187 个 .lean 文件**、**818755 条定理声明**、无 `sorry` 或 `axiom`，压缩包 **229MB** 解压约 **1.4GB**；他称文字证明超过 **25 万页** 因过长未公开，攻关历时 **41 天**，并自承后半程 Claude 已「远远超过了我」、部分技术描述来自模型生成的总结、自己尚未完全掌握全部数学内容。

数学界的反应是本条真正的分量所在。**2006 年菲尔兹奖得主陶哲轩**在个人博客初步盘点称，证明似乎动用了 **朗兰兹纲领**与算术几何的现代成果，梳理核心思路与验证正确性「还需要一段时间」；**Elliot Glazer** 初查后确认 Lean 文件中形式化的命题「确实是广义黎曼猜想」，正在编译（预计数小时），并估计 Lean 自身可靠性漏洞概率**远低于 1%**；**MIT 的 Andrew Sutherland** 在独立完成相关 Lean 代码编译后称「这确实是一个历史性时刻」；数论专家 **Brian Conrey** 称其为「人类历史上的一个里程碑式时刻」但强调自己只看了个人声明；康奈尔 **Steven Strogatz** 形容为「一位技术高超的 AI 骑手，驾驭着一匹速度极快的 AI 骏马」；罗格斯 **Alex Kontorovich** 反因「黎曼猜想需要运用一切」而更有信心。网传疑似 **2026 年菲尔兹奖得主邓煜** 的聊天截图回复「至少拿出 500 页版本前看都不看」。

**核心亮点：**
- **第一次把模型用在「有确定答案」的纯数学难题上**：与 **8 月** Claude 在黎曼猜想相关研究中把临界线零点比例下界从约 **41.6% 提到 67.2%**（先试 650 个思路全败、再组织约 60 个子智能体跑 2400 次命令、写数百个 Python 脚本、下载 54 篇论文）不同，这次是完整命题的主张，量级不可同日而语。
- **没有论文，只有代码**：Lean 通过小型可信内核逐步检查逻辑推导，能被机器验收；但 **Lean 验证的只是代码所指向的形式化目标，不自动保证它与自然语言层面的原始猜想语义完全一致**——《科学》**2026 年 10 月** 曾报道 AI 生成的 Lean 代码在 OpenAI 高调的 Navier-Stokes 证明中弱化了原始英文命题表述，Lean 4 部分历史版本也曾出现允许无效证明通过的内核缺陷。
- **对照系已经存在**：**9 月** 费马大定理的整个证明翻成 Lean 约 **1300 万行**，本次 **1737 万行** 在量级上并非离谱，但 25 万页文字证明不公开，意味着人类同行暂时无法按传统方式审读。
- **与上期是同一条线索的升级**：上期记录的是 Claude 用六个星期、22 个候选、两次 Lean 验证补完 2003 年没算完的黑洞相变，社区争的是「这算不算发现」；本期把争的对象换成了 167 年未解的千禧年难题，而争的形式没变。
- **需要保留的清醒**：这是**作者自陈、未经同行评议、Anthropic 官方未发声明亦未背书**的成果，独立编译与命题语义核查仍在进行；训练语料是否见过相关材料、是否依赖未证明的额外假设都待查。今天该把它当信号看，不是结论。

### 5. 32 个 agent 跑出 18.9 倍、单体最强的模型却「人越多越差」：Replit 与 Vercel 同一周给出多智能体编排的两条答案

**11 月 19 日**，**Replit** 公布一组性能工程任务的 agent 集群对照：在 **NumPy** 负载上，**1 个 Claude Opus 5.5 agent 在两小时内做到 3.7 倍** 加速，**32 个 Opus 5.5 agent 在同样两小时达到 18.9 倍**；而 **GPT-6.2 Astra 是测试中单体最强的模型，但它的集群随规模变大反而变差**。研究给出的结论不是「多加 agent 就好」，而是**接线方式决定结果**：最佳跑法用**共享任务板 + 尽量少的直接消息**，由协调器逐条路由的设置在 agent 变多时先堵死。**11 月 18 / 19 日**，**Vercel 发布 Board**（实验性），把这套「共享任务板」做成产品：agent 通过 CLI 或 JavaScript SDK 从共享队列认领任务、长任务续租 lease、完成后挂上待审链接；工作分 channel 与 thread，标签承载状态，消息可按注册的 schema 校验结构化字段（如 repository / severity / status），watcher 在回复落地或标签变化时唤醒 agent 并在 Vercel 平台上直接触发一次 deployment，agent 还能给自己排后续任务（如开 PR 五分钟后查 CI）；权限按 per-user / per-agent 授予、每个事件记录行为人，沙箱内 agent 可拿到一个**不存任何凭据**、仅限指定 channel 与动作的 board 连接；与 Slack、GitHub 双向同步。Vercel 称内部 **v0 软件工厂现在一半以上的 PR 由该系统合并**，并列出 Claude Code、Codex、OpenCode、Mastra、LangChain 可共用一块板。

同一周还有三块拼图：**Stripe** 于 **11 月 20 日** 在 Treasury 公开预览里让企业给 AI agent 受控的资金划转权限，退款、付款、转账均带审批规则；**Microsoft Foundry** 同日让组织构建「在 Microsoft 365 中以自己身份与权限行动」的 agent；**Scale Labs** 发布 **VeRO**——用编码 agent 去优化目标 agent 的 prompt、工具与控制流，在 **5 个基准、105 次运行** 中发现工具使用类任务确有可优化空间，但模型探索多样性有限、明显偏向改 prompt 而非改架构。

**核心亮点：**
- **18.9 倍不是模型赢的，是拓扑赢的**：同一批 Opus 5.5、同样两小时，从 3.7 倍到 18.9 倍的差别来自「共享任务板 + 少直接消息」，而单体最强的 Astra 在协调器路由下退化——选模型之前先选编排，这对今天要搭多 agent 的团队是最省事的一条结论。
- **lease、schema、scoped grant 是三个新原语**：Board 把「认领 / 超时 / 依赖」当成一等公民（一个 review 任务只有在对应 fix 完成后才变为可认领），Linear 与 GitHub Issues 默认假设分配者和阅读者都是人，这套假设在 agent 数量超过监督者时先失效。
- **钱和身份开始变成 agent 的一等属性**：Stripe 给受控资金权、Foundry 给 M365 独立身份，加上 Amuse 的 stand-in token vault，权限模型正从「能不能读」走向「能以谁的名义花多少」。
- **VeRO 泼的那盆冷水值得记**：让 agent 优化 agent 时，它更愿意改提示词而不动架构，所以「自动化调参」目前更像局部搜索，架构决策仍得留给人。
- **需要保留的清醒**：Vercel 称「v0 一半以上 PR」是**公司自报、无基线对照**，Board 明确标 experimental、未公布定价、规模数据与失败模式（例如两个 agent 持冲突 lease 会怎样）；Replit 的 18.9 倍限定在 NumPy 性能工程这一类可并行任务上，换成长程编码未必成立；wake-on-event 绑 Vercel deployment，也意味着这套协调带有托管绑定。

### 6. 同一天两篇「能力边界」报告：MedChemBench 让模型认得出分子却选不对药，反蒸馏把推理链提取成功率从 54% 压到 0.2%

**11 月 20 日**，**OpenAI** 连发两份与「模型到底能干什么」有关的材料。其一是 **MedChemBench**：**99 道题**取自 **117 篇论文与专利**、涉及 **761 个不同分子结构**，把模型放在某个真实药物化学项目的决策节点上，给生物靶点、项目目标、已研究化合物与部分实验读数，评分拆成**分子结构重建、科学解释、排序与选择、性质预测**四项。在十一个模型共用的 **xhigh** 推理档下，**GPT-6.2 Astra 拿到 84.5%** 可用分，**GPT-6 Astra 83.3%**、**GPT-6.1 Sol 82.0%**、**GPT-6.1 Terra 75.1%**、**GPT-5.6 Sol 58.2%**；Astra 的结构分项高达 **95.4%**，而**化合物选择与数值性质预测只有约一半分数**。官方举的两个例子很直观：一道要求保留 **18 原子环** 的组装题，GPT-6 Astra 十次全对，GPT-5.6 Sol 做成 **15 原子环**、Luna 把分子拆成两段互不相连的片段，十次全错；PRMT5 抑制剂题里，隐去的后续实验显示化合物 23 在更低浓度起效、化合物 24 更易穿膜且肝酶降解更慢，多目标权衡正是模型丢分处。

其二是 **《Combatting adversarial distillation》**，把「别人用海量 API 调用把你的模型能力蒸馏走」定义为需要持续运营的常态问题，给出**模型训练、safeguards、检测、执法**四层。自适应黑盒红队（**6 个攻击者模型**、随系统响应调整策略、只看外部用户能看到的东西）测得：从**历史请求**提取受保护推理的平均成功率由 GPT-6 Astra 原始防护下的 **54.0% 降至 GPT-6.2 Astra 的 0.2%**，从**当前请求**提取由 **22.9% 降至 0.9%**；防护覆盖 GPT-6.2 Astra / Sol，部分改进回灌 GPT-6 Astra，并称每周因协同蒸馏活动暂停**数千至数万**个账号。内部网络安全迁移实验里，用**精确教师推理轨迹**训练的学生在 SFT 后普遍优于只用「最终回答 + 推理摘要 + 工具交互」的学生，轻量 RL 后在最大推理预算下仍领先两个基准。

**核心亮点：**
- **「认得出分子」和「选得对化合物」是两件事**：95.4% 的结构分对上约一半的决策分，正好把 AI for Science 里最容易被一个总分盖过去的缺口画了出来；OpenAI 自己写明这不证明模型能发现新药或改善实验室决策。
- **反蒸馏把「推理链」重新定义成资产**：输入 / 输出分类器同时检查 assistant 消息与 **tool-call 参数**（流式与非流式），因为推理可能只出现在工具参数里而不出现在最终答案；GPT-6.2 的 protected reasoning 绑定到产生它的会话历史，改写前序消息即丢弃其后续推理，旧模型家族也不能读 6.2 的推理。
- **对开发者是一条立刻可执行的提醒**：凡是把完整 CoT 导出「留着调试」的 CI bot、评测管线、跨线程重放加密推理的 harness，都在持有 OpenAI 明确要阻止外流的那类资产；本周该把 trace 存储当凭据管——限定范围、说明用途、默认分类器会看工具参数而不只是聊天文本。
- **同一天还有第三份自测**：转述称 OpenAI 的「jagged frontier」报告披露，估计需 **2–4 小时**人工的任务自主成功率从 **3 月 23% 升到 10 月 46%**、**4–8 小时**任务从 **13% 升到 35%**，中位长任务日均 API 花费约 **$2400**（该组数字来自聚合日报转述、口径待核，故不入数据表）。
- **需要保留的清醒**：MedChemBench 题目来自公开论文与专利，**不能排除训练语料已见过**，且每次回答都是单次尝试、无工具无反馈无新实验；榜首全是发布方自家模型、最强配置还是未广泛描述的 Astra 变体。反蒸馏的 0.2% / 0.9% 则是**内部自适应评测**，检测如何在大规模正常重度使用里区分滥用、执法标准是否公开，都还没答案。

### 7. 端到端加密挡不住「已经解了密的屏幕」：Signal 默认屏蔽截图，Meta Muse 事件把 agent 权限模型推到台前

**11 月 20 日**，**Signal** 宣布默认限制手机截图访问，以阻止 AI 助手读取私人聊天内容：在 **iOS 27** 上直接阻止应用内及多任务切换界面截图，用户尝试截图会看到「截图已被『屏蔽 Siri AI』设置阻止」的提示；在受支持的 Android 版本上，检测到截图尝试或 AI 助手访问屏幕时弹出提示，由用户按设备情况决定是否解除。Signal 在给路透的博文中称这套防护**并不完整**，呼吁 **苹果、谷歌、微软** 给开发者提供明确的技术手段把应用标记为「对 AI agent 不可见」、并披露 agent 的运作机制，尤其点名 **Siri AI** 与 **Gemini Intelligence** 这类深度嵌进操作系统的能力，称 AI 与 OS 的整合正让其运行环境「对隐私愈发不利」，构成**「生存威胁」**。Signal 去年已在 Windows 上封堵微软 Recall，但自承在 macOS 上无法可靠提供同类保护。

触发这套防御的是 **路透 11 月 18 日** 的调查（本窗口为后续落地与中文媒体密集发酵）：路透与 Signal、AI Now Institute 复现了 **Meta 的 Muse** 读取 Signal 消息——Android 上靠**安装时授予的通知读取权限**（一名员工称 setup 时默认开启）取推送里的消息文本，macOS 上靠苹果为残障用户设计的**辅助功能与截图权限**，两者都**绕过 Meta 自家 Connector**，iPhone 上同样请求被挡，**端到端加密全程未被破解**，读的是系统已解密并显示在屏幕上的字。路透查阅 **20 多条内部帖**，员工收到过不属于自己的育儿安排、商品订单、咖啡桌取货、不可退款的 Airbnb 预订，以及 **Capital One $2,722.58** 与 **Charles Schwab $5,899.57** 两笔余额；Meta 发言人 **Daniel Roberts** 称是「isolated incidents」、多为已修复的幻觉，内部超级智能团队有人写这些幻觉「偏偏偏向财务 / 安全这类最让人不适的话题」，而路透**无法确定这些数字究竟属于他人还是模型编的**。Muse **9 月上线、下载超 1000 万**，条款把 agent 行为责任放在用户身上；Signal 总裁 **Meredith Whittaker** 称这种程度的设备访问「technologically reckless」。苹果 **11 月 16 日** 的 macOS 更新限制开发者对辅助功能的调用、并为 AI agent 新增独立权限，封堵了 Mac 路径；**macOS 27.3 beta 2** 进一步把权限拆成「系统与应用保护覆盖」「辅助功能」等项、可只授权特定文件夹或应用、对被控应用设「Ask First」，测试版里 ChatGPT 启用第三方电脑操控从 **4 步变成 14 步**。

**核心亮点：**
- **没有任何人被打穿**：Signal 加密保护的是传输中的消息；一旦消息抵达并被系统解密显示，任何能看通知流或屏幕的权限都能读到它。变化在于读者现在是「一个在正规安装流程里索取这些权限的消费级产品」。
- **修复发生在操作系统层，不在应用层**：真正堵住 Mac 路径的是苹果 11-16 的更新，而不是 Signal 或 Meta；这解释了 Signal 为何坚持要一个由 OS 强制、AI 公司必须尊重的 app 级 opt-out 标记——权限页本身是整套安全模型，而它是为「一个 app 只做一件事」的时代设计的。
- **同一天的两种 agent 设计摆在一起看格外清楚**：OpenAI 把 Codex 的边界逐条写下、并默认把网络关掉；Muse 依赖的则是系统恰好提供的宽泛权限。两个产品都能跑，只有一个能说清自己碰过什么。
- **数字真假难辨本身就是风险**：一个会编出精确到分的银行余额的 agent 是社工攻击的现成素材，一个会泄露真实余额的 agent 是数据事故，Meta 至今无法判定发生了哪一种；英国 **ICO** 关于 agentic AI 的征求意见恰于 **11 月 20 日** 截止，问的正是工具与数据访问如何限制、动作如何留痕、边界由谁设定。
- **需要保留的清醒**：路透调查发布于 **11 月 18 日、属窗口外**，本窗口的新增是 Signal 的默认屏蔽、苹果与谷歌的回应及权限细节；苹果称正「考虑」更细粒度授权、谷歌称 Android 通知访问「必须由用户明确授予」，均非已全面落地的方案；另有 Meta 与记者关于 Messages 数据库同步（第 187,462 行）是否需 Full Disk Access 的说法互相冲突，本栏不作事实认定。

### 9. 「巨额税」还没告诉自己人：特朗普要把算力锁在境内，众议院同日抖出 88 万颗对华芯片许可，拉加德让公共资金先亏

真正有确定日期的是 **BIS 周一（11 月 17 日）** 签发的临时最终规则：向**全球任何**向中国或其他受限司法辖区总部实体提供**超 1200 万 TPP** 算力的数据中心发运先进 AI 芯片与服务器需许可，已在服务这类客户的运营商有 **90 天** 合规期，并新增对**印尼、马来西亚、新加坡、泰国、巴西** 的芯片许可要求，**60 天** 评论期（上期本栏已记该规则 **11 月 19 日** 在《联邦公报》刊登并当日生效，此处只记「周一签发 + 总统表态」这一叠加，避免重复）。**11 月 20 日**，**众议院外交事务委员会** 依《出口管制改革法》公布数据：**2025 年 12 月至 2026 年 5 月**，商务部批准对华出口 **879,000 余颗** 英伟达 H200 与 AMD MI325X（企业申请超 **340 万颗**），其中**腾讯 15 万、阿里 7.5 万**，加上百度与比亚迪，四家合计近三分之一的批准量且**均在五角大楼 alleged Chinese military companies 清单**上；实际发货数量不明，商务部称依 **2026 年 1 月** 规则逐案做国安审查，英伟达称此后已停止向中国发运 H200。另有 **FT** 报道 **台积电与三星** 暂扣部分中国客户芯片待美方许可（三星客户含字节与百度昆仑），**白宫** 解除国家网络总监 **Sean Cairncross**（曾主导 6 月邀头部 AI 公司自愿送测新模型的行政令，2025 年 8 月以 **59-35** 获参议院确认，由 **Kirsten Davies** 暂代）。**11 月 20 日**，**欧洲央行行长拉加德** 在**第 36 届法兰克福欧洲银行业大会** 称，若欧盟资金补贴的芯片厂与数据中心项目失败，**公共资金应承担首轮损失**以撬动私人资本；她估算欧洲 AI 算力全球占比需从 **5% 提升到 2030 年的 15%**，对应约 **1.3 万亿欧元** 投资，并称 AI 与网络威胁结合是「让我夜不能寐」的事。

**核心亮点：**
- **对出海团队是选址逻辑上的硬约束**：若「境外机房 = 巨额税」哪怕只落地一部分，把海外节点当备份或就近服务的设计都要重算；更现实的是 BIS 规则已经把**「谁在用这座数据中心」**变成发运许可条件，而非「机房在哪」——合规尽调从采购单前移到了客户名单。
- **88 万颗是第一个可核对的量**：此前讨论多停留在规则条文，众议院这次给出批准数、申请数与企业分布，虽然「批准 ≠ 发货」，但至少让「管制到底放了多少」有了公开分母。

### 10. 从「能不能翻跟头」到「按台、按只算账」：智元进手机产线、SuperMimic 用千分之一算力反超，PhyDEX 把三个 VLA 打回 2.4%

**核心亮点：**
- **口径从自由度与舞蹈换成节拍、精度与群控**：11 月 19—21 日南京世界智能制造大会有 **630 家企业、5.5 万平方米**展区，埃斯顿 18 轴轮式具身机器人报重复定位精度 **±0.05 毫米** 并率 18 台机器人做多机协同；东方精工第一次给出「订单 8300 万 / 已确认收入 2666 万」的完整对照，让量产真实性有了可核对的账本。
- **训练成本出现数量级拐点，但只在单一基准上**：SuperMimic 的「可微世界模型可直接给梯度」若成立，具身模型迭代将不再被算力预算锁死；这条来自报纸转述、未见论文一手数据，宜等复现。
- **PhyDEX 是一记必要的刹车**：看起来一样的立方体，质量、重心、摩擦不同就能让三个主流 VLA 全跌到 3% 以下；ForceVLA 在三只立方体的窄场景真机上靠力觉拿到 **51.3%**，恰好说明「场景收窄」与「能力达标」之间的差距有多大。
- **软件架构比堆模型更划算的另一组证据**：武大 / 中关村学院 / 三星的 **RoC** 只在进度异常、切换请求与关键接触时才唤醒上层推理智能体，RMBench 成功率比最强智能体基线高 **24 个百分点**、token 消耗降 **65.3%**；CMU 等的 **AgentRoboCritic** 在 12 个基准发现约一半成功回合里机器人曾出错后自行纠正，并发布 12,844 条标注动作。
- **需要保留的清醒**：本节几乎所有百分比都是**论文或公司自报**、每项真机常只测 10 次，PGX 未报告真机端到端成功率、RoC 摘要未列真机成功率；智元与蓝思未给成功率与接管频率，ABB 交易后续（剥离约 30% 中国业务、分手费条款）均为知情人士口径、双方拒绝置评。**厂商自评与真机验收之间，仍是这一行最宽的一道缝。**
